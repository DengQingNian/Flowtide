# 004 数据模型与持久化设计

> 文档编号：004  
> 依赖：002 总体架构、003 代码结构  
> 目标读者：后端开发、DBA、运维

## 1. 设计结论

1. **完整复用 Flowable 8.x 的 `ACT_*` / `FLW_*` Schema**，表名、列名、索引名、唯一约束保持不变。
2. 不引入 ORM；使用 `database/sql` + 显式 SQL + 动态查询构造器。
3. 事务内采用工作单元（UoW）缓冲，命令结束时按依赖顺序批量 Flush。
4. 乐观锁使用 `REV_` 列；作业抢占使用行锁或 `SKIP LOCKED`。
5. ID 使用 UUIDv7 字符串（36 字符，适配 `varchar(64)`），时间有序、索引友好。
6. 时间统一以 UTC 存取；MySQL 使用 `timestamp(3)/datetime(3)`，PostgreSQL 使用 `timestamptz(3)`。
7. 新增内部元数据只写 `ACT_GE_PROPERTY`（如 `flowtide.version`），不新增表。

> 复用 Schema 的收益：既有数据、报表、运维脚本、BI 工具、Java 引擎回滚能力全部保留；代价是需要严格遵循既有列语义，不能"顺手重构"表结构。

## 3. 类型映射

| Flowable 类型 | Go 类型 | 数据库类型 | 说明 |
| --- | --- | --- | --- |
| `VARCHAR(n)` | `string` | `varchar(n)` | UTF-8；长度按字符计 |
| `INTEGER` | `int32` | `integer` | 乐观锁 `REV_`、版本、计数 |
| `BIGINT` | `int64` | `bigint` | 持续时间、日志序号 |
| `TINYINT/BOOLEAN` | `bool` | `tinyint(1)/boolean` | 方言层转换 |
| `TIMESTAMP(3)` | `time.Time` | `timestamptz(3)` | 统一 UTC；禁止本地时区落库 |
| `LONGBLOB/BLOB` | `[]byte` | `bytea/longblob` | 资源、序列化变量、异常栈 |
| `NUMERIC` | `decimal.Decimal` | `numeric` | 仅金额/精确计算扩展 |
| 可空列 | 指针或 `sql.Null*` | — | 公共 DTO 用指针表达"未设置" |

约定：

- 所有时间写入前 `UTC()`；读取后按配置时区展示，引擎内部只用 UTC。
- 空字符串与 NULL 语义不同：租户默认空串，可空业务列用 NULL。
- 金额禁止 `float64`；流程变量 `double` 仍用 `float64` 以兼容。
- 字符集：MySQL `utf8mb4`；排序规则需与 Flowable 的 `utf8_bin` 行为对齐（大小写敏感查询用 `BINARY` 或显式 `COLLATE`）。

## 4. 实体模型

~~~go
// Entity 是所有持久化实体的最小契约。
type Entity interface {
    // TableName 返回表名。
    // @return 表名
    TableName() string
    // GetID 返回主键。
    // @return 主键
    GetID() string
    // GetRevision 返回乐观锁版本。
    // @return 版本号
    GetRevision() int
    // SetRevision 设置乐观锁版本。
    // @param rev 版本号
    SetRevision(rev int)
}

// ExecutionEntity 对应 ACT_RU_EXECUTION。
type ExecutionEntity struct {
    ID               string
    Revision         int
    ProcessInstanceID string
    ParentID         *string
    ProcessDefinitionID string
    ActivityID       *string
    IsActive         bool
    IsScope          bool
    IsConcurrent     bool
    IsEventScope     bool
    IsMultiInstanceRoot bool
    SuspensionState  int
    TenantID         string
    BusinessKey      *string
    Name             *string
    StartTime        *time.Time
    StartUserID      *string
    // 计数字段用于快速删除级联，避免 COUNT(*)
    TaskCount        int
    JobCount         int
    VariableCount    int
}
~~~

实体设计规则：

1. 实体字段与列一一对应，不在实体中放聚合对象（如 `[]Task`）。
2. 聚合关系由仓储显式查询，避免隐式 N+1。
3. 实体只做数据承载与不变量校验，不包含 SQL。
4. 实体可变，但只允许通过实体管理器方法修改；修改后标记 dirty。
5. `REV_` 在插入时为 1，每次更新 +1；更新 SQL 带 `WHERE ID_=? AND REV_=?`。

## 5. 工作单元与会话

~~~go
// Session 聚合一条命令内的实体变更。
type Session struct {
    tx      *sql.Tx
    clock   Clock
    idGen   IDGenerator
    tracked map[string]Entity
    order   []string
    dirty   map[string]bool
    removed map[string]bool
}

// Track 将实体纳入工作单元；首次调用视为新增。
// @param entity 实体
// @return error 跟踪错误
func (s *Session) Track(entity Entity) error

// MarkDirty 标记实体已修改。
// @param entity 实体
func (s *Session) MarkDirty(entity Entity)

// Remove 标记实体待删除。
// @param entity 实体
func (s *Session) Remove(entity Entity)

// Flush 按依赖顺序批量写入。
// @return error 写入错误
func (s *Session) Flush() error
~~~

### 5.1 Flush 顺序

| 顺序 | 表 | 原因 |
| --- | --- | --- |
| 1 | `ACT_RE_DEPLOYMENT`、`ACT_GE_BYTEARRAY` | 资源先落库 |
| 2 | `ACT_RE_PROCDEF`、`ACT_PROCDEF_INFO` | 依赖部署 |
| 3 | `ACT_RU_EXECUTION` | 执行树先于任务/变量 |
| 4 | `ACT_RU_TASK`、`ACT_RU_ACTINST` | 依赖执行 |
| 5 | `ACT_RU_VARIABLE`、`ACT_RU_IDENTITYLINK`、`ACT_RU_ENTITYLINK`、`ACT_RU_EVENT_SUBSCR` | 依赖执行/任务 |
| 6 | `ACT_RU_JOB`、`ACT_RU_TIMER_JOB` 等 | 依赖执行 |
| 7 | `ACT_HI_*` | 历史最后写 |
| 8 | 删除 | 依赖逆序 |

批量策略：

- 同一张表 100 条或累计 1 MB 触发一次多值 INSERT / CASE UPDATE。
- 删除使用 `DELETE ... WHERE ID_ IN (...)`，每批 ≤ 500。
- 大字段（`BYTES_`、异常栈）单独批次，避免包过大。

### 5.2 乐观锁与冲突

~~~sql
UPDATE ACT_RU_EXECUTION
SET ACT_ID_ = ?, REV_ = REV_ + 1, ...
WHERE ID_ = ? AND REV_ = ?
~~~

- 影响行数为 0 → 返回 `ErrOptimisticLock`（`ENGINE-0409`）。
- 同步命令：直接向调用方返回 409，由上层决定重试。
- 异步作业：捕获冲突，回滚事务，按退避策略重试；不计入业务失败次数。
- 死锁/锁等待超时：识别数据库错误码，转为可重试错误，最多重试 3 次。

### 5.3 ID 生成

- 默认 `UUIDv7`：36 字符，含时间前缀，B+ 树插入局部性好。
- 可选 `snowflake`（多节点时钟回拨保护）与 `sequence`（单库自增表）。
- ID 在实体插入前生成，便于在事务内建立父子引用。
- 禁止依赖数据库自增（`ACT_EVT_LOG.LOG_NR_` 除外，它是日志序号）。

## 6. 查询层

### 6.1 动态查询

使用 `squirrel` 构造，列名与排序字段全部白名单：

~~~go
// ProcessInstanceQueryBuilder 构造流程实例查询。
type ProcessInstanceQueryBuilder struct {
    base squirrel.SelectBuilder
    cond squirrel.And
    order []string
}

// Apply 将过滤条件应用到查询。
// @param q 公共查询参数
// @return error 参数错误
func (b *ProcessInstanceQueryBuilder) Apply(q api.ProcessInstanceQueryParams) error {
    if q.ProcessDefinitionKey != "" {
        b.cond = append(b.cond, squirrel.Eq{"PROC_DEF_ID_": q.ProcessDefinitionKey})
    }
    if q.NameLike != "" {
        b.cond = append(b.cond, squirrel.Like{"NAME_": "%" + escapeLike(q.NameLike) + "%"})
    }
    // 排序字段白名单校验
    for _, o := range q.OrderBy {
        if !allowedOrderColumns[o.Column] {
            return fmt.Errorf("非法排序字段: %s", o.Column)
        }
    }
    return nil
}
~~~

规则：

- `LIKE` 查询转义 `%`、`_`、`\`，使用 `ESCAPE '\\'`。
- 分页必须有稳定排序；缺省按 `ID_` 升序。
- `COUNT(*)` 与列表查询分离；大表可用近似计数（可选）。
- 最大页大小 1,000；超过返回参数错误，避免拖垮数据库。
- 深度分页（offset > 100,000）建议改用"上一页最后 ID"游标；REST 暂保持兼容。
- 原生查询（NativeQuery）仅开放给管理端，参数化并限制语句类型（只允许 SELECT）。

### 6.2 索引策略

沿用 Flowable 索引，不重复创建。新增索引必须满足：

1. 有明确的慢查询证据（`pg_stat_statements` / `performance_schema`）。
2. 写放大评估通过（目标表写入 QPS、索引大小）。
3. 在 004 文档登记，并提供回滚脚本。
4. 索引名遵循 `ACT_IDX_*`，避免与 Java 升级脚本冲突。

重点索引：

| 表 | 索引 | 用途 |
| --- | --- | --- |
| `ACT_RU_EXECUTION` | `PROC_INST_ID_`、`PARENT_ID_`、`ROOT_PROC_INST_ID_` | 执行树遍历 |
| `ACT_RU_TASK` | `ASSIGNEE_`、`PROC_INST_ID_`、`CREATE_TIME_`、`DUE_DATE_` | 待办查询 |
| `ACT_RU_VARIABLE` | `EXECUTION_ID_`、`TASK_ID_`、`NAME_` | 变量读取 |
| `ACT_RU_JOB` | `DUEDATE_`、`LOCK_EXP_TIME_` | 作业扫描 |
| `ACT_HI_PROCINST` | `PROC_DEF_ID_`、`START_TIME_`、`END_TIME_` | 历史查询 |
| `ACT_HI_ACTINST` | `PROC_INST_ID_`、`ACT_ID_`、`START_TIME_` | 轨迹查询 |

## 7. 数据库方言

~~~go
// Dialect 封装数据库差异。
type Dialect interface {
    // Name 返回方言名。
    // @return 名称
    Name() string
    // Placeholder 返回第 n 个占位符。
    // @param n 从 1 开始的序号
    // @return 占位符
    Placeholder(n int) string
    // Limit 返回分页子句。
    // @param limit 数量
    // @param offset 偏移
    // @return 子句
    Limit(limit, offset int) string
    // ForUpdateSkipLocked 返回跳过已锁行的锁子句。
    // @return 子句
    ForUpdateSkipLocked() string
    // IsRetryable 判断错误是否可重试。
    // @param err 数据库错误
    // @return 是否可重试
    IsRetryable(err error) bool
}
~~~

| 能力 | PostgreSQL | MySQL 8.0 | 备注 |
| --- | --- | --- | --- |
| 占位符 | `$1` | `?` | 构造器统一生成，方言替换 |
| 分页 | `LIMIT ? OFFSET ?` | `LIMIT ?, ?` | 方言生成 |
| 跳过锁 | `FOR UPDATE SKIP LOCKED` | 同左（8.0+） | 作业抢占 |
| 布尔 | `boolean` | `tinyint(1)` | 扫描为 bool |
| UPSERT | `ON CONFLICT` | `ON DUPLICATE KEY` | 仅内部属性表使用 |
| 大小写 | 区分 | 依 collation | 统一用 `LOWER()` 显式比较 |
| 时间精度 | `timestamptz(3)` | `datetime(3)` | 统一 UTC |

### 7.1 错误分类

| 场景 | PostgreSQL | MySQL | 处理 |
| --- | --- | --- | --- |
| 唯一键冲突 | `23505` | `1062` | 返回 `ErrDuplicate`，部署重试 |
| 外键冲突 | `23503` | `1452` | 返回 `ErrConstraint` |
| 死锁 | `40P01` | `1213` | 可重试 |
| 锁等待超时 | `55P03` | `1205` | 可重试 |
| 连接失败 | `08***` | `2002/2003` | 不可重试，快速失败 |

## 8. Schema 生命周期

### 8.1 内嵌脚本

~~~text
schema/
├── postgres/
│   ├── common.sql
│   ├── engine.sql
│   ├── history.sql
│   ├── identity.sql
│   └── upgrade/
│       ├── 8.0-to-8.1.sql
│       └── ...
├── mysql/
│   └── ...
└── checksums.json
~~~

- 使用 `embed.FS` 打包，发布时无需外部文件。
- 每个脚本记录 SHA-256，启动时校验未被篡改。
- 脚本按 `common → engine → history → identity` 顺序执行。
- `create-drop` 仅用于测试；生产禁止。

### 8.2 版本校验

~~~mermaid
flowchart TD
    A[读取 ACT_GE_PROPERTY schema.version] --> B{存在?}
    B -- 否 --> C{schemaUpdate?}
    C -- true --> D[执行全量 DDL]
    C -- false --> E[报错: 库未初始化]
    B -- 是 --> F{版本 == 期望?}
    F -- 是 --> G[启动成功]
    F -- 否且库更旧 --> H{schemaUpdate?}
    H -- true --> I[按升级脚本逐版本执行]
    H -- false --> J[报错: 需要升级]
    F -- 否且库更新 --> K[报错: 引擎过旧]
~~~

版本常量：

| 键 | 值 | 写入方 |
| --- | --- | --- |
| `schema.version` | `8.1.0.3`（与 Flowable 8.1.0-SNAPSHOT 对齐） | 建表/升级脚本 |
| `flowtide.version` | 引擎版本，如 `1.0.0` | Go 引擎启动时 |
| `next.dbid` | 兼容旧版序列，可写 `1` | 建表脚本（若 Java 需要） |

### 8.3 升级原则

1. **只增不减**：新增列必须可空或带默认值；不删除列、不改类型。
2. **向后兼容**：Go 引擎升级后，Java 引擎仍可读取（同一 MAJOR）。
3. **可回滚**：每个升级脚本配套回滚脚本；回滚仅处理本版本新增对象。
4. **幂等**：脚本可重复执行（`IF NOT EXISTS` / 捕获已存在错误）。
5. **大表变更**：增加索引使用在线 DDL；禁止在主库业务高峰期执行。
6. **数据修复**：单独的数据脚本，必须在升级前备份，并记录影响行数。

## 9. 缓存与一致性

| 缓存 | 一致性策略 |
| --- | --- |
| 流程定义 | 部署事务提交后失效本地；集群 TTL 5 分钟或 Redis 广播 |
| 部署资源 | 按 deploymentID 缓存，删除即失效 |
| 表达式 | 引擎级不可变，重启失效 |
| 租户配置 | TTL 60 秒 |

缓存不缓存"查询结果"，只缓存不可变模型，避免复杂的失效逻辑。

## 10. 性能设计

- **连接池**：`MaxOpenConns` 默认 50，按 CPU × 4 调整；`ConnMaxLifetime` 30 分钟。
- **批处理**：插入/更新批量提交；关闭 `autocommit`，由命令控制事务。
- **避免 N+1**：查询任务时按需 join 流程实例字段，不逐条查询。
- **大字段分离**：变量大文本走 `LONG_` 或 `BYTEARRAY_ID_`，列表查询不选大字段。
- **历史表膨胀**：提供清理作业与分区建议（按月分区需改 Schema，默认不启用）。
- **慢 SQL**：超过 200ms 记录日志与指标，附执行计划摘要。
- **压测基线**：见 012 文档，PR 合并前对比关键基准。

## 11. 数据迁移与兼容缺口

| 缺口 | 影响 | 方案 |
| --- | --- | --- |
| Java 原生序列化变量 | Go 无法反序列化 | 迁移工具扫描并报告；提供 Java 侧导出为 JSON 的一次性脚本；运行期遇到则返回明确错误 |
| Java 委托类 | 无法执行 | 迁移工具列出 `flowable:class`；要求改写为 Go 委托或表达式 |
| 自定义 MyBatis 查询 | 不影响数据 | 无需迁移 |
| 自定义 History Level | 可能未知 | 启动时校验，未知级别拒绝启动 |
| 表前缀 | 部分客户使用自定义前缀 | 配置 `tablePrefix`，SQL 模板统一注入 |
| 大小写排序差异 | 查询结果顺序不同 | 显式 `ORDER BY`，不依赖数据库默认 |

## 12. 测试要点

- Schema 建表/升级/回滚在 PG14、PG16、MySQL 8.0 上全量执行。
- 每个实体仓储：插入、更新、乐观锁冲突、删除、分页、空值。
- Flush 顺序：父子实体同事务插入不违反外键。
- 并发：100 goroutine 同时更新同一执行，只有 1 个成功。
- 方言：同一查询在两种数据库生成等价 SQL，结果一致。
- 数据兼容：用 Flowable 8.x 初始化的 fixture 库启动 Go 引擎并读取。
- 迁移工具：对 Java 序列化变量、Java 委托、未知元素给出准确报告。
- 性能：批量插入 10,000 条执行记录 < 2 秒（本地 PG）。
