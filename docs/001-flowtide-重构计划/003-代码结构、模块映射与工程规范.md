## 3. 依赖规则与包边界

~~~mermaid
flowchart LR
    CMD[cmd/*] --> API[api]
    API --> MODEL[bpmn/model]
    API --> INTERNAL[internal/*]
    REST[internal/rest] --> API
    RUNTIME[internal/runtime] --> PERSIST[internal/persistence]
    RUNTIME --> EXPR[internal/expression]
    RUNTIME --> VAR[internal/variable]
    RUNTIME --> BPMNXML[internal/bpmn/xml]
    PERSIST --> DIALECT[internal/persistence/dialect]
    JOB[internal/job] --> CMD2[internal/command]
    HISTORY[internal/history] --> PERSIST
    TEST[test/*] --> API
~~~

强制规则：

1. `bpmn/model` 不得导入任何 `internal/` 包。
2. `internal/persistence` 不得导入 `internal/runtime`；需要运行时数据时使用接口参数。
3. `internal/rest` 不得直接调用仓储；只能调用 `api` 服务接口。
4. `cmd/` 不得包含业务判断；只负责读配置、构造引擎、启动/停止。
5. 禁止循环依赖；CI 使用 `go list -deps` + `depguard` 校验。
6. 任何 `internal/` 包不得暴露到公共 API 的签名中（用 DTO 转换）。

## 4. 公共 API 设计

### 4.1 引擎门面

~~~go
// Engine 是流程引擎实例，聚合全部服务。
// 实现应并发安全；Close 后所有服务调用返回 ErrEngineClosed。
type Engine interface {
    // RepositoryService 返回仓库服务。
    // @return 仓库服务
    RepositoryService() RepositoryService

    // RuntimeService 返回运行时服务。
    // @return 运行时服务
    RuntimeService() RuntimeService

    // TaskService 返回任务服务。
    // @return 任务服务
    TaskService() TaskService

    // HistoryService 返回历史服务。
    // @return 历史服务
    HistoryService() HistoryService

    // ManagementService 返回管理服务。
    // @return 管理服务
    ManagementService() ManagementService

    // IdentityService 返回身份服务。
    // @return 身份服务
    IdentityService() IdentityService

    // Close 优雅关闭引擎。
    // @param ctx 关闭超时上下文
    // @return error 关闭错误
    Close(ctx context.Context) error
}

// New 创建流程引擎。
// @param ctx 启动上下文
// @param cfg 引擎配置
// @param opts 可选构造选项
// @return 引擎实例
// @return error 启动错误
func New(ctx context.Context, cfg Config, opts ...EngineOption) (Engine, error) { /* ... */ }
~~~

### 4.2 服务接口风格

- 所有方法第一个参数为 `context.Context`（除纯计算）。
- 查询方法返回 `(结果, error)`；列表返回 `(items, total, error)` 或独立 `Count`。
- 变更方法返回受影响实体或 `error`。
- 不使用可变参数表达业务语义（除 Options）。
- 不暴露 `*sql.Tx`、内部实体、内部枚举。

~~~go
// RuntimeService 提供流程实例与执行的运行时操作。
type RuntimeService interface {
    // StartProcessInstanceByKey 按流程定义 Key 启动实例。
    // @param ctx 上下文
    // @param key 流程定义 Key
    // @param businessKey 业务键，可为空
    // @param vars 启动变量
    // @param opts 启动选项（租户、名称、回调等）
    // @return 流程实例
    // @return error 启动错误
    StartProcessInstanceByKey(ctx context.Context, key, businessKey string, vars map[string]any, opts ...StartOption) (ProcessInstance, error)

    // DeleteProcessInstance 删除流程实例。
    // @param ctx 上下文
    // @param processInstanceID 实例 ID
    // @param reason 删除原因，写入历史
    // @return error 删除错误
    DeleteProcessInstance(ctx context.Context, processInstanceID, reason string) error
}
~~~

### 4.3 查询构造器

采用"不可变链式"或"可变链式"二选一。为贴近 Flowable 且便于复用，选择**可变链式 + 显式 Clone**：

~~~go
// ProcessInstanceQuery 是流程实例查询构造器。
// 构造器不是并发安全的，单次查询内使用。
type ProcessInstanceQuery interface {
    // ProcessDefinitionKey 按流程定义 Key 过滤。
    // @param key 流程定义 Key
    // @return 查询构造器
    ProcessDefinitionKey(key string) ProcessInstanceQuery

    // BusinessKey 按业务键过滤。
    // @param key 业务键
    // @return 查询构造器
    BusinessKey(key string) ProcessInstanceQuery

    // IncludeProcessVariables 查询结果包含流程变量。
    // @return 查询构造器
    IncludeProcessVariables() ProcessInstanceQuery

    // OrderByProcessInstanceId 按实例 ID 排序。
    // @param asc 是否升序
    // @return 查询构造器
    OrderByProcessInstanceId(asc bool) ProcessInstanceQuery

    // List 分页查询。
    // @param ctx 上下文
    // @param offset 偏移量，从 0 开始
    // @param size 每页数量，最大 1000
    // @return 实例列表
    // @return 总数
    // @return 查询错误
    List(ctx context.Context, offset, size int) ([]ProcessInstance, int64, error)
}
~~~

### 4.4 变量与 DTO

- 公共 DTO 使用值类型 + 指针可空字段表达"未设置"。
- 时间统一 `time.Time`，序列化为 ISO-8601 UTC（REST 层可带偏移）。
- 变量值使用 `any`，但写入前经类型推断；跨语言场景强制 JSON 可表达。
- ID 一律 `string`，不透明，调用方不得解析。

~~~go
// ProcessInstance 是流程实例的只读视图。
type ProcessInstance struct {
    ID                 string            // 实例 ID
    ProcessDefinitionID string           // 流程定义 ID
    ProcessDefinitionKey string          // 流程定义 Key
    ProcessDefinitionVersion int         // 流程定义版本
    BusinessKey        string            // 业务键
    Name               string            // 实例名称
    TenantID           string            // 租户
    StartTime          time.Time         // 开始时间
    EndTime            *time.Time        // 结束时间，运行中为 nil
    Ended              bool              // 是否已结束
    Suspended          bool              // 是否挂起
    Variables          map[string]any    // 变量，按需加载
}
~~~

## 5. 编码规范

### 5.1 注释规范（强制）

每个函数（含未导出）必须有中文注释，并标注参数与返回值。自定义 `doccheck` 分析器在 CI 中强制执行。

~~~go
// CalculateNextDueDate 计算定时器下一次触发时间。
// 支持 ISO-8601 重复间隔与 cron 表达式。
// @param now 当前时间
// @param repeat 重复表达式，如 R3/PT10M
// @param dueDate 当前到期时间
// @return 下次到期时间
// @return 是否还有下一次
// @return 解析错误
func CalculateNextDueDate(now time.Time, repeat string, dueDate time.Time) (time.Time, bool, error) { /* ... */ }
~~~

规则：

1. 注释以函数名开头，使用中文完整句子。
2. 每个参数一行 `@param 参数名 说明`；无参数写 `@param 无`。
3. 每个返回值一行 `@return 说明`；无返回值写 `@return 无`。
4. 导出类型、常量、包必须有中文注释。
5. 复杂分支（圈复杂度 ≥ 3 的函数内分支）加行注释说明"为什么"，不是"做了什么"。
6. TODO 必须带负责人与 issue：`// TODO(@alice, #123): ...`。

### 5.2 命名

| 类别 | 规则 | 示例 |
| --- | --- | --- |
| 包 | 小写单词，不用下划线 | `persistence`、`expression` |
| 接口 | 名词，不加 `I` 前缀 | `RuntimeService` |
| 实现 | `Default` 或 `SQL` 前缀 | `defaultRuntimeService` |
| 错误 | `Err` 前缀 | `ErrDefinitionNotFound` |
| 选项 | `With` 前缀 | `WithHistoryLevel` |
| 上下文键 | 私有类型，不用 string | `type ctxKey int` |
| 测试 | `TestXxx_场景` | `TestStart_WithVariables` |

### 5.3 错误处理

- 禁止忽略 error；必须处理、包装或显式注释原因。
- 包装使用 `fmt.Errorf("...: %w", err)`，保留 `errors.Is` 链。
- 对外错误统一 `*EngineError`，含稳定错误码。
- 不使用 `panic` 表达业务错误；仅用于不可恢复的编程错误（如 Agenda 溢出），并由 RecoveryInterceptor 兜底。

### 5.4 并发与资源

- 所有可能阻塞的调用接收 `context.Context`。
- 禁止在循环内创建无界 goroutine。
- `sql.Rows`、`http.Response.Body` 必须 `defer Close`。
- 共享 map 必须加锁或使用 `sync.Map`；优先不可变数据 + 原子替换。
- 时间统一通过注入的 `Clock`，禁止直接 `time.Now()`（测试与定时器场景除外，需注释）。

### 5.5 日志

- 使用 `slog`，结构化字段，禁止字符串拼接。
- 级别约定：Debug（SQL/议程细节）、Info（生命周期/部署）、Warn（重试/降级）、Error（失败）。
- 不记录变量值、密码、Token；敏感字段统一脱敏。

## 7. 版本与发布

- 语义化版本：`vMAJOR.MINOR.PATCH`；MAJOR 对应不兼容 API/数据变更。
- 预发布：`v0.x` 阶段允许破坏性变更，但必须写迁移说明。
- 引擎版本写入 `ACT_GE_PROPERTY` 的 `flowtide.version`，Java 引擎忽略该行。
- 数据库 Schema 版本单独记录 `schema.version`，与 Flowable 8.x 保持同值。
- 发布物：源码 tag、二进制、容器镜像、Helm Chart、OpenAPI 文件、CHANGELOG。
- 兼容承诺：同一 MAJOR 内，`api/` 的导出符号不删除；新增字段使用可选。

## 8. 与 Java 版并存的策略

~~~mermaid
flowchart LR
    J[Java Flowable] -->|同一数据库| DB[(ACT_*)]
    G[Go Flowable] -->|同一数据库| DB
    DB --> M[迁移工具]
~~~

- **禁止双写**：同一流程实例同一时刻只能由一个引擎推进，否则会破坏令牌状态。
- 推荐切换方式：停写 → 等待作业清空 → 切换流量 → Go 引擎接管 → 观察。
- 迁移工具只读扫描并生成报告：不支持的 BPMN 元素、Java 序列化变量、Java 委托类、定时器。
- 回滚窗口内，Go 引擎写入的数据必须能被 Java 引擎读取（Schema 兼容）。
