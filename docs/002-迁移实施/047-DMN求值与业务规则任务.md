# 047 DMN 求值与业务规则任务

> 文档编号：002-047  
> 更新日期：2026-10-28  
> 对应计划：005 BPMN 模型、XML 解析与部署校验；006 流程执行引擎 PVM 设计

## 1. 背景

046 期只实现了 DMN 决策元数据读取，BPMN 业务规则任务仍未执行。本期在纯标准库前提下实现一个**安全子集**的 DMN 决策表求值，并把结果接入 BPMN 业务规则任务：

- 部署 ZIP 中的 `.dmn` 与 `.bpmn20.xml` 一起落库；
- 进入 `businessRuleTask` 时按 `decisionRef` 在当前流程定义所在部署查找决策；
- 只支持确定性的单表求值，不执行脚本、不访问外部服务；
- 求值失败返回 400 `ENGINE` 错误，由引擎命令边界统一回滚。

## 2. 模型与解析

### 2.1 BPMN 模型

`bpmn/model/model.go` 新增：

~~~go
type BusinessRuleTask struct {
    FlowNodeBase
    DecisionRef    string // 决策引用：decision id 或 decision table id
    ResultVariable string // 结果变量名，为空时按输出列写入多个变量
}

func (t *BusinessRuleTask) ElementType() string { return "businessRuleTask" }
~~~

### 2.2 XML 解析

`internal/bpmn/xml/parse.go` 新增 `businessRuleTask` 分支：

- 复用 `parseFlowNodeBase` 解析 `id`、`name`、异步、补偿、文档等公共字段；
- 使用 `attrAny` 依次读取 Flowable 命名空间、Activiti 命名空间与无前缀属性：
  - `flowable:decisionRef` / `activiti:decisionRef` / `decisionRef`
  - `flowable:resultVariable` / `activiti:resultVariable` / `resultVariable`
- 缺少 `decisionRef` 不在部署期报错，而是在进入任务时返回 `ENGINE-1910`。

## 3. 部署内查找

`internal/engine/dmn_eval.go` 的 `findDMNDecision`：

1. 通过当前执行的 `DefinitionID` 找到流程定义与 `DeploymentID`；
2. 只读取该部署的资源，资源名以 `.dmn` 结尾（大小写不敏感）；
3. 按资源名升序解析，保证同名决策的查找顺序稳定；
4. 决策 ID 与决策表 ID 任一等于 `decisionRef` 即命中；
5. 复用 `dmn.go` 已有的 `collectDecisionNodes` 与 `Node` 解析能力，不修改
   `ListDecisionDefinitions` / `ListDecisionTables` 的既有行为。

查找范围**不跨部署聚合**，也不读取最新版本的其他部署。

## 4. 求值语义

### 4.1 输入表达式

`inputExpression` 的文本按 `internal/expr` 编译求值：

- 变量名：`amount`；
- 简单表达式：`level * 2`、`amount + 1`；
- `${...}` / `#{...}` 表达式；
- 表达式放在 `text` 属性中同样兼容。

表达式为空或编译/求值失败返回 `ENGINE-1913`。变量不存在时表达式结果为 `nil`，不会单独报错；后续条件通常不命中。

### 4.2 输入条件

支持以下写法，任一分支命中即视为该输入匹配：

| 写法 | 示例 | 说明 |
| --- | --- | --- |
| 任意 | `-` | 空单元格同样按任意处理 |
| 字符串 | `"gold"`、`'silver'` | 单/双引号，严格字符串相等 |
| 布尔 | `true`、`false` | 大小写不敏感 |
| 数字相等 | `42` | 整数优先 `int`，否则 `float64` |
| 比较 | `< 100`、`<= 100`、`> 0`、`>= 0`、`= 1`、`== 1`、`!= 1` | 数字按数值比较，字符串按字典序比较 |
| 区间 | `[1..10]`、`(1..10]`、`[1..10)`、`(1..10)` | 含端点由括号决定 |
| 反向区间 | `]1..10[` | 两端均不包含 |
| 开区间 | `[..10]`、`[10..]` | 缺省端点表示无界 |
| 多值 | `"gold", 'silver'` | 顶层逗号分隔，引号内逗号不拆分 |
| 字符串区间 | `["a".."c"]` | 字典序比较 |

类型不匹配（例如字符串输入与数字比较）按不命中处理；条件语法错误、引号未闭合、非法字面量等返回 `ENGINE-1914`。

### 4.3 输出转换

| 输出单元格 | 结果 |
| --- | --- |
| `"high"` / `'high'` | 字符串 |
| `42` / `1.5` | `int` / `float64` |
| `true` / `false` | 布尔 |
| `-` 或空 | 跳过，不写变量 |
| `${amount * 2}` / `#{name}` | 用流程变量求值后写入 |
| 其他裸文本 | 按字符串写入 |

引号未闭合、`${...}` 编译或求值失败返回 `ENGINE-1919`。

### 4.4 命中策略

`hitPolicy` 为空时按 `FIRST` 处理，大小写与下划线不敏感。

| 策略 | 语义 |
| --- | --- |
| `FIRST` | 返回第一条匹配规则 |
| `RULE ORDER` | 简化为返回第一条匹配规则，不做多规则聚合 |
| `UNIQUE` | 多条规则匹配即冲突，返回 `ENGINE-1916`（即使输出相同） |
| `ANY` | 允许多条匹配，但所有输出必须逐列一致，否则 `ENGINE-1917` |
| 其他（`COLLECT`、`OUTPUT ORDER`、`PRIORITY` 等） | 返回 `ENGINE-1918` |

所有策略在没有规则匹配时返回 `ENGINE-1915`。这一定义让“规则漏配”在流程执行时立即暴露，而不是静默写入空结果。

## 5. 变量写入

设输出列顺序为 `out1..outN`：

- `ResultVariable` 非空：
  - 单输出：把该输出值直接写入结果变量；
  - 多输出：写入 `map[string]any`，键优先取输出 `id`，缺失时取 `name`，值为各输出结果；
  - 输出为 `-` 时单输出写入 `nil`，多输出从映射中省略该列。
- `ResultVariable` 为空：
  - 每个产生值的输出列写入流程变量，变量名优先取 `id`，缺失时取 `name`；
  - 输出 `-` 不写入，不会覆盖已有变量；
  - 多输出中某列既无 `id` 也无 `name` 时返回 `ENGINE-1920`。

写入复用 `e.setVariable`，与脚本/服务任务保持同样的作用域与历史变量记录语义。

## 6. 错误码与回滚

| 错误码 | 场景 |
| --- | --- |
| `ENGINE-1910` | 业务规则任务缺少 `decisionRef` |
| `ENGINE-1911` | 部署不存在、部署内无 DMN、决策不存在、决策没有决策表 |
| `ENGINE-1912` | 决策表没有输出列 |
| `ENGINE-1913` | 输入表达式为空或求值失败 |
| `ENGINE-1914` | 输入条件非法 |
| `ENGINE-1915` | 没有匹配规则 |
| `ENGINE-1916` | `UNIQUE` 命中多条规则 |
| `ENGINE-1917` | `ANY` 多规则输出不一致 |
| `ENGINE-1918` | 不支持的命中策略 |
| `ENGINE-1919` | 输出项非法或表达式求值失败 |
| `ENGINE-1920` | 输出列缺少 `id` 与 `name` |

以上错误均以 `api.ErrBadRequest` 作为 Cause，REST 层映射为 400。非法 DMN XML 沿用 046 期的 `ENGINE-1207` / 400。

业务规则任务在命令内执行，任一步骤返回错误都会触发 `execute` 的状态备份回滚，流程实例、活动历史与变量均不会落库。

## 7. BPMN 执行语义

`internal/engine/runtime.go` 新增：

~~~go
case *model.BusinessRuleTask:
    if err := e.executeBusinessRuleTask(cc, execution, node); err != nil {
        return err
    }
    e.cancelBoundaryTimers(execution.ID)
    e.cancelBoundarySubscriptions(execution.ID)
    e.registerCompensation(cc, execution, node.ID)
    e.recordActivityEnd(cc, execution.CurrentHistActivityID)
    execution.CurrentHistActivityID = ""
    return e.scheduleTakeOutgoing(cc, execution, node)
~~~

即：

- 业务规则任务按同步任务执行，求值成功后立即沿出线继续；
- 与同步服务任务一致，清理边界定时器/订阅并登记补偿处理器；
- 不在任务内创建用户任务或外部作业；
- 普通 BPMN 流程分支未改动，原有行为保持不变。

## 9. 限制

1. **每次进入任务重新解析部署中的 DMN**：引擎状态中没有 DMN 解析缓存，解析成本与部署内 `.dmn` 数量、文档大小相关；后续可在引擎级增加只读缓存。
2. **只支持单层决策表**：不处理 `decision` 之间的依赖、`knowledgeModel`、BKM、literal expression 与决策服务。
3. **只支持确定性子集**：不支持日期/时间、duration、list、context、`not()`、`some/every`、自定义函数等 FEEL 能力；输出与输入类型不做 `typeRef` 强制转换。
4. **输入条件不支持 `${...}` 表达式**：输入单元格只接受本文列出的字面量与比较/区间写法；需要计算时请写在 `inputExpression` 中。
5. **`RULE ORDER` 已简化**：只返回第一条匹配规则，不做多规则输出聚合。
6. **`COLLECT` / `OUTPUT ORDER` / `PRIORITY` 未实现**：返回 400，避免静默产生与 Flowable 不一致的结果。
7. **多输出 + 结果变量使用映射**：键优先输出 `id`，其次 `name`；如果需要平铺流程变量，请不配置 `ResultVariable`。
8. **无匹配规则按错误处理**：与部分 Flowable 版本返回空结果的差异在此明确；如业务允许空结果，应在决策表中配置兜底 `-` 规则。
9. **同名决策**：同一部署内多个 `.dmn` 出现相同 decision id 时，按资源名升序取第一个，不报重复错误。
