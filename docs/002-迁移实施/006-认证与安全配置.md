# 006 认证与安全配置

> 文档编号：002-006  
> 更新日期：2026-10-28  
> 状态：Basic Auth / Bearer Token 已实现；RBAC 与多租户待完成

## 1. 启用方式

### 1.1 服务端参数

~~~bash
# Basic Auth
flowable-server -basic-auth alice:secret

# Bearer Token
flowable-server -bearer-token token-1
~~~

- 两者可同时配置，满足任一即通过。
- 未配置任何认证时，保持开放（仅适合内网/演示）。

### 1.2 代码方式

~~~go
handler := rest.New(engine,
    rest.WithBasicAuth(map[string]string{"alice": "secret"}),
    rest.WithBearerToken("token-1"),
).Handler()
~~~

## 2. 行为

| 路径 | 认证 |
| --- | --- |
| `/healthz`、`/readyz` | 公开 |
| `/service/**` | 必须认证 |
| 其他 | 公开 |

- 失败返回 401，附带 `WWW-Authenticate: Basic realm="flowable"`。
- 密码/令牌使用常量时间比较。
- 认证只做身份校验，不做权限控制。

## 2.1 RBAC

~~~go
handler := rest.New(engine,
    rest.WithBasicAuth(map[string]string{"alice": "secret"}),
    rest.WithRBAC(
        map[string][]string{"alice": {"reader"}},
        map[string][]string{"reader": {"read"}, "admin": {"admin"}},
    ),
).Handler()
~~~

- 端点权限：GET/HEAD 需要 `read`，写操作需要 `write`，管理/身份端点需要 `admin`。
- 用户角色来自 `userRoles`；角色权限来自 `rolePermissions`。
- Bearer Token 视为服务账号，拥有全部权限。
- 未配置 `WithRBAC` 时只认证不鉴权。
- 失败返回 403。

## 2.2 身份库认证与密码

~~~go
handler := rest.New(engine, rest.WithIdentityAuth())
~~~

- Basic Auth 可回退到身份库校验用户名/密码。
- 创建用户时传 `password`，引擎使用 PBKDF2-SHA256（12 万次迭代、随机盐）保存哈希。
- 用户 `roles` 持久化在身份库，可与 `WithRBAC` 的角色权限组合。
- 密码哈希不通过 JSON 输出。

## 2.2.1 用户更新与角色

- `PUT /service/identity/users/{id}` 更新资料、角色、禁用状态。
- `PUT /service/identity/users/{id}/roles` 单独设置角色。
- 更新时传 `password` 会重置密码；不传则保留原哈希。
- 禁用用户 `CheckPassword` 直接失败。

## 2.2.2 角色与权限实体

- `GET/POST /service/identity/roles`
- `GET/PUT/DELETE /service/identity/roles/{id}`
- 角色包含 `permissions`；启用 `WithIdentityAuth` 时，RBAC 会把角色实体的权限与配置权限合并。
- 不配置 `WithRBAC` 的 `rolePermissions` 时，权限完全来自角色实体。

## 2.3 密码修改与锁定

- `PUT /service/identity/users/{id}/password`：
  - 传 `oldPassword` 时校验旧密码后修改；
  - 不传时作为管理员重置。
- 连续 5 次密码错误锁定 5 分钟。
- 修改/重置/成功登录都会清零失败计数与锁定。
- 失败计数通过命令提交持久化，不会因认证失败回滚。

## 2.4 限流与 TLS

- `WithRateLimit(rate, burst)`：令牌桶限流，超限 429。
- 只限制 `/service/**`，健康检查不限流。
- 服务端参数：`-rate-limit`、`-rate-burst`。
- `-tls-cert` + `-tls-key` 启用 HTTPS；两者必须同时配置。

## 2.5 审计日志

- `WithAuditLog(size)` 启用内存审计。
- 记录 `/service/**` 的方法、路径、状态、耗时、用户、租户、客户端地址。
- 查询端点：`GET /service/management/audit-logs`（RBAC 下需 admin）。
- 容量满后保留最近事件。

## 2.6 指标

- `WithMetrics()` 启用 `GET /metrics`。
- 输出 Prometheus 文本：请求总数（method/status）、耗时总和/次数、进行中请求数。
- `/metrics` 自身不计数，且不需要认证。
- 目前只有 HTTP 指标，流程/作业指标待补。

## 2.7 租户过滤

- 部署、启动实例可通过 `X-Tenant-Id` 请求头或请求体 `tenantId` 指定租户。
- 部署/定义/实例列表支持 `X-Tenant-Id` 或 `?tenantId=` 过滤。
- 任务查询支持 `?tenantId=`。
- 租户校验已下沉到引擎服务层：跨租户按 ID 查询/操作返回 404。
- 列表接口仍显式过滤。
- SQL 仓储查询尚未自动追加租户条件。

## 3. 已知限制

1. 用户表为内存/快照存储，尚未接入外部 LDAP/AD。
2. 锁定为单用户计数，未做 IP/全局限流。
2. 无角色/权限模型，认证通过即可访问全部端点。
3. 无 TLS 终止；生产需在反向代理或 `http.Server` 上配置 TLS。
4. SQL 仓储/行加载尚未自动追加租户条件。
5. 无速率限制、审计日志、Token 过期/刷新。
