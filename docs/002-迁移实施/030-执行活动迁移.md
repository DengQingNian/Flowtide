# 030 执行活动迁移（change-state）

> 文档编号：002-030  
> 更新日期：2026-10-28  
> 对应计划：006 流程执行引擎 PVM 设计；011 REST API 与兼容契约

## 1. 背景

Flowable 管理端支持把运行中的执行直接移动到指定活动（change activity state），常用于：

- 跳过/回退人工任务；
- 修复卡住的流程；
- 将令牌移动到补偿/异常处理分支。

本期实现执行级与实例级迁移端点，采用同步、单目标活动的安全子集。

## 2. 引擎 API

`RuntimeService` 新增：

| 方法 | 说明 |
| --- | --- |
| `ChangeActivityState(ctx, executionID, activityIDs)` | 移动指定执行 |
| `ChangeProcessInstanceState(ctx, instanceID, activityIDs)` | 移动实例根执行 |

规则：

- 执行/实例不存在返回 404；已结束、已挂起返回 409。
- 目标活动为空返回 400；目标活动不存在返回 404。
- 目标必须是流程节点（事件、任务、网关、子流程等），顺序流等非节点返回 400。
- 当前仅支持单个目标活动；多目标返回 400。
- 移动前取消当前执行上的运行中任务、边界定时器与事件订阅，并结束当前历史活动。
- 移动后从目标活动继续执行：用户任务会创建新任务，结束事件会结束实例。

## 3. 端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/service/runtime/executions/{id}/change-state` | 移动执行 |
| POST | `/service/runtime/process-instances/{id}/change-state` | 移动实例根执行 |

请求：

~~~json
{"startActivityIds": ["taskB"]}
~~~

- 成功返回 204。
- 空数组 400；多目标 400；目标不存在 404；实例挂起 409。
- 实例端点会自动选择未结束且无父执行的根执行。

## 4. 审计

- 当前活动历史记录写入结束时间。
- 被取消的任务写入历史结束、删除原因 `change-state`，并记录任务日志（delete）。
- 目标活动重新写入历史开始记录。

## 5. 限制

1. 仅支持单目标活动，未实现多目标并发分支。
2. 只支持当前流程顶层节点；子流程内部活动迁移未实现。
3. 不处理多实例、补偿作用域的特殊语义。
4. 未提供 `currentActivityId` 校验参数，默认以执行当前活动为准。
5. 取消任务不触发任务删除监听器/边界错误事件。

## 6. 测试

- `internal/engine/change_state_test.go`：执行/实例迁移、任务替换、完成后结束、挂起/缺失/多目标/非节点错误。
- `internal/rest/change_state_test.go`：两个端点、错误路径、任务迁移结果。
- 覆盖率：`internal/engine` 90.8%，`internal/rest` 90.6%。
