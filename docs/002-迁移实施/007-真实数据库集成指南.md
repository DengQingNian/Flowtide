# 007 真实数据库集成指南

> 文档编号：002-007  
> 更新日期：2026-10-28  
> 状态：MySQL 8.0.35 完整 Schema、快照恢复、迁移命令及服务启动验收通过

## 1. 推荐的 MySQL 测试入口

仓库已依赖 `github.com/go-sql-driver/mysql`，不再需要手动添加驱动。现有 `.env` 的 `db_mysql_*` 配置直接可用。

```bash
FLOWABLE_MYSQL_INTEGRATION=1 go test -count=1 -v ./internal/persistence/mysql
```

默认不访问数据库；显式启用后任何连接或权限错误均导致测试失败。Schema 测试和快照测试各自创建唯一临时库，分别验证完整 DDL/重复初始化及快照原子保存/引擎重启恢复，正常结束后删除临时库；账号需要创建和删除数据库权限。

更换数据库后，已在 MySQL 8.0.35 上重新执行完整测试：41 张表初始化、重复初始化、启动校验及快照恢复全部通过；迁移命令和服务 MySQL 模式下的两次启动、健康检查、优雅退出、快照保存也验证通过。所有验证均使用独立临时库，结束后已清理。

上一次 MySQL 8.4.9 开发容器的 512 MiB 内存限制曾导致完整 Schema 测试被 OOM 中断，该阻塞已通过更换数据库环境解除。单独验证快照可使用：

```bash
FLOWABLE_MYSQL_INTEGRATION=1 go test -count=1 -v ./internal/persistence/mysql -run '^TestIntegrationMySQLSnapshot$'
```

配置规则、分阶段计划、测试范围与当前限制见 [052 MySQL 集成计划与首阶段实现](052-MySQL集成计划与首阶段实现.md)。

## 2. 初始化开发库并启动

```bash
go run ./cmd/flowable-migrate -dialect mysql -apply -env .env
go run ./cmd/flowable-server -storage mysql -env .env
```

服务仅校验已初始化的 Schema。迁移命令在没有引擎表时执行建表，已有完整 Schema 时校验版本和完成标记。部分表、缺失标记与版本冲突均拒绝自动接管。

## 3. 原有通用 SQL 测试入口

`internal/persistence/flowable` 下原有 `TestIntegrationSQL` 仍供自定义驱动验证使用，依赖 `FLOWABLE_TEST_DRIVER`、`FLOWABLE_TEST_DSN` 与 `FLOWABLE_TEST_DIALECT`；调用方必须自行注册驱动。它会在给定目标库直接建表且不清理，不支持重复执行。MySQL 开发优先使用上面的新入口。

PostgreSQL 驱动和对应真实数据库验证尚未接入，后续另行实施。
