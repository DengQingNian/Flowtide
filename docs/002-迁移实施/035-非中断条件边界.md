# 035 非中断条件边界事件

> 文档编号：002-035
> 更新日期：2026-10-28
> 对应计划：006 流程执行引擎 PVM 设计；031 条件事件

## 1. 背景

031 期实现条件事件时，为保证安全子集，边界条件事件统一按中断语义处理：
即使 BPMN 模型声明 `cancelActivity="false"`，条件命中后也会取消依附的用户任务。

本期补齐 **非中断边界条件事件**：条件命中时保留原用户任务，创建并发子执行沿边界出线继续，
并保留条件订阅，使后续变量变化或显式求值可以再次触发。

## 2. 语义

### 2.1 非中断命中（`cancelActivity="false"`）

条件命中后：

1. 不删除依附执行上的运行中任务，任务历史活动保持未结束；
2. 不清理依附执行的边界定时器、边界消息/信号订阅与条件订阅；
3. 在原用户任务执行下创建一个并发子执行（`ParentID` 指向任务执行），
   子执行以边界事件为起点，沿边界事件出线继续；
4. 原用户任务执行保持 `Waiting=true`，流程继续等待任务完成；
5. 条件订阅保留，后续变量变化、显式求值或该实例的其他求值入口可再次触发，
   每次触发都会产生一条新的边界路径。

### 2.2 中断命中（`cancelActivity="true"`，默认值）

保持既有行为不变：

1. 删除依附执行上的运行中任务并写任务结束历史；
2. 结束当前活动历史；
3. 取消依附执行上的边界定时器与边界订阅（含条件订阅）；
4. 清除等待状态，执行切换到边界事件并沿出线继续。

### 2.3 表达式的错误语义

条件表达式求值失败仍返回 `ENGINE-0631`，命令整体回滚，不静默忽略。
非中断与中断边界的错误语义一致。

## 3. 实现

### 3.1 触发入口

`internal/engine/conditional.go`：

- `triggerConditionalSubscription`：边界条件订阅先解析边界事件，
  读取 `boundary.CancelActivity` 作为 `forceInterrupt` 传给 `triggerBoundaryEvent`；
  中间捕获条件事件仍走 `triggerCatchConditionalSubscription`。
- `conditionalBoundaryEvent`：按订阅的执行、流程定义、流程元素逐层解析边界事件。
  定义缺失时返回不存在，调用方删除陈旧订阅，避免无效订阅持续参与求值。
- `registerConditionalBoundarySubscriptions`：订阅的 `Interrupting` 字段改为记录
  `boundary.CancelActivity`，与 BPMN 语义保持一致；触发时仍以模型中的
  `cancelActivity` 为准，避免持久化/恢复后字段缺失导致语义漂移。

### 3.2 边界事件触发

`internal/engine/events.go` 的 `triggerBoundaryEvent` 继续承担两种边界语义：

- 中断分支（`boundary.CancelActivity || forceInterrupt`）逻辑保持不变；
- 非中断分支创建并发子执行、调度边界事件出线，不改写父执行的
  `Waiting` 与 `CurrentHistActivityID`，因此原任务历史活动保持打开；
- 订阅消费改为 `defer`：默认删除订阅（包括提前返回路径），
  仅当「非中断 + 条件订阅」时保留，保证消息/信号非中断边界仍是一次性订阅。

### 3.3 求值范围与防循环

`internal/engine/conditional.go` 新增：

- `evaluateConditionalSubscriptionsOnExecution`：只求值指定执行上的订阅；
- `evaluateConditionalSubscriptionList`：实例级求值可按 `executionID` 过滤。

`internal/engine/runtime.go` 中两处节点进入即求值的入口改为执行级求值：

| 位置 | 原因 |
| --- | --- |
| 用户任务创建后 | 非中断边界路径可能落到新的用户任务，若仍按实例整体求值，会再次命中依附任务保留的订阅，形成自激循环 |
| 中间捕获条件事件注册后 | 边界路径上的捕获条件若按实例整体求值，同样会反向触发依附任务订阅 |

变量变化、完成任务、任务变量写入、`SetVariable`、`EvaluateConditions` 等显式入口
仍按实例整体求值，因此条件持续为真时，后续显式/变量求值可以再次触发。
单次实例级求值对订阅列表做快照，每个订阅最多触发一次，不会在单轮循环内重复触发同一订阅。

### 3.4 历史与等待状态

- 非中断触发不结束父执行当前活动历史，原用户任务完成时才写结束时间；
- 边界事件活动、边界路径上的任务与结束事件由新子执行记录历史，历史实例 ID 不变；
- 父执行 `Waiting=true` 保持不变，直到任务完成或被其他中断事件取消。

## 5. 限制

1. **仅注册用户任务的边界条件事件**：与服务任务、脚本任务等活动的条件边界仍未注册，沿用 031 的范围。
2. **重复触发无去重与上限**：条件持续为真时，每次求值都会新增一条边界路径；流程模型需要自行保证汇合、
   取消或终止，否则可能产生大量并发任务。单次命令仍受议程最大步数保护。
3. **节点进入求值范围收窄**：进入用户任务/中间捕获事件时只求值当前执行上的订阅，
   跨执行的条件依赖变量变化、完成任务、显式求值等入口触发。
4. **主路径结束的实例终止语义**：非中断边界路径与主路径是并发执行，但主路径到达结束事件时
   现有引擎会结束整个实例并清理并发任务；该行为与非中断消息/信号边界一致，本期未调整。
5. **任务完成即取消订阅**：依附任务完成、被中断边界取消、实例结束时都会清理条件订阅，
   之后条件不再触发。
6. **持久化字段**：行表导入不恢复 `Interrupting` 字段，但触发逻辑每次从 BPMN 模型读取
   `cancelActivity`，因此恢复后的边界条件语义仍正确；`Interrupting` 仅作状态说明。
