# 046 DMN 决策元数据

> 文档编号：002-046  
> 更新日期：2026-10-28  
> 对应计划：005 BPMN 模型、XML 解析与部署校验；011 REST API 与兼容契约

## 1. 背景

Flowable 设计器可将 DMN 决策文件（`.dmn`）与 BPMN 一起打包部署。此前
`/repository/process-definitions/{id}/decisions` 与 `.../decision-tables` 两个端点
只校验流程定义存在，然后固定返回空数组，客户端无法读取部署中的决策元数据。

本期只实现 **DMN 元数据读取**：从部署资源中解析决策、决策表、输入列、输出列与规则数量，
不做任何表达式求值，也不改变 BPMN 业务规则任务的执行语义。

## 2. API 类型

定义于 `api/dmn.go`：

~~~go
type DecisionDefinition struct {
    ID           string
    Key          string
    Name         string
    DeploymentID string
    ResourceName string
    TenantID     string
    Version      int // 可选，沿用流程定义版本
}

type DecisionTableInput struct {
    ID         string
    Label      string
    Expression string
}

type DecisionTableOutput struct {
    ID   string
    Name string
    Type string
}

type DecisionTableDefinition struct {
    ID           string
    Key          string
    Name         string
    DeploymentID string
    ResourceName string
    TenantID     string
    HitPolicy    string
    Inputs       []DecisionTableInput
    Outputs      []DecisionTableOutput
    RuleCount    int
}
~~~

`DMNService` 提供两个只读方法：

~~~go
ListDecisionDefinitions(ctx context.Context, processDefinitionID string) ([]DecisionDefinition, error)
ListDecisionTables(ctx context.Context, processDefinitionID string) ([]DecisionTableDefinition, error)
~~~

`*engine.Engine` 实现 `DMNService() DMNService`。为不扩大 `api.Engine` 门面，
额外定义可选的 `api.DMNEngine` 接口（嵌入 `api.Engine` 与 `DMNService()`），
REST 通过类型断言探测 DMN 能力；不支持的引擎返回 500 `ENGINE-1208`。

## 3. 解析规则

- 只要资源名以 `.dmn` 结尾即视为 DMN 资源，扩展名大小写不敏感。
- 使用 `internal/bpmn/xml.Decode` 的通用 Node 树解析，不引入第三方库；最大 16 MiB。
- 根元素本地名必须为 `definitions`。
- 递归收集 `definitions` 下直接或嵌套的 `decision` 节点，保持文档顺序。
- `decision` 必须有直接子元素 `decisionTable`；没有决策表的 decision 被忽略。
- `decision`：读取 `id`、`name`。
- `decisionTable`：读取 `id`、`hitPolicy` 属性；`id` 缺失时回退 decision 的 id。
- `input`：读取 `id`、`label`；其 `inputExpression` 的文本取 `TextContent()`，
  文本为空时回退 `text` 属性。
- `output`：读取 `id`、`name`、`type`；`type` 缺失时回退标准属性 `typeRef`。
- `ruleCount` 为 `decisionTable` 直接子元素 `rule` 的数量。
- 不校验 DMN 命名空间与版本号，只按本地名匹配，兼容 DMN 1.1/1.2/1.3 文档。

## 4. 引擎语义

- 先按 `processDefinitionID` 查找流程定义，不存在返回 `ENGINE-0404` / 404。
- 租户沿用流程定义；跨租户查询按不存在处理，返回 404。
- 只读取该流程定义所在部署的资源，不跨部署聚合。
- 结果按 `resourceName` 升序排序；同一资源内再按 decision id 升序稳定排序。
- 无 DMN 资源或部署缺失时返回非 nil 空切片 `[]`。
- 非法 XML、空内容、根元素错误、DTD 等返回 `ENGINE-1207` / 400，不静默跳过。
- `DecisionDefinition.ID` 与 `Key` 都取 decision 的 `id`；`Version` 沿用所查询流程定义的版本，
  DMN 资源本身不做版本管理。`DecisionTableDefinition.ID` 取 decisionTable 的 `id`，
  `Key` 取 decision 的 `id`。

## 5. REST 端点

### 5.1 决策列表

`GET /service/repository/process-definitions/{id}/decisions`

~~~json
[
  {
    "id": "decisionA",
    "key": "decisionA",
    "name": "Decision A",
    "deploymentId": "dep-1",
    "resourceName": "decisions/alpha.dmn",
    "tenantId": "",
    "version": 1
  }
]
~~~

### 5.2 决策表列表

`GET /service/repository/process-definitions/{id}/decision-tables`

~~~json
[
  {
    "id": "tableA",
    "key": "decisionA",
    "name": "Decision A",
    "deploymentId": "dep-1",
    "resourceName": "decisions/alpha.dmn",
    "tenantId": "",
    "hitPolicy": "UNIQUE",
    "inputs": [{"id": "inputA", "label": "金额", "expression": "amount"}],
    "outputs": [{"id": "outputA", "name": "结果", "type": "string"}],
    "ruleCount": 1
  }
]
~~~

- 空结果输出 `[]`，不输出 `null`。
- 流程定义不存在 404；非法 DMN 400。
- `inputs` / `outputs` 始终输出数组。

## 6. 测试

- `internal/engine/dmn_test.go`：
  - ZIP 部署 BPMN + 两个 `.dmn`（含大写扩展名），校验字段、资源名排序、hitPolicy、
    inputs/outputs、ruleCount；
  - 嵌套 decision、无 decisionTable 的 decision、表 ID 回退、表达式属性回退、typeRef 回退；
  - 无 DMN 返回 `[]`、定义不存在 404、部署缺失返回 `[]`、租户隔离；
  - 空内容、未闭合 XML、错误根元素、DTD 四种非法输入均返回 400 `ENGINE-1207`；
  - 同一资源内按 decision id 排序。
- `internal/rest/definition_artifacts_test.go`：
  - decisions / decision-tables 真实列表与 camelCase 字段；
  - 非法 DMN 400、空列表 `[]`、缺失定义 404；
  - 引擎未实现 DMN 服务时 500 `ENGINE-1208`。
- 覆盖率：`internal/engine` 91.0%（DMN 实现函数 100%），`internal/rest` 90.8%。

## 7. 限制

1. 仅读取元数据，不执行命中策略、输入表达式或输出表达式求值，不产生决策结果。
2. DMN 资源在部署时只存储不解析；非法 DMN 不会使部署失败，而是在查询列表时返回 400。
3. 不建立决策定义的独立版本与持久化 ID，`Version` 仅沿用流程定义版本。
4. 每个 decision 只读取第一个直接 `decisionTable` 子元素。
5. 不解析 DRD、informationRequirement、知识源、函数定义、BPMN 与 DMN 的关联引用。
6. 未提供独立的 DMN 仓库端点（决策定义详情、按 Key 查询、部署/删除）。
7. `api.Engine` 门面未增加 `DMNService()` 方法；调用方需使用 `api.DMNEngine` 或
   `api.DMNService` 类型断言探测能力，避免影响已有引擎实现。
