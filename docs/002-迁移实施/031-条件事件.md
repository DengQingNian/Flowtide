# 031 条件事件（conditional events）

> 文档编号：002-031
> 更新日期：2026-10-28
> 对应计划：006 流程执行引擎 PVM 设计；011 REST API 与兼容契约

## 1. 背景

Flowable/BPMN 的条件事件在变量满足表达式时触发，常用于“金额达到阈值自动跳转”“资料齐备后继续”等场景。
本期实现安全子集：**中断边界条件事件**与**中间捕获条件事件**，复用现有表达式引擎求值。

## 2. 支持范围

| 事件 | 依附/位置 | 行为 |
| --- | --- | --- |
| 边界条件事件 | 用户任务（attachedToRef 为用户任务） | 中断任务，沿边界事件出线继续 |
| 中间捕获条件事件 | 流程任意位置 | 等待条件，满足后沿出线继续 |

不支持：

- 条件开始事件、事件子流程条件开始事件；
- 非中断边界条件事件（运行时按中断语义处理，见限制）；
- 条件事件与其他事件定义同时配置时的组合语义（条件优先）。

## 3. 模型与解析

- `model.BoundaryEvent` 新增 `Condition string`。
- `model.IntermediateCatchEvent` 新增 `Condition string`。
- `internal/bpmn/xml/parse.go` 新增 `parseCondition`：

```xml
<boundaryEvent id="amountReached" attachedToRef="review">
  <conditionalEventDefinition>
    <condition>${amount > 100}</condition>
  </conditionalEventDefinition>
</boundaryEvent>
```

兼容 Flowable 的 `conditionExpression` 子元素。条件文本为空或缺失时解析失败（`BPMN-1009`），避免静默忽略。
表达式支持带定界符（`${...}`）或裸表达式（如 `amount > 100`）。

## 4. 引擎语义

### 4.1 边界条件事件

1. 进入用户任务并创建任务后，注册 `EventType="condition"` 的订阅，`Condition` 保存表达式，`BoundaryEventID` 指向边界事件。
2. 注册后立即求值一次；条件已满足则直接取消任务，不产生等待。
3. 变量变化后再次求值。
4. 条件为真时：
   - 删除条件订阅；
   - 删除执行上的运行中任务并写历史结束；
   - 结束当前活动历史；
   - 取消该执行的边界定时器与其他边界订阅；
   - 执行切换到边界事件，沿边界出线继续。
5. 任务正常完成、服务任务/脚本任务/手动任务完成时，原有清理逻辑会删除条件订阅，条件不会在活动结束后误触发。

### 4.2 中间捕获条件事件

1. 进入捕获事件时注册条件订阅，执行进入 `Waiting=true`。
2. 立即求值一次；满足则结束捕获活动并沿出线继续，不再等待。
3. 未满足时等待变量变化；触发后删除订阅、结束活动历史、清除等待状态、调度出线。

### 4.3 求值规则

- 使用 `internal/expr.EvalBool`，与顺序流条件表达式一致。
- 求值失败返回 `ENGINE-0631`，命令整体回滚，不静默忽略。
- 条件求值变量 = 执行可见变量 + 同一执行所属任务的局部变量（任务局部变量在条件事件中具有执行可见性）。
- 实例挂起时不触发条件；实例结束后清理订阅。
- 多个条件同时为真时按订阅创建时间顺序处理，先触发者会清理同一执行上的其他边界订阅。

## 5. 变量变化触发点

统一调用 `internal/engine/conditional.go` 的 `evaluateConditionalSubscriptions(cc, processInstanceID)`，随后运行 agenda：

| 入口 | 触发时机 |
| --- | --- |
| `completeTask` | 写入 `Variables` / `LocalVariables`，取消本任务边界并调度出线后，求值其他分支条件 |
| `SetVariable` | 写入流程实例变量后 |
| `SetExecutionVariable` | 写入执行局部变量后 |
| `SetTaskVariable` | 写入任务局部变量后（任务有执行时） |

完成任务时，任务自身的边界事件按 BPMN 语义随任务完成而取消，不会因为完成任务写入变量而走边界路径；其他分支上的条件订阅仍会立即求值。

## 6. RuntimeService API

```go
EvaluateConditions(ctx context.Context, processInstanceID string) error
```

- 显式求值实例全部条件订阅，并运行 agenda；
- 实例不存在：404（`ENGINE-0404`）；
- 实例已结束：409（`ENGINE-0636`）；
- 实例已挂起：409（`ENGINE-0637`）；
- 空 ID：400（`ENGINE-0635`）。

## 7. REST 端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/service/runtime/process-instances/{id}/evaluate-conditions` | 显式求值条件事件 |

- 成功返回 204；
- 错误统一走 `writeError`，由 `api.Error` 映射 400/404/409/500；
- 处理器为 `internal/rest/conditional_events.go` 中的 `handleEvaluateConditions`，路由由主代理注册。

## 8. 持久化

- 内存快照（JSON）会保存订阅的 `condition` 字段。
- `ACT_RU_EVENT_SUBSCR.CONFIGURATION_` 保存条件表达式（`EVENT_NAME_` 为空），行表导出/恢复可还原条件订阅。
- 条件事件依赖运行期变量求值，历史级别不影响触发逻辑。

## 9. 限制

1. **非中断边界条件事件不支持**：为保证安全子集，运行时统一按中断处理，即无论 `cancelActivity` 是否为 false 都会取消依附任务。若需要非中断语义，应扩展为子执行分支并补充并发清理逻辑。
2. **仅注册用户任务的边界条件事件**：依附到服务任务、脚本任务等活动的条件边界暂不生效。
3. **条件优先级**：中间捕获事件同时配置条件与定时器/消息/信号时，条件分支优先，其他定义被忽略。
4. **任务局部变量可见性**：条件求值会叠加任务局部变量；任务完成后其局部变量随任务删除，不再对其他执行可见。
5. **多实例**：多实例子执行会各自注册条件订阅，未实现根级聚合条件语义。
6. **行表持久化**：条件表达式存于 `CONFIGURATION_`，与 Flowable 原生列语义存在差异。
