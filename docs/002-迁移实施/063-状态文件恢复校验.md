# 063 状态文件恢复校验

> 实施日期：2026-10-28。对应命令为 `flowtide-migrate -verify-state`。本阶段交付离线状态文件的只读恢复校验，不连接数据库、不执行停写、备份、执行者切换或回退演练。

## 1. 问题与结果

`-convert` 可以生成 Go 状态文件，但生成成功不等于该文件能在独立进程中恢复。备份/恢复演练需要回答三个问题：

1. 文件是否能被当前引擎实际解析和恢复；
2. 恢复后包含哪些实体、数量是多少；
3. 文件内容是否在传递过程中发生变化。

新增 `internal/migration.VerifyState` 与 `flowtide-migrate -verify-state`：

- 校验非空文件、JSON 可解析性和快照版本；
- 计算 SHA-256 与字节数；
- 使用 `statestore.NewMemory` 与 `engine.New(Config{StateStore: store, HistoryLevel: audit})` 在隔离内存中恢复；
- 使用公共查询 API 汇总部署、定义、运行实例、当前任务、历史流程实例、历史任务和历史变量数量；
- 输出不包含变量值、部署源码、连接凭据或文件路径内容的结构化 JSON 报告。

整个校验不访问数据库，不修改状态文件，也不修改输入字节。

## 2. 与 `-convert` 的关系

`-convert` 负责“从只读源库快照准备状态”，`-verify-state` 负责“验证已准备好的状态能否恢复”：

```text
源库只读快照 -- -convert --> 新状态文件 -- -verify-state --> 恢复校验报告
```

两者都使用引擎统一的状态格式与恢复入口，但职责不同：

| 项目 | `-convert` | `-verify-state` |
| --- | --- | --- |
| 数据来源 | 源库只读扫描 | 本地状态文件 |
| 是否连接数据库 | 是，只读 | 否 |
| 主要产物 | 新状态文件 + 转换报告 | 恢复校验报告 |
| 是否写文件 | 仅创建新状态文件 | 仅可选创建新报告；不写状态文件 |
| 是否证明可恢复 | 转换阶段会做内存恢复，但不产出独立校验报告 | 是，独立进程按服务同一恢复入口重新恢复 |
| 是否替代停写/回退 | 否 | 否 |

`-verify-state` 的 `format` 字段固定为 `flowtide-state`，与 `-convert` 报告的 `preparedState.format` 保持一致，便于把两份报告对应起来。

**验证通过不代表源库与状态的数量自动一致。** 本工具只恢复状态并统计状态内实体；与源库数量对照仍需使用停写快照上的预检/转换报告，或另行执行受控查询。

## 3. 使用方式

```bash
make build

# 校验状态并在标准输出查看 JSON 报告。
./bin/flowtide-migrate -verify-state -state prepared-state.json

# 将报告写入新文件；目标必须不存在。
./bin/flowtide-migrate -verify-state -state prepared-state.json -out verify-report.json

# 恢复过程受超时约束，默认 5 分钟。
./bin/flowtide-migrate -verify-state -state prepared-state.json -timeout 30s
```

参数约束：

- `-verify-state` 与 `-preflight`、`-convert`、`-apply`、`-tables`、`-cutover-check` 互斥。
- `-state` 只允许与 `-verify-state` 同时使用，且必须是非空路径；文件不存在、不可读或为目录时退出码为 1。
- 不接受 `-tenant`。校验覆盖状态中出现的全部租户，不按调用方租户裁剪。
- `-timeout` 可用于恢复超时；`<= 0` 在读取文件之前按参数错误拒绝。
- `-out` 可选。未指定时报告写入标准输出；指定时必须是当前不存在的普通文件，父目录必须存在，不能是 `.env` 配置文件或其硬链接/软链接，也不能是目录。
- 报告使用同目录私有临时文件完整写入后硬链接发布，已有文件不会被覆盖，权限为 `0600`。
- `-env`、`-dialect` 不参与恢复；`-env` 仍用于保护配置文件不被报告覆盖，`-dialect` 仍按全局参数规则校验。

## 4. 校验流程

`VerifyState(ctx, data)` 的顺序：

1. 检查上下文；已取消或已超时直接返回错误。
2. 拒绝空字节和仅含空白字符的文件。
3. 解析最小元数据，取得 `version`、`recordSequenceFlowHistory` 以及用于枚举租户的部署、定义、实例、任务、历史实例租户字段；不读取变量值、源码和附件内容。
4. 拒绝负版本。未知新版本由引擎恢复入口按统一格式上限拒绝，迁移工具不复制版本常量。
5. 计算 SHA-256 和字节数。
6. 把输入字节复制到 `statestore.NewMemory`，再通过 `engine.New` 恢复；内存存储的 `Save` 不持有调用方切片。
7. 恢复成功后逐租户调用公共查询 API 统计；任何查询错误返回零值报告和错误，不输出部分报告。
8. 输出前再次检查上下文；最后填充格式、版本、字节数、摘要、顺序流标记和固定边界说明。

恢复使用 `HistoryLevel: audit`，读取的是状态内已有的历史容器，不会因为本次校验而改变历史级别。校验完成后不调用会写状态的关闭流程，内存引擎随函数返回被丢弃。

## 5. 报告字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `format` | string | 固定为 `flowtide-state` |
| `version` | number | 状态 JSON 中的快照格式版本；合法旧版可为 0 |
| `bytes` | number | 状态文件字节数，包含原始空白 |
| `sha256` | string | 状态文件完整字节的 SHA-256 十六进制摘要 |
| `deployments` | number | 恢复后的部署数量 |
| `definitions` | number | 恢复后的流程定义数量 |
| `runningInstances` | number | 未结束的流程实例数量 |
| `endedInstances` | number | 历史流程实例中具有结束时间的数量 |
| `tasks` | number | 当前用户任务数量，取自 `ListTasks(Size: 1).Total` |
| `historicProcessInstances` | number | 历史流程实例容器数量，包含仍在运行的实例 |
| `historicTaskInstances` | number | 按运行中与历史流程实例逐实例汇总的历史任务数量 |
| `historicVariables` | number | 按运行中与历史流程实例逐实例汇总的历史变量数量 |
| `sequenceFlowHistory` | bool | 状态内的 `recordSequenceFlowHistory` 标记，表示续跑时是否按 Java audit 语义补记顺序流历史 |
| `limitations` | array | 固定边界说明，见第 7 节 |

报告只有数量、摘要和固定说明，不包含变量名、变量值、任务名称、BPMN XML、部署资源、附件内容或连接信息。

### 5.1 租户统计口径

`-convert -tenant` 可以生成只包含指定租户的状态。校验命令没有 `-tenant`，因此从状态元数据中枚举出现过的租户，再对每个租户使用 `tenant.With` 上下文调用公共查询 API，最后求和。默认租户始终参与查询。

这样可以避免“状态里有租户 A 的实例，但校验按默认租户查询得到零”的误判。租户枚举只使用状态格式已有的字段，不访问 `engine` 包私有字段，也不读取业务变量。

### 5.2 历史统计口径

- `runningInstances` 来自 `ListProcessInstances`，该 API 本身排除已结束实例。
- `historicProcessInstances` 来自 `ListHistoricProcessInstances`；引擎在实例启动时即写入历史容器，因此运行中实例也会计入。
- `endedInstances` 只统计 `EndTime != nil` 的历史流程实例。
- `historicTaskInstances` 与 `historicVariables` 对“运行实例 + 历史实例”去重后的每个实例调用 `ListHistoricTaskInstances(ctx, instanceID)` 和 `ListHistoricVariableInstances(ctx, instanceID)`，不直接读取引擎内部集合。
- 未归属任何流程实例的独立历史任务/变量不会进入上述两个逐实例统计，这是当前已知口径，已写入 `limitations`。

## 6. 退出码

| 退出码 | 含义 | 后续动作 |
| --- | --- | --- |
| 0 | 状态文件已成功恢复并输出完整报告 | 可将报告与转换/预检记录核对；仍需完成停写、备份、切换与回退演练 |
| 1 | 参数错误、文件缺失或不可读、JSON/版本/恢复失败、取消/超时、报告生成或输出失败 | 修复文件或参数后重新校验；不得用旧报告代表本次结果 |

本命令不返回 2。只有 `-preflight` 阻断和 `-cutover-check` 检测到变化使用退出码 2。

使用编译后的二进制获取退出码；`go run` 会包装非零退出状态。

## 7. 只读与适用边界

`-verify-state` 的所有操作都在本进程和隔离内存中完成：

- 不连接 MySQL/PostgreSQL，不建立事务，不执行任何 SQL；
- 不读取或写入源库；
- 不修改 `-state` 指向的文件；
- 不执行 BPMN 活动、事件、异步作业、定时器或委托；
- 不写回状态文件，也不创建状态文件；
- 只允许通过 `-out` 创建一个新报告。

`VerifyState` 返回成功只表示“当前引擎能在内存中恢复该状态并完成公共 API 统计”，**不表示**：

- 生产服务可以长期接管该状态；
- 源库已经停写、备份可恢复或可安全回退；
- 状态内数量与源库一致；
- 状态文件未被恶意篡改；
- Java 与 Go 可以同时处理同一批实例。

因此它不能替代：

- `-cutover-check` 的停写静默观察；
- 停写后对源库做可恢复备份；
- 执行者切换与双跑隔离；
- 首次回退演练；
- Java 与 Go 的续跑验收。

校验报告中的 `sha256` 只是本次读取字节的摘要。若需要证明文件来自某次 `-convert` 且未被替换，必须把该摘要与外部保存的转换报告 `preparedState.sha256` 做人工或流水线比对；本工具不保存也不信任外部期望值。

## 9. 剩余风险与下一阶段

- 恢复只验证结构可加载，不执行活动、作业、事件和委托，不能证明业务流程在 Go 中可继续推进。
- 历史任务/变量按实例统计，独立历史行不计入；若后续需要完整审计口径，应新增不依赖实例过滤的公共查询，而不是访问私有字段。
- 租户枚举依赖状态格式中部署、定义、实例、任务和历史实例的租户字段。若引擎升级改变这些字段的序列化名称，校验统计会漏计，需要同步调整并补充对照测试。
- SHA-256 不做签名验证，也不与外部期望值自动比对；传输完整性需由备份流程或流水线负责。
- 与源库数量的一致性、停写证据、回退能力和生产容量仍未覆盖。后续受控切换仍需按顺序完成：冻结写入与后台作业、备份源库、`-convert`、`-verify-state`、`-cutover-check`、切换执行者、Go 续跑验收、首次回退演练。任一步缺失时，不得仅凭本报告启用 Go 接管。
