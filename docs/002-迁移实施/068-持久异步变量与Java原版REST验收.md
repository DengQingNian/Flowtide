# 068 持久异步变量与 Java 原版 REST 验收

## 1. 验收范围

本阶段消除六个 `variables-async` 方法的同步替代行为。请求在单次命令事务中校验整批变量、检查创建冲突及更新存在性，然后提交持久作业。请求返回时变量和历史明细保持原值，执行器成功提交作业后才发布整批更新。

参考 Java 提交固定为 `f6017e32a4bdd3e59a8881f58b0ee181652d1d9e`，Schema 为 `8.1.0.3`。真实引擎样本与原版控制器 HTTP 样本分别保存为 `testdata/compatibility/java/002-async-variables.json`、`003-async-variable-rest.json`。期望来自原版 Java 的实际执行，不能用 Go 输出更新这些文件。

## 2. 原版 HTTP 行为

| 方法 | 目标路径（前缀 `/service/runtime`） | 成功状态 | 请求体 |
| --- | --- | ---: | --- |
| POST | `/process-instances/{id}/variables-async` | 201 | 非空变量数组，仅创建 |
| PUT | `/process-instances/{id}/variables-async` | 201 | 非空变量数组，创建或更新 |
| PUT | `/process-instances/{id}/variables-async/{name}` | 204 | 含匹配名称的单变量对象，仅更新 |
| POST | `/executions/{id}/variables-async` | 204 | 非空变量数组，仅创建 |
| PUT | `/executions/{id}/variables-async` | 204 | 非空变量数组，创建或更新 |
| PUT | `/executions/{id}/variables-async/{name}` | 204 | 含匹配名称的单变量对象，仅更新 |

所有成功响应均为空正文。执行变量集合的官方 OpenAPI 标记为 201，但固定提交的原版控制器经 Spring MVC 实际调度后返回 204；当前以原版 HTTP 实际响应为准，并在端点清单保留该差异。

Java HTTP 运行器使用四个原版控制器、原版异常处理器与实际引擎，通过 Spring 7.0.7 MockMvc 完成真实控制器调度。14 个场景包括两个目标各自的三种成功操作、创建冲突、单变量名称不匹配、集合误传对象、空数组。Go 回放逐项比较状态码、完整响应正文、入队前后变量、待执行作业数及执行后的变量；只将真实生成的实例 ID 归一化，不筛除错误字段。

原版错误正文的 `message`、`exception` 属于兼容契约，保留英文原值；内部 API 错误说明继续使用中文。集合端点不接受变量名称映射或单对象，单变量端点的正文名称必须与 URL 相等。

## 3. 持久化、类型和事务

- 新作业类型为 `variable-update`，复用现有到期执行、挂起、三次重试、死信、人工修复再执行机制。
- 载荷采用带版本的精确快照编码，保存有符号 64 位整数、日期、字节及 JSON 类型。REST 使用精确数字解码，`9007199254740993` 不经过浮点中转；整型边界及未知类型拒绝请求。
- 作业通过 `CUSTOM_VALUES_ID_` 引用独立 `ACT_GE_BYTEARRAY` 行，避免大载荷受 `HANDLER_CFG_` 文本列容量限制。待执行及死信行恢复均读取该引用，引用缺失或损坏时拒绝恢复。
- 载荷只存在于标准作业关联字节行，运行时控制快照不保存第二份权威副本。命令备份深复制字节，避免回滚状态共享内存。
- 创建前完整校验并序列化；执行前完整解码。冲突、损坏、请求取消、保存失败均不能留下部分变量或可执行作业。
- 执行局部作用域保持子执行遮蔽；全局作用域从父执行解析变量所有者。混合作用域拒绝提交，流程实例端点统一写根作用域。
- 绑定租户的手动执行仅能运行本租户作业；无绑定的后台执行器可以调度不同租户，执行每条作业前绑定所属实例租户。
- 日期变量的历史类型修正为 `date`，避免异步日期更新被记录为 JSON。

这些行载荷用于 Go 单执行者续跑，不能据此让 Java 直接读取 Go 新增作业。

## 4. 真实数据库验收

MySQL 8.0.35 与 PostgreSQL 16.3 均执行 `TestIntegrationAsyncVariables`：

1. 在隔离临时库创建行仓储引擎并提交异步变量；立即读取仍为旧值。
2. 关闭引擎、释放独占连接，再用新连接取得所有权并从行表恢复；变量仍未提前改变。
3. 运行作业，核对大整数、日期及 15,000 字节内容完整；没有遗留作业或载荷字节行。

普通测试另覆盖 JSON 快照重启、全批冲突、重试进入死信、死信行恢复与修复重放、条件事件继续执行、租户隔离、挂起激活和失败回滚。Java 公共服务样本包含全局和局部两种异步更新，full 历史明细在入队期间保持 2 条，成功执行后为 7 条。

## 5. 回归与本地重生成

```bash
go test ./internal/engine -run TestJavaAsyncVariableReference -count=1
go test ./internal/rest -run TestJavaAsyncRESTReference -count=1
make check
make race
make test-mysql
# PostgreSQL 连接通过受限配置或环境注入，不在日志中输出密码。

```

按本地交付约束，生成器和构建脚本不纳入提交；干净检出可以执行固定样本回归，不能直接重新生成 Java 样本。`async-provenance.json` 记录两份制品、生成器源码及脚本摘要。本轮使用 JDK 17、Maven 和固定提交的无修改 Java 工作区，两次独立 Java 执行的完整 JSON 一致。

重生成需先取得本地生成器和脚本并核对摘要。脚本校验固定提交和源码修改，再构建 REST 依赖并解析实际类路径；两套 Java 运行器都成功后才发布新目录，已有路径或并发创建的目标均不覆盖。代理配置由调用者提供，不提交凭据。新增样本必须人工审核差异并同步 `baseline.json`。Go 普通门禁只消费固定制品，不依赖 Java 环境。
