# 073 身份标准行恢复验收

验收日期：2026-10-29。对应进度总览 M7，[072](072-身份原版REST与可空用户信息验收.md)遗留的 SQL 身份行恢复缺口。范围为单执行者行仓储中 Go 引擎身份资料的标准行持久化与重启恢复；不涉及从 Java 源库迁移身份业务表，也不改变集群、生产切换与 Java 反向接管的验收边界。

## 行映射与导出

行仓储新增 `ACT_ID_USER`、`ACT_ID_GROUP`、`ACT_ID_MEMBERSHIP`、`ACT_ID_INFO`、`ACT_ID_BYTEARRAY` 五张标准身份表，总映射从 21 张流程表扩展到 26 张。

- `ACT_ID_MEMBERSHIP` 使用 `USER_ID_` + `GROUP_ID_` 真实复合主键：INSERT 不虚构 `ID_` 列，UPDATE 与 DELETE 的 WHERE 包含全部主键分量，避免删除一个成员关系误删同用户的全部组关系。行标识对复合键按 JSON 数组编码，用户或组标识包含竖线、零字节时仍无碰撞；旧快照的 `user|group` 普通键保持读取兼容并归一化。
- `ACT_ID_USER.PICTURE_ID_`、`ACT_ID_INFO.USER_ID_/PARENT_ID_`、`ACT_ID_MEMBERSHIP.USER_ID_/GROUP_ID_` 声明为外键，参与行依赖排序；非成员身份行要求修订号至少为 1。
- 导出以标准列为唯一真实来源：用户资料与密码哈希（`PWD_` 保持原编码，不经过明文转换）、头像字节行（含零字节与非 UTF-8 字节无损）、用户信息行（保留原行 `ID_` 与显式空值键，已清空的键仍写入标准表）。
- Go 扩展属性——用户角色、禁用、失败计数、锁定截止、组租户、角色权限定义——标准表无法表达，写入独立控制字节行 `flowable-go-identity-control/v1`；普通原版资料不复制进控制行，避免双源。

## 导入与整组校验

解码阶段严格校验列类型、修订号、主键唯一与身份表范围，未知身份表拒绝。引擎导入先整组校验再发布：

1. 引用完整性：头像引用、成员关系的用户与组、信息归属用户必须存在，悬空引用拒绝。
2. 未支持资料拒绝：`TYPE_` 非 `userinfo` 的账户及账户明细、非空 `PASSWORD_` 列、`PARENT_ID_` 子级一律拒绝启动，不能忽略后在下一次保存时删除原库资料。
3. 控制行版本、未知字段、尾随内容与悬空扩展归属拒绝；恢复只回填安全扩展，不覆盖标准用户资料与密码。
4. 同一用户的信息键重复拒绝；任何失败不发布部分状态（隔离引擎暂存后整体提交）。

## 双库真实库验收

`TestIntegrationMySQLRowsIdentityRecovery` 与 `TestIntegrationPostgresRowsIdentityRecovery` 在 MySQL 8.0.35 / PostgreSQL 临时库执行：

1. 行仓储服务模式创建用户（编码密码）、带租户扩展的组、复合成员关系、信息（含已清空的显式空值键）、含零字节与非 UTF-8 字节的头像、角色定义与用户角色绑定。
2. 关闭引擎、释放独占锁、关闭连接池后由新执行者重新接管并从标准行恢复。
3. 核对用户资料、密码校验、组与租户扩展、信息空值语义（键列表保留、单键读取 404）、头像字节、角色与权限定义。
4. 直接 SQL 断言标准行是真实来源：`PWD_` 非明文非空、成员复合主键行、空值信息行、控制行各恰好一行。

两个方言均一次通过；期间执行者切换不复用前一引擎内存。

## 回归与边界

```bash
go test ./internal/persistence/flowable -run 'TestDecodeIdentity|TestIdentityMembershipCompositeKey' -count=1
go test ./internal/engine -run 'TestIdentityRows|TestIdentityMembershipDelimiter' -count=1
FLOWABLE_MYSQL_INTEGRATION=1 go test ./internal/persistence/mysql -run TestIntegrationMySQLRowsIdentityRecovery -count=1
FLOWABLE_POSTGRES_INTEGRATION=1 go test ./internal/persistence/postgres -run TestIntegrationPostgresRowsIdentityRecovery -count=1
make check
```

边界与已知限制：

- 账户及账户明细（`TYPE_` ≠ `userinfo`）、身份历史表等仍不支持导入，保持拒绝而非静默丢弃。
- 旧版本行模式数据库中没有身份行（此前身份不随行仓储持久化），重启后身份从下一次保存开始写入；存量 JSON/内存快照行为不变。
- 本验收不使 `flowable-migrate` 获得从 Java 源库转换身份业务表的能力；迁移预检对身份表的支持范围仍以 [067](067-双库行服务与迁移闭环验收.md) 为准。
