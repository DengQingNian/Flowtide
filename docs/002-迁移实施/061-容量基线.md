# 061 容量基线（本机首轮）

> 文档编号：002-061
> 更新日期：2026-10-28
> 对应计划：012 测试策略与质量门禁、013 里程碑与资源计划

## 1. 目的与边界

本文记录当前实现在固定开发环境下的首轮基准，用于识别明显退化、比较后续优化和建立容量讨论的起点。它不是生产容量承诺：

- 测试运行在 QEMU 虚拟 CPU、单进程、内存状态模式下，没有数据库网络、连接池、锁竞争和真实磁盘开销；
- 业务负载为单一用户任务流程与人工构造的 1000 行快照，不代表真实流程组合、变量大小和历史数据量；
- 没有多执行者、集群、故障注入或长时间稳定性数据。

## 2. 环境与方法

| 项目 | 值 |
| --- | --- |
| Go | `go1.27.3 linux/amd64` |
| CPU | QEMU Virtual CPU version 2.5+，4 vCPU |
| 引擎 | 内存状态、`HistoryLevel=audit`、假时钟 |
| 命令 | `make bench BENCHTIME=1s` |
| 基准源 | `internal/engine/benchmark_test.go`、`internal/persistence/flowable/benchmark_test.go` |

`make bench` 只运行基准，不进入默认测试和覆盖率门禁。样本数由 Go 基准框架自动决定；每项重复执行并报告 `ns/op`、`B/op`、`allocs/op`。

## 3. 结果

### 3.1 引擎命令与查询

| 基准 | 单次耗时 | 内存/次 | 分配/次 | 说明 |
| --- | ---: | ---: | ---: | --- |
| `BenchmarkStartAndCompleteUserTask` | 23.43 ms | 7.61 MB | 42,381 | 启动实例、查询任务、完成任务的端到端命令开销 |
| `BenchmarkCompleteUserTask` | 15.01 ms | 6.57 MB | 33,058 | 固定任务集上的完成任务命令 |
| `BenchmarkListTasks1000` | 5.24 ms | 1.90 MB | 4,730 | 1000 个运行任务中分页查询 100 条 |
| `BenchmarkSnapshotRows1000` | 274.57 ms | 62.74 MB | 854,263 | 1000 个运行实例的全量行导出 |

### 3.2 行仓储增量与全量操作

| 基准 | 单次耗时 | 内存/次 | 分配/次 | 说明 |
| --- | ---: | ---: | ---: | --- |
| `BenchmarkDiffOperations1000` | 2.97 ms | 0.78 MB | 16,013 | 1000 行中单行变化的增量操作生成 |
| `BenchmarkSnapshotOperations1000` | 8.87 ms | 2.90 MB | 7,051 | 1000 行全量替换操作生成 |

## 4. 初步结论

1. **命令开销主要来自状态复制与历史写入**：启动/完成命令需要克隆状态、维护执行树和历史，单次十几到二十几毫秒；在 QEMU 环境下该绝对值不能直接外推到生产硬件。
2. **任务查询仍为线性扫描**：1000 个任务时列表查询约 5 ms，主要成本是遍历和过滤全部任务；任务量继续增长时需要查询下推与索引支持。
3. **全量快照导出是当前最大单点**：1000 实例约 275 ms、63 MB，且每次导出都生成全部行；行仓储的增量写入减少了数据库写放大，但没有消除引擎侧的 O(state) 导出。
4. **增量操作生成明显低于全量替换**：单行变化时增量生成约 3 ms，全量替换约 9 ms；实际收益还取决于数据库往返与事务成本。
5. **内存分配高**：命令路径和快照导出均产生大量临时对象，后续应结合 `pprof` 优化热路径，不能仅靠增加硬件。

## 5. 后续工作

1. 接入 MySQL 行仓储服务模式后，在真实数据库上重复相同基准，区分网络、事务与引擎 CPU 成本。
2. 实现查询下推，避免任务/实例/历史查询全量扫描。
3. 对命令路径做 `pprof` 采样，评估状态克隆、历史写入和 agenda 分配的可优化点。
4. 增加多实例、大变量、复杂网关与定时器负载，形成分场景基线。
5. 在固定硬件和固定数据规模下建立回归阈值，超过阈值时阻断合并；当前数值只作为首轮观察，不作为门禁。

## 6. 复现

```bash
HOME=/root make bench
# 或指定更长的采样时间
HOME=/root make bench BENCHTIME=3s
```

基准结果只保存在本机输出，不写入覆盖率文件；`make check` 不运行基准。
