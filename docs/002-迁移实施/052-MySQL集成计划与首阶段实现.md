## 2. 第一阶段的实现

- `internal/persistence/mysql` 使用纯 Go MySQL 驱动，连接池最多 10 个连接、5 个空闲连接，连接寿命 3 分钟，空闲回收 1 分钟。
- `LoadConfig` 读取 `.env`，不修改进程环境；进程环境变量优先于文件配置，支持引号和密码中的特殊字符。
- 字符集为 `utf8mb4`；时间解析和连接会话统一使用 UTC。连接、读写均有超时。
- 服务通过 `-storage mysql` 显式启用数据库；`-env` 指定配置文件，默认 `.env`。与 `-state` 互斥。
- `flowable-migrate -apply` 在目标数据库尚无引擎表时执行内置完整 DDL，已有完整 Schema 时校验版本及脚本校验和。
- `sqlstate.Store` 的 MySQL 保存改为单条 `INSERT ... ON DUPLICATE KEY UPDATE`，写入失败时保留旧快照。
- 引擎继续通过已有 `StateStore` 命令提交/回滚机制写入 `ACT_GE_BYTEARRAY` 中的 `flowable-go-state`；服务启动自动恢复。
- 补齐原快照遗漏的流程模型、编辑源、扩展编辑源和流程实例身份链接；旧快照缺少新增字段时仍可读取。
- 关闭顺序为 HTTP 停止接收请求、引擎保存、数据库连接池释放，保存失败会记录错误。

## 3. 开发配置和启动

现有 `.env` 的配置项保持不变：

| 配置项 | 含义 |
| --- | --- |
| `db_mysql_host` | MySQL 地址，支持 IPv6 |
| `db_mysql_port` | 端口，缺省为 3306 |
| `db_mysql_user` | 用户名 |
| `db_mysql_pwd` | 密码，允许本地开发时为空 |
| `db_mysql_db_name` | 已存在的目标数据库 |

`.env` 已由 `.gitignore` 排除，配置示例见根目录 `.env.example`。命令从仓库根目录运行：

```bash
# 首次执行建表；重复执行会进行版本与初始化完成标记校验。
go run ./cmd/flowable-migrate -dialect mysql -apply -env .env

# 启动并从数据库恢复；服务本身仅校验 Schema，不执行 DDL。
go run ./cmd/flowable-server -storage mysql -env .env -addr :8080

# 原有内存与文件模式继续可用。
go run ./cmd/flowable-server -state ./data/engine.json
```

数据库需要预先创建；初始化需要建表、建索引、外键和插入权限。服务运行需要读取和更新相关表的权限。单独导出 SQL、列出表名的既有命令仍可使用，但手动导入原始 SQL 不会生成本工具的初始化完成标记。

## 4. Schema 校验与失败处理

初始化检查内置 41 张表（包含 `ACT_*` 和 `FLW_*`）是否存在；已有部分表时拒绝自动补建。完成所有 DDL 后才向 `ACT_GE_PROPERTY` 写入 `flowable-go.schema.checksum` 标记。启动要求 `schema.version` 为 `8.1.0.3` 且标记与内置脚本校验和一致。

MySQL DDL 会隐式提交，整个初始化不是原子事务。失败时保留现场并报告失败语句序号；需要人工检查或重建专用开发库后重试。部分表、缺失标记、版本或校验和不一致都会返回错误。初始化期间应只有一个迁移进程；本阶段未实现并发迁移锁。

已有 Java Flowable 数据库或手动导入的 Schema 不会被自动接管；本阶段不提供自动升级、表结构修复或任意既有 Schema 兼容保证。表数量、版本和校验和检查不能代替逐列、索引、约束漂移检查。

## 5. 测试与质量门禁

先新增配置、原子写入、初始化及服务配置测试，确认缺失接口和先删后插行为导致失败，再实现功能。单元测试覆盖配置优先级、特殊密码、IPv6、非法端口、缺失配置、连接取消、部分 Schema、版本冲突、缺失标记及数据库错误。

```bash
# 常规测试不访问真实数据库。
go test -coverprofile=coverage.out ./...
go tool cover -func=coverage.out

go vet ./...
CGO_ENABLED=1 go test -p 2 -race ./...

# 显式启用真实数据库，连接目标取自现有 .env。
FLOWABLE_MYSQL_INTEGRATION=1 go test -count=1 -v ./internal/persistence/mysql

# 单独验证已实现的快照路径，只在临时库建立二进制表。
FLOWABLE_MYSQL_INTEGRATION=1 go test -count=1 -v ./internal/persistence/mysql -run '^TestIntegrationMySQLSnapshot$'
```

真实数据库测试要求账号有创建和删除数据库权限。测试连接开发库获取服务器信息，然后创建唯一的 `flowable_go_it_时间戳` 临时库。Schema 测试验证完整 DDL 与重复初始化；独立快照测试只创建二进制表，验证旧快照保护、中文和表情变量、模型与身份链接恢复、任务恢复、任务完成及历史恢复。正常结束后关闭连接并删除临时库；清理失败会报告库名和错误，不修改开发库现有数据。可使用 `FLOWABLE_MYSQL_ENV` 指定其他配置文件的绝对路径；显式启用后连接失败或权限不足均判定失败。

## 7. 当前边界

- 第一阶段将完整 JSON 状态写入一个二进制记录；任务、执行、历史等尚未作为独立 SQL 行自动更新，不能直接用关系表查询本阶段服务的流程数据。
- 仅支持单服务进程独占一个快照；原子保存保证单次写入完整，不提供多实例状态协调、跨进程乐观锁或作业抢占。
- 快照仍是全量读写，大小受数据库报文、内存和网络限制；后续以按表事务替换。
- 原始 Flowable DDL 使用 `utf8` 表字符集，连接使用 `utf8mb4`；本阶段表情变量存放在快照二进制列中，关系文本列的完整表情支持需要后续迁移评估。
- 不自动把现有 `-state` 文件导入数据库，也不混用状态文件与 SQL 快照。
- PostgreSQL 的原快照保存路径不在本次改动范围，仍需后续补齐原子保存和真实驱动验证。
