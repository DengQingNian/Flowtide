# 015 流程定义候选发起人

> 文档编号：002-015  
> 更新日期：2026-10-28  
> 对应计划：005 BPMN 模型、XML 解析与部署校验；011 REST API 与兼容契约

## 1. 背景

Flowable 允许在 BPMN 的 `process` 元素上声明候选发起人：

~~~xml
<process id="leave" isExecutable="true"
         flowable:candidateStarterUsers="alice,bob"
         flowable:candidateStarterGroups="managers,hr">
~~~

它们对应 `ACT_RU_IDENTITYLINK` 中 `PROC_DEF_ID_` 非空、`TYPE_=candidate` 的记录，用于 UI 控制“谁可以发起流程”，也可在运行时通过 REST 增删。

本期补齐模型解析、运行时增删查、持久化与 4 个 REST 端点。

## 2. 模型解析

`model.Process` 新增：

| 字段 | 说明 |
| --- | --- |
| `CandidateStarterUsers` | 候选发起人用户 |
| `CandidateStarterGroups` | 候选发起人组 |

解析规则：

- 读取 `flowable:candidateStarterUsers` 与 `flowable:candidateStarterGroups`。
- 逗号分隔，自动去空白与空项。
- 部署时为每个候选人生成 `candidate` 身份链接，记录到 `definitionState.StarterLinks`。

## 3. 引擎 API

`RepositoryService` 新增：

| 方法 | 说明 |
| --- | --- |
| `ListDefinitionIdentityLinks(ctx, definitionID)` | 候选发起人列表 |
| `GetDefinitionIdentityLink(ctx, definitionID, family, identityID)` | 查询单个 |
| `AddDefinitionIdentityLink(ctx, definitionID, link)` | 添加候选人 |
| `DeleteDefinitionIdentityLink(ctx, definitionID, family, identityID)` | 删除候选人 |

规则：

- 类型固定为 `candidate`，调用方传入的 `type` 忽略。
- `userId` 与 `groupId` 必须且只能提供一个。
- 重复添加幂等，返回已存在链接。
- 定义不存在或跨租户返回 404。

## 4. 端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/service/repository/process-definitions/{id}/identitylinks` | 列表 |
| POST | `/service/repository/process-definitions/{id}/identitylinks` | 添加 |
| GET | `/service/repository/process-definitions/{id}/identitylinks/{family}/{identityId}` | 单个 |
| DELETE | `/service/repository/process-definitions/{id}/identitylinks/{family}/{identityId}` | 删除 |

响应示例：

~~~json
[
  {
    "id": "link-1",
    "type": "candidate",
    "userId": "alice",
    "processDefinitionId": "leave:1:abc",
    "createTime": "2026-10-28T01:02:03.000+08:00"
  }
]
~~~

- `family` 只接受 `users` 与 `groups`。
- 添加返回 201；删除返回 204；单个查询/删除不存在返回 404。

## 5. 持久化

- 候选发起人写入 `ACT_RU_IDENTITYLINK`：`PROC_DEF_ID_` 为定义 ID，`PROC_INST_ID_` 与 `TASK_ID_` 为空。
- JSON 状态快照在 `definitions[].starterLinks` 中保存。
- 行恢复时优先使用持久化链接，避免从 BPMN 重新生成导致 ID 变化。
- 部署新定义时从 BPMN 属性生成初始链接。

## 6. 错误码

| 场景 | HTTP | 错误码 |
| --- | --- | --- |
| 用户与组未二选一 | 400 | `ENGINE-1302` |
| 参与者类型非法 | 400 | `ENGINE-1303` |
| 链接不存在 | 404 | `ENGINE-1304` |
| 定义不存在/跨租户 | 404 | `ENGINE-0404` |

## 7. 限制

1. 候选发起人仅作为元数据，启动流程时引擎未强制校验发起人权限；权限由上层网关/应用控制。
2. 不支持按候选人查询“可发起流程”的列表接口。
3. 候选发起人变更不写历史表，仅影响运行时链接。
