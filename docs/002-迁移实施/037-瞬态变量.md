# 037 瞬态变量

> 文档编号：002-037  
> 更新日期：2026-10-28  
> 对应计划：007 变量、表达式与脚本引擎；011 REST API 与兼容契约

## 1. 背景

Flowable 支持瞬态变量（transient variables）：只在当前命令/事务内参与表达式求值，不持久化、不写历史、不产生变量实例。典型用途：

- 启动时传入一次性参数；
- 完成任务时驱动后续条件分支，但不污染流程变量；
- 触发等待执行时传入临时处理人/参数。

## 2. 引擎实现

`executionState` 新增 `Transient map[string]any`（JSON 不序列化）。

- `variablesOf` 在执行可见变量上叠加瞬态变量，叶子作用域优先。
- 每条命令成功结束前统一清空所有执行的 `Transient`，确保不进入快照、行表或查询。
- 命令失败回滚时随状态一起回滚。

### 2.1 入口

| 入口 | 字段 |
| --- | --- |
| `StartProcessInstance` / REST 启动 | `transientVariables` |
| `Complete` / 完成任务动作 | `transientVariables` |
| `TriggerExecutionWithTransient` / 执行 trigger 动作 | `transientVariables` |

`TriggerExecution` 保持原签名，内部委托给 `TriggerExecutionWithTransient`。

### 2.2 可见性

- 瞬态变量在命令执行期间对表达式、条件、任务处理人/优先级解析可见。
- 不写入执行变量、不写历史变量/明细、不生成变量实例。
- 同名持久变量被瞬态值覆盖**仅限命令内**，命令结束后持久值不变。

## 3. REST 示例

开始流程：

~~~json
{
  "processDefinitionKey": "leave",
  "variables": [{"name": "days", "value": 3}],
  "transientVariables": [{"name": "operator", "value": "admin"}]
}
~~~

完成任务：

~~~json
{
  "action": "complete",
  "transientVariables": [{"name": "approved", "value": true}]
}
~~~

触发执行：

~~~json
{
  "action": "trigger",
  "variables": [{"name": "note", "value": "ok"}],
  "transientVariables": [{"name": "assignee", "value": "bob"}]
}
~~~

## 4. 限制

1. 瞬态变量只存在于单条命令；跨命令/跨异步作业不可见。
2. 异步作业恢复时不会保留瞬态变量（符合 Flowable 语义）。
3. 任务局部变量与瞬态变量是不同机制：前者持久化到任务并写历史。
4. 未实现 transient 变量的查询/历史 API（本就不应出现）。
