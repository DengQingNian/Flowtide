## 5. 已知限制

1. **脚本**：仅表达式子集，不支持完整 JS 语句、Groovy、Starlark；生产应限制脚本任务或引入沙箱引擎。
2. **持久化**：JSON 快照为过渡方案，单文件、全量写入，不具备并发写与大数据量能力。
3. **集群**：无多节点锁、作业抢占、缓存失效。
4. **安全**：无认证、密码、Token、权限模型；REST 仅适合内网/演示。
5. **历史**：未记录评论、附件、身份链接、变量明细；full 级别未实现。
6. **REST**：覆盖核心路径，不是 Flowable 全量契约；未做 OpenAPI 契约测试。
7. **执行语义**：事件子流程/补偿/事务/迁移做了简化，边界场景需与参考实现对比验证。

## 6. 下一阶段建议

1. **持久化层**：定义 `Store` 接口，实现 SQL 仓储（PG/MySQL），保留 JSON 作为测试替身。
2. **作业体系**：重试、死信、锁过期、集群抢占、管理 REST。
3. **REST 扩展**：按官方 OpenAPI 生成路由清单，补齐仓库/运行时/历史/管理端点。
4. **BPMN 补全**：事务子流程、Send/Receive、Ad-hoc、定时器重复。
5. **安全**：Basic/Bearer、租户、密码哈希、权限。
6. **兼容性**：移植参考仓库 BPMN 夹具，建立执行路径黄金对比。
