# 053 既有 Java 数据库只读预检

> 实施日期：2026-10-28。参考 Java 提交为 `f6017e32a4bdd3e59a8881f58b0ee181652d1d9e`，Schema 基线为 `8.1.0.3`。本阶段交付迁移前的存量风险报告，不交付数据转换或接管执行。

## 1. 问题与结果

此前 `flowable-migrate` 只提供 Schema 导出和 MySQL 初始化，无法在修改既有库之前识别 Java 运行时结构、序列化变量、作业、脚本及委托映射。本阶段新增 `internal/migration` 和 `-preflight` 命令模式，使这些检查可以通过纯 Go 二进制重复执行。

扫描器通过 `database/sql` 开始 `ReadOnly=true`、`RepeatableRead` 事务，查询当前数据库或模式中的 `ACT_*` 基础表。已知表读取实际列，表名和列名统一为大写供分析；未知表只统计行数。所有数据库操作均为元数据查询、`SELECT` 和事务回滚，不调用 Schema 初始化、引擎恢复或变量反序列化执行。

读取、遍历、关闭结果集或结束事务发生错误时，不返回部分源快照，也不替换旧报告。扫描出的原始行只留在进程内，不进入报告 JSON。

## 2. 使用方式

```bash
make build
# MySQL 配置与服务端沿用同一格式；此命令不初始化源库。
./bin/flowable-migrate -preflight -dialect mysql -env .env -out preflight.json
# 只选择指定租户的实体；全库结构风险仍会报告。
./bin/flowable-migrate -preflight -dialect mysql -tenant=tenant-a -out tenant-a.json
# 空字符串明确选择默认租户；不传 tenant 则分析全部租户。
./bin/flowable-migrate -preflight -dialect mysql -tenant="" -out default.json
# PostgreSQL 从 FLOWABLE_POSTGRES_DSN 环境读取凭据。
./bin/flowable-migrate -preflight -dialect postgres -timeout 5m -out postgres.json
```

`-preflight` 与 `-apply`、`-tables` 互斥；显式 `-tenant` 和 `-timeout` 仅适用于预检。未指定 `-out` 时标准输出为 JSON；指定输出时，以 `0600` 权限的同目录临时文件完整写入后原子替换目标。配置文件及其链接不能作为报告目标。命令错误不打印数据库连接凭据。

| 退出码 | 含义 | 后续动作 |
| --- | --- | --- |
| 0 | 当前分析范围未发现阻断 | 继续准备转换和 Java 对照，不能直接启用 Go 接管 |
| 2 | 报告包含阻断问题 | 按问题码、表、实体及实例归属安排整改 |
| 1 | 参数、连接、扫描或输出失败 | 先恢复可重复执行的完整检查，不采用旧报告代表本次结果 |

使用编译后的二进制获取退出码；`go run` 会自行包装被运行程序的非零退出状态。

## 3. 报告与阻断规则

报告包含 Schema 和兼容基线、全库表行数、分析范围、请求租户标识、租户实例/执行/任务/变量统计、逐实体问题以及限制。问题输出实体标识和固定中文说明，不包含变量值、脚本内容或 Java 类实现。分析器要求 14 张核心、事件订阅和 Java 作业表存在；未纳入分析的历史、身份和模型等非空表仍会阻断。

- Schema 版本不符合基线或缺少必需表时阻断。
- 对运行时变量检查显式类型、数值范围、外置字节引用、JSON 数据及执行/任务归属；Java `serializable` 和未知类型阻断。
- 检查定义、部署、BPMN 资源以及执行树/任务引用；定义键须匹配模型流程，活动及任务键须匹配实际用户任务。对多实例、并发、调用及无法确认的复杂结构阻断。
- BPMN 中 Java 委托、监听器、脚本和复杂模型需要独立映射或验证，进入阻断报告；不尝试执行源码。
- Java 作业及订阅尚无受验收的转换器，现阶段保守阻断。其他未完成分析的非空表同样阻断，不能由已有行解码器推导迁移兼容。
- 指定租户后，无法确认归属的数据与全库未知表风险仍需处理；表统计始终代表扫描的全库，不等于租户内行数。

## 4. 适用边界

当前扫描会在进程内读取已知表的全部行，未实现分页、容量上限、流式分析或业务实例集合选择。`-tenant` 是分析范围过滤，不是数据库查询下推。使用者需要对整个目标模式的 `ACT_*` 表拥有读取与元数据可见权限；只授予部分表权限不能保证发现全部未知实体。非事务表和扫描期间发生的 DDL 也不在一致性保证内。

本阶段仅支持无表名前缀的 MySQL/PostgreSQL `ACT_*` 布局；PostgreSQL 选择 `current_schema()`，支持官方 DDL 自动折叠的小写标识符。源 Java 继续运行时报告只代表事务快照，不构成停写切换证据。现阶段未实现全量模型语义分析、委托注册表核对、转换、续跑、反向转换或回退演练。

## 5. 验证记录

2026-10-28 阶段验收结果如下。真实数据库测试只创建和删除专用临时库，使用仓库固定 DDL 与 Go 生成及直接 SQL 写入的 Java 形态测试实体；不冒充 Java 引擎实际写入并续跑的对照证据。

| `make check` | 通过：中文函数注释、格式、vet、覆盖率、基线摘要、端点清单、独立 SDK 与无 CGO 构建 |

双库均验证真实驱动的只读事务拒绝写入、两次扫描结果不变、运行时实体统计、无 Go 控制快照的 Java 形态根/子执行及用户任务、序列化变量逐实体拒绝和非空未知表阻断。扫描失败、结果集错误、结束回滚失败、表名注入与大小写冲突等路径由单测覆盖。Go 原生覆盖率衡量语句，不能称作逐物理行覆盖率。
