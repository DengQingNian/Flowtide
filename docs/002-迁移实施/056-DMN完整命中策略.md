# 056 DMN 完整命中策略

> 文档编号：002-056
> 更新日期：2026-10-28
> 对应计划：005 BPMN 模型、XML 解析与部署校验；006 流程执行引擎 PVM 设计
> 前置文档：[046-DMN决策元数据](./046-DMN决策元数据.md)、[047-DMN求值与业务规则任务](./047-DMN求值与业务规则任务.md)

## 1. 背景

047 期实现了 DMN 决策表的安全子集求值，但只支持 `FIRST`、`UNIQUE`、`ANY`：

- `RULE ORDER` 被简化为“首个匹配”，与 Flowable 返回全部匹配结果的语义不一致；
- `COLLECT`、`OUTPUT ORDER`、`PRIORITY` 直接返回 `ENGINE-1918`；
- 解析层不读取 `aggregation` 属性与输出列的 `outputValues`，无法表达聚合与优先级。

本期按 Flowable DMN 引擎的命中策略实现补全上述能力，并把求值结果从“单条结果”
扩展为“结果行列表”，同时保持 047 期已发布的单结果写入语义不变。

本期实现取代 047 文档的以下条目：

- `4.4 命中策略表：`RULE ORDER` 不再简化，`COLLECT` / `OUTPUT ORDER` / `PRIORITY` 已支持；
- `9.5、`9.6 限制：RULE ORDER 多结果聚合、COLLECT/OUTPUT ORDER/PRIORITY 未实现。

## 2. 模型与解析

### 2.1 决策表聚合器

`decisionTable` 读取 `aggregation` 属性（DMN 标准属性，Flowable `DmnXMLConverter`
同样读取该名称），缺省为空表示不做聚合。为兼容部分文档，属性缺失时再尝试
`aggregator` 别名。

- 取值大小写不敏感，允许 `SUM`、`MIN`、`MAX`、`COUNT`；
- 其他取值在解析阶段返回 400 `ENGINE-1921`，不会静默忽略；
- `dmnTableModel.Aggregation` 保存规范化后的大写值。

### 2.2 输出顺序值

输出列支持 DMN 的 `outputValues` 子元素：

~~~xml
<output id="level" name="等级" typeRef="string">
  <outputValues>
    <text>"high","medium","low"</text>
  </outputValues>
</output>
~~~

解析规则：

1. 取 `outputValues` 的文本内容并去除首尾空白，空文本表示未配置，保存为 `nil`；
2. 按顶层逗号拆分，双引号或单引号内的逗号不拆分；
3. 每个值去掉包裹引号后按输出列类型转换：
   - `number`：按数字解析，非法时 400 `ENGINE-1922`；
   - `boolean` / `bool`：`true` / `false`，非法时 400 `ENGINE-1922`；
   - `string`：保留字符串；
   - 类型缺失：依次推断布尔、数字，其余按字符串；
4. 解析结果保存到 `dmnOutputModel.Values []any`。

顺序值只在 `OUTPUT ORDER` 与 `PRIORITY` 中参与排序；其他策略即使配置了
`outputValues` 也不影响结果，但非法顺序值仍会让求值在解析阶段失败。

## 3. 语义矩阵

设 `matches` 为按文档顺序收集的全部匹配规则结果行，每行按输出列顺序保存
`dmnOutputValue`：

| `hitPolicy` | 返回 | 说明 |
| --- | --- | --- |
| 空 / `FIRST` | 1 行 | 命中首条后停止求值，不再执行后续规则 |
| `UNIQUE` | 1 行 | 出现第 2 条匹配立即返回 `ENGINE-1916`（即使输出相同） |
| `ANY` | 1 行 | 允许多条匹配，逐列比较输出，不一致返回 `ENGINE-1917` |
| `RULE ORDER` | 全部行 | 按文档顺序返回所有匹配结果 |
| `OUTPUT ORDER` | 全部行 | 按输出列声明顺序、`outputValues` 下标稳定排序后返回 |
| `PRIORITY` | 1 行 | 与 `OUTPUT ORDER` 同样排序，只取第一条 |
| `COLLECT`（无聚合器） | 全部行 | 收集全部匹配结果 |
| `COLLECT`（有聚合器） | 1 行 | 对唯一的 `number` 输出列做 `SUM`/`MIN`/`MAX`/`COUNT`（输出列数与类型有前置校验） |
| `UNORDERED` 及其他 | 0 行 | 返回 `ENGINE-1918` |

所有策略在没有规则匹配时统一返回 `ENGINE-1915`，与 047 期一致。

### 3.1 OUTPUT ORDER / PRIORITY 排序

排序键为输出列的 `outputValues` 列表下标：

- 按输出列声明顺序逐列比较，第一处不同即决定顺序；
- 未配置 `outputValues` 的输出列不参与比较；
- 输出值不在列表中（含空值 `nil`）时下标为 `-1`，排在所有列表值之前，
  与 Java `OutputOrderComparator` 的 `indexOf` 语义一致；
- 使用稳定排序，下标相同的规则保持文档顺序；
- 所有比较列都没有 `outputValues` 时返回 400 `ENGINE-1922`
  （对应 Flowable `strictMode = true` 默认行为）；
- 输出值不是数字、字符串、布尔或 `nil`（例如表达式返回映射/切片）时返回
  400 `ENGINE-1922`。

### 3.2 COLLECT 聚合与部署约束

配置聚合器时先执行与 Flowable `RuleEngineExecutorImpl.sanityCheckDecisionTable`
一致的前置校验（在输入表达式求值之前）：

- 输出列必须恰好 **1** 列，否则 400 `ENGINE-1921`；
- 该输出列的 `typeRef` 必须是 `number`（`string`、`boolean`、缺失等均拒绝），
  否则 400 `ENGINE-1921`；`COUNT` 同样要求 `number`；
- 校验通过后才求值规则。

聚合语义：

- 未配置聚合器：返回全部匹配结果；
- 配置聚合器：聚合唯一输出列在全部匹配行中已产生的值；
- `SUM`、`MIN`、`MAX`、`COUNT` 都要求输出值为数字（对应 Flowable 把输出统一
  转换为 `Double`），否则 400 `ENGINE-1921`；
- 聚合值统一为 `float64`，对应 Flowable 的 `Double`；
- 结果行只在该列写入聚合值，因此配置 `resultVariable` 时结果变量直接是聚合
  标量（单输出）；
- 匹配行均未产生输出值时返回一条空结果行，与 Flowable 的空决策结果一致；
  流程变量不会写入新值。

## 4. 多结果写入

`executeBusinessRuleTask` 按结果行数量适配 047 期语义：

| 场景 | 结果变量（配置 `resultVariable`） | 未配置 `resultVariable` |
| --- | --- | --- |
| 单行 + 单输出 | 标量 | 写入该输出列变量 |
| 单行 + 多输出 | `map[string]any`，键优先 id 其次 name | 每个有值输出列写一个变量 |
| 多行 + 单输出 | `[]any`，每项为该行标量 | 该输出列写 `[]any` |
| 多行 + 多输出 | `[]any`，每项为该行的 `map[string]any` | 每个输出列写 `[]any` |

多行写入的补充规则：

- 未配置结果变量时，列内未产生值的行（输出 `-`）被跳过，不写入空值；
- 整列都没有产生值时保持已有变量不变；
- 多行多输出映射中，未产生值的列不出现在该行的映射里；
- 输出列缺少 `id` 与 `name` 时仍返回 `ENGINE-1920`。

## 5. 与 Java 实现对照

| 关注点 | Flowable Java | 本期 Go 实现 |
| --- | --- | --- |
| 聚合属性 | `DecisionTable.aggregation`，`BuiltinAggregator` 枚举 | `decisionTable/@aggregation`，另兼容 `@aggregator` |
| FIRST | `HitPolicyFirst` + `ContinueEvaluatingBehavior` 命中即停 | 命中首条立即返回，不再求值后续规则 |
| UNIQUE | `HitPolicyUnique.evaluateRuleValidity`，`strictMode` 默认抛异常 | 第二条匹配立即 `ENGINE-1916` |
| ANY | `HitPolicyAny` 两两比较，严格模式抛异常 | 逐列比较，不一致 `ENGINE-1917` |
| RULE ORDER | `HitPolicyRuleOrder` 继承默认 `composeDecisionResults`，返回全部规则结果 | 按文档顺序返回全部匹配行 |
| OUTPUT ORDER | `HitPolicyOutputOrder`，按 `outputValues` 排序，`multipleResults = true` | 稳定排序后返回全部匹配行 |
| PRIORITY | `HitPolicyPriority`，排序后只取第一条 | 稳定排序后返回第一行 |
| 排序比较器 | `OutputOrderComparator`：`indexOf(o1) - indexOf(o2)`，缺失为 `-1` | `dmnOrderIndex` 返回值下标，缺失 `-1`，逐列比较 |
| COLLECT 收集 | `HitPolicyCollect` 无聚合器时返回全部规则结果 | 返回全部匹配行 |
| COLLECT 聚合 | 对唯一输出列的已产生值聚合，结果为 `Double` | 对唯一输出列的已产生值聚合，结果为 `float64` |
| 聚合前置校验 | `sanityCheckDecisionTable`：输出列恰好 1 列且 `typeRef` 为 `number`，否则抛异常 | 相同约束，违反时 400 `ENGINE-1921`，且在输入求值前返回 |
| 无顺序值 | `strictMode = true` 时抛 `FlowableException` | 返回 400 `ENGINE-1922` |
| BPMN 变量写入 | `DmnActivityBehavior`：单结果逐输出写变量；多结果把 JSON 数组写入决策 Key | 沿用 047 期的 `resultVariable` / 输出列模型，多结果写 `[]any` |

说明：Java 的 `businessRuleTask` 与 DMN 集成分支（`DmnActivityBehavior`）并不使用
`resultVariable` 属性，而是把多结果 JSON 数组写入决策 Key。Go 引擎的
`resultVariable` 是 047 期定义的兼容契约，本期只扩展其结果类型，没有改为
Java 的变量写入方式，避免破坏既有流程定义。

## 6. 错误码

沿用 047 期的 1910–1920，并新增两个稳定错误码：

| 错误码 | 场景 |
| --- | --- |
| `ENGINE-1915` | 没有任何规则匹配（所有策略） |
| `ENGINE-1916` | `UNIQUE` 命中多条规则 |
| `ENGINE-1917` | `ANY` 多规则输出不一致 |
| `ENGINE-1918` | 不支持的命中策略（含 `UNORDERED`） |
| `ENGINE-1920` | 输出列缺少 `id` 与 `name` |
| `ENGINE-1921` | `aggregation` 属性非法；`COLLECT` 聚合时输出列不是恰好一列或类型不是 `number`；聚合输出值不是数字 |
| `ENGINE-1922` | `OUTPUT ORDER`/`PRIORITY` 缺少 `outputValues`、顺序值解析失败，或输出值不是可排序标量 |

以上错误均以 `api.ErrBadRequest` 为 Cause，REST 层映射为 400；业务规则任务
在命令内执行，失败时由命令边界回滚，不落库。

## 7. 限制

1. `outputValues` 只支持单个 `<text>` 子元素，不支持按行声明多个 `<text>`；
2. 只支持内置四种聚合器，不支持 DMN 1.1 的 `C+` 去重收集、自定义聚合函数；
3. 不做输出 `typeRef` 强制转换。输出项的实际类型由字面量决定，若输出列的
   `typeRef` 与实际值类型不一致，排序时该值会被视为不在顺序列表中（下标 `-1`），
   聚合时会返回 `ENGINE-1921`；
4. 不支持日期、时间、duration、列表、上下文等 FEEL 类型，因此这些值不能作为
   排序键（会返回 `ENGINE-1922`）；
5. `UNORDERED` 视为不支持的命中策略，返回 `ENGINE-1918`（与 Flowable 未提供
   `UNORDERED` 行为类一致）；
6. `aggregation` 属性在任何策略下都会被解析校验，但只有 `COLLECT` 使用它；
   单输出与 `number` 类型约束也只在 `COLLECT` 且配置聚合器时生效；
7. 多结果在 Go 侧以 `[]any` 暴露，不是 JSON 数组对象；REST 序列化后仍是数组；
8. 无匹配时沿用 047 契约统一返回 400 `ENGINE-1915`；Java `DmnActivityBehavior` 默认返回空结果并继续，只有 `decisionTaskThrowErrorOnNoHits=true` 时才抛错。该行为差异本期未改变，调用方需按现有 Go 契约处理。
