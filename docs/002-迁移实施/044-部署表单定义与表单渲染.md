# 044 部署表单定义与表单渲染

> 文档编号：002-044  
> 更新日期：2026-10-28  
> 对应计划：008 任务、身份与表单；012 流程模型仓库

## 1. 背景

Flowable 设计器可将表单以 `.form` JSON 资源随流程一起部署，BPMN 的 `formKey` 引用该表单。此前本仓库只支持 BPMN 扩展属性 `formProperty`，`/form-definitions` 端点固定返回空数组。

本期实现部署内 `.form` 读取与启动/任务表单渲染。

## 2. .form 格式

```json
{
  "key": "leaveForm",
  "name": "请假申请",
  "fields": [
    {"id": "days", "name": "天数", "type": "long", "required": true},
    {"id": "reason", "name": "原因", "type": "string", "writable": true}
  ]
}
```

- `key` 为空时使用资源文件名（去掉扩展名）。
- 字段映射为 `FormProperty`：id/name/type/required/readable/writable/enumValues。
- 非法 JSON 或缺少 fields 在读取表单定义时返回 400，不静默忽略。

## 3. 端点

`GET /service/repository/process-definitions/{id}/form-definitions`

- 返回该定义所在部署的全部 `.form`，按资源名排序。
- 字段：

~~~json
{
  "key": "leaveForm",
  "name": "请假申请",
  "deploymentId": "dep-1",
  "resourceName": "forms/leave.form",
  "tenantId": "",
  "fields": [{"id": "days", "name": "天数", "type": "long", "required": true, ...}]
}
~~~

- 流程定义不存在 404；无表单返回 `[]`。

## 4. 启动/任务表单

- `GET /repository/process-definitions/{id}/start-form`；
- `GET /form/form-data?taskId=...`；
- 历史任务表单。

当 BPMN `formKey` 与同部署 `.form` 的 key 匹配时：

- 使用 `.form` 字段生成 `formProperties`；
- 值从流程变量/任务局部变量填充；
- required/readable/writable/enumValues 透传；
- 找不到对应 `.form` 时保持原有 BPMN 扩展属性行为。

## 5. 限制

1. 仅支持 JSON `.form` 资源，不支持 Flowable Form Engine 的完整表达式、动态字段与跨部署版本解析。
2. 表单定义无独立版本号，按部署隔离。
3. 表单提交仍按字段 ID 写入变量，不执行 `.form` 级校验（required 只透传）。
4. 未实现表单定义的部署/更新端点。

## 6. 测试

- `internal/engine/form_definitions_test.go`：部署解析、排序、key 回退、非法 JSON、启动/任务表单字段与值、回退 BPMN 属性。
- `internal/rest/definition_artifacts_test.go`：form-definitions 端点。
- 覆盖率：`internal/engine` 90.9%，`internal/rest` 90.2%。
