# 065 历史、审计与变量明细验收

验收日期：2026-10-29。对应进度总览 M5。

## 交付行为

- 六级历史使用独立矩阵验收：`none` 关闭历史；`instance` 保留实例；`task` 增加任务；`activity` 增加活动及变量最终值；`audit` 保留审计实体；`full` 才记录每次变量更新明细。
- 固定 Java 源码 `DefaultHistoryManager.recordHistoricDetailVariableCreate` 要求 `FULL`；修复原先在 `activity/audit` 级别也写明细的偏差。生产默认仍为 `audit`，需要逐次变量值时显式选择 `-history full`。
- 历史变量单条删除、独立任务变量按名读取及明细单条读取统一执行资源租户校验，越权返回资源不存在且不改变状态。
- 按名查询和明细读取通过历史实例、历史任务定位归属，仅恢复历史表后也可读取。实例变量按名查询排除同名任务局部变量。
- HTTP 审计记录认证后的主体和有效租户，支持 Basic、JWT 等统一认证入口；失败凭据不成为操作人。审计和指标记录首次实际终态响应码。

## 可重复验收

```bash
go test ./internal/engine -run 'TestHistoryLevelAcceptance|TestHistoricStandaloneTenantAcceptance|TestHistoricOnlyLookupAcceptance' -count=1
go test ./internal/rest -run 'TestAuditAuthenticatedIdentity|TestStatusWriterFirstHeader' -count=1
make check
```

新增用例先复现旧实现失败，再进行实现修复。原变量明细测试显式选择 `full`；普通测试继续使用 `audit`，避免提高默认测试级别掩盖生产行为。

## 边界

HTTP 审计仍为配置容量的内存环形日志，重启不保留；业务历史随快照或行仓储持久化。本文验收不代表异步历史、外部审计存储、清理调度或全量 Java HTTP 行为兼容已通过。
