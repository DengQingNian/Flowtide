# 034 执行动作端点

> 文档编号：002-034  
> 更新日期：2026-10-28  
> 对应计划：011 REST API 与兼容契约；007 变量、表达式与脚本引擎

## 1. 背景

Flowable 通过 `PUT /runtime/executions/{id}` 对单个执行执行动作（触发、信号、消息），
通过 `PUT /runtime/executions` 广播信号。本期实现安全的信号/消息子集。

## 2. 端点

### 2.1 单个执行

`PUT /service/runtime/executions/{id}`

请求：

~~~json
{
  "action": "message_event_received",
  "messageName": "approvedMessage",
  "variables": [{"name": "approved", "value": true}]
}
~~~

支持动作：

| action | 必填 | 说明 |
| --- | --- | --- |
| `signal_event_received` | signalName | 向该执行的匹配信号订阅投递 |
| `message_event_received` / `message` | messageName | 向该执行的匹配消息订阅投递 |
| `trigger` / `signal` | 无 | 触发无事件定义的接收任务/中间捕获事件 |

- 只触发 **executionId 匹配** 的订阅，不广播到其他实例。
- 成功返回 200 与执行信息；执行已结束时返回 204。
- 缺少名称 400；执行/订阅不存在 404；实例已结束 409。
- 其他 action 返回 400。

### 2.2 广播信号

`PUT /service/runtime/executions`

~~~json
{"action": "signal_event_received", "signalName": "refresh"}
~~~

- 仅支持 `signal_event_received`，广播到全部匹配订阅。
- 成功 204；缺少 signalName 或 action 非信号返回 400。

## 3. 引擎 API

`RuntimeService` 新增：

| 方法 | 说明 |
| --- | --- |
| `MessageEventReceivedForExecution(ctx, executionID, name, vars)` | 定向消息 |
| `SignalEventReceivedForExecution(ctx, executionID, name, vars)` | 定向信号 |
| `TriggerExecution(ctx, executionID, vars)` | 触发无事件等待执行 |

实现复用现有订阅触发逻辑：先按事件类型/名称查找订阅，再筛选 `executionId`，命中后执行变量写入、活动结束与出线调度。

## 4. 限制

1. transient variables 通过 `transientVariables` 字段支持，仅命令内可见。
2. 未实现 Flowable 的 `signalEventReceived` 多执行/租户批量匹配参数。
3. 消息仍为点对点（每个执行只取第一个匹配订阅）；信号在单执行上只取第一个匹配订阅。
4. 不触发启动事件订阅（需通过广播信号/消息接口）。
