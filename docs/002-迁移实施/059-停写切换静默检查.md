# 059 停写切换静默检查

> 实施日期：2026-10-28。对应命令为 `flowtide-migrate -cutover-check`。本阶段交付切换前的只读观察证据，不执行停写、备份、执行者切换或回退演练。

## 1. 问题与结果

`-preflight` 只做一次性扫描，能证明某一时刻的存量结构，却无法证明源 Java 库在一个观察窗口内保持静止。切换前如果仍有请求写入运行时表，或异步执行器、定时器继续推进作业，预检报告与离线状态文件会在生成后迅速过期。

本阶段在 `internal/migration` 新增 `CheckQuiescence` 与 `CutoverReport`，在 `flowtide-migrate` 新增 `-cutover-check`、`-quiesce-window` 两个参数。命令在观察窗口前后各做一次完整只读扫描，比较每张表的前后行数与确定性内容指纹：

- 两次快照的表集合、行数或内容任一变化，`stable` 为 `false`。
- 已知表即使行数不变，只要列值变化也会因指纹不同被识别。
- 未知表只有 `COUNT(*)`，报告明确标记 `contentCompared=false`，并在 `limitations` 中说明无法比对内容。
- 扫描、取消或数据库错误直接返回错误，不输出部分报告，也不写入报告文件。

## 2. 观察窗口的含义

`-quiesce-window` 是**两次快照之间的等待时间**，不是“静默保证期”，也不是自动停写开关：

1. 第一次快照完成，记录 `scanTimes[0]`；
2. 等待 `window`（默认 5 秒），等待可被 `-timeout` 或调用方取消立即中断；
3. 第二次快照完成，记录 `scanTimes[1]`；
4. 比较两次快照。

第二次扫描只能看到其快照建立前已提交的数据。因此：

- 窗口内提交的写入会出现在第二次快照，检查可以发现；
- 在第二次快照建立之后提交、或窗口结束后才提交的写入，检查无法发现；
- 未提交事务和已回滚写入通常不可见；
- 若源库持续有短事务写入，检查大概率判为不稳定，这正是需要人工停写或收紧写入入口的信号。

两次扫描**各自**开启 `ReadOnly=true`、`RepeatableRead` 事务并在返回前回滚。两次扫描刻意不复用同一个事务：同一可重复读事务的第二次查询仍读取第一次建立的快照，会把窗口内的变化全部遮蔽，无法承担“窗口内是否稳定”的判断。每次扫描内部保持一致快照，扫描之间相互独立，才能观察到窗口内提交的写入。

默认 5 秒只是保守起点。切换窗口较长或源端写入稀疏时，应按实际停写流程设置更长的 `-quiesce-window`，并保证 `-timeout` 大于窗口加两次扫描耗时。

## 3. 使用方式

```bash
make build
# MySQL 沿用 .env 配置；只读检查，不初始化源库。
./bin/flowtide-migrate -cutover-check -dialect mysql -env .env -quiesce-window 30s -out cutover.json
# PostgreSQL 从 FLOWABLE_POSTGRES_DSN 读取连接信息。
./bin/flowtide-migrate -cutover-check -dialect postgres -timeout 5m -quiesce-window 60s
```

参数约束：

- `-cutover-check` 与 `-preflight`、`-convert`、`-apply`、`-tables` 互斥，也不接受 `-tenant`。
- `-quiesce-window` 只允许与 `-cutover-check` 同时使用；`window <= 0` 在任何连接之前按参数错误拒绝。
- `-out` 可选。未指定时报告写入标准输出；指定时目标必须是普通文件、父目录存在、不能是 `.env` 配置文件或其链接，且不得覆盖已有文件。报告以同目录私有临时文件写入后硬链接发布，已存在的报告不会被覆盖。
- 报告内容只有表名、行数、指纹摘要、作业计数和固定边界说明，不包含变量值、部署源码、BPMN 内容或连接凭据。

| 退出码 | 含义 | 后续动作 |
| --- | --- | --- |
| 0 | 两次快照一致，窗口内未观察到变化 | 可继续切换准备，但仍需完成停写、备份和回退演练 |
| 2 | 检测到表集合、行数、内容或 Schema 版本变化 | 停止切换，定位写入来源并重新观察 |
| 1 | 参数、连接、扫描、取消或输出失败 | 修复后重跑；不得用旧报告或缺失报告代表本次结果 |

使用编译后的二进制获取退出码；`go run` 会包装非零退出状态。

## 4. 报告字段

| 字段 | 含义 |
| --- | --- |
| `dialect` | `mysql` 或 `postgres` |
| `schemaVersion` | 第一次快照从 `ACT_GE_PROPERTY` 读取的 `schema.version` |
| `windowSeconds` | 观察窗口秒数，如 `30` |
| `stable` | 窗口内是否未观察到变化；`false` 对应退出码 2 |
| `scanTimes` | 两次快照完成时间，RFC3339Nano UTC |
| `tables` | 每张表一项：`name`、`beforeRows`、`afterRows`、`contentCompared`、`beforeFingerprint`、`afterFingerprint`、`changed` |
| `changedTables` | 变化的表名，按字典序 |
| `jobCounts` | `ACT_RU_JOB`、`ACT_RU_TIMER_JOB`、`ACT_RU_SUSPENDED_JOB`、`ACT_RU_DEADLETTER_JOB`、`ACT_RU_EXTERNAL_JOB`、`ACT_RU_HISTORY_JOB` 的 `table`、`before`、`after` |
| `limitations` | 固定边界说明；存在未知表或 Schema 版本变化时追加对应说明 |

### 4.1 内容指纹

对 `Scan` 读取到行的已知表：

1. 每行列名统一大写并按字典序排序；
2. 每个值编码为“类型标记 + uvarint 长度前缀 + 内容”：`S` 字符串、`B` 字节、`D` 数字（整数与浮点归一为十进制文本）、`T` 时间（统一 UTC RFC3339Nano）、`N` 空值、`O` 布尔、`X` 未知驱动类型（保留类型名与文本）；
3. 列名同样按上述长度前缀编码，避免相邻字段拼接产生歧义；
4. 单行编码后按字节序排序，消除数据库返回顺序差异；重复行各自保留，不会被合并；
5. 按“行长度 + 行内容”依次写入 SHA-256，取前 16 字节的十六进制（32 个字符）作为报告中的指纹摘要。

因此行顺序、列顺序、同一时刻的不同时区表示都不会改变指纹；字符串 `"1"`、字节 `0x31`、数字 `1`、时间值和 `nil` 会产生不同指纹。指纹是摘要，不包含可还原的列值。

指纹对数据库返回的表示形式敏感：例如 `DECIMAL` 文本的尾随零、时间精度或驱动类型变化都会被保守地判为内容变化。这是有意为之——静默检查宁可误报变化，也不放过潜在写入。

### 4.2 稳定性判定

- 表只在一侧出现（窗口内建表或删表）或前后行数不同：`changed=true`；
- 两次都存在且属于已知表：比较内容指纹，不同则 `changed=true`；
- 未知表：只比较行数；同数改值无法发现，`contentCompared=false` 且 `limitations` 列明；
- `schemaVersion` 前后不同：即使表项未变化也判定 `stable=false`，并追加限制说明；
- `changedTables` 非空即 `stable=false`。

## 5. 只读与适用边界

本检查的所有数据库操作都是 `SELECT`、元数据查询和事务回滚，不执行 `INSERT`、`UPDATE`、`DELETE`、DDL、Schema 初始化、引擎恢复或变量反序列化。它不会修改源库，也不会创建 Go 状态文件。

`stable=true` **只表示观察窗口内未观察到变化**，不能替代以下工作：

- 真正的停写：关闭或冻结 Java 应用写入、消息消费、异步执行器和定时器；
- 备份：在停写后对源库做可恢复备份；
- 执行者切换：确认没有 Java 进程继续运行；
- 回退演练：验证 Go 写入后能否回到 Java 继续运行；
- 双跑隔离：禁止 Java 与 Go 同时处理同一批实例。

检查无法覆盖：

- 第二次快照建立之后发生的写入；
- 未提交事务、已回滚写入、其他数据库或模式中的写入；
- 非 `ACT_*` 表，例如业务自定义表或外部系统状态；
- 作业已触发外部副作用但尚未写回数据库的情况；
- 只读从库的复制延迟，以及非事务表的读写；
- 触发器、存储过程或数据库外部脚本产生的副作用。

## 6. 验证记录

按任务约束未运行 `make check`（会与并行任务争用 `coverage.out` 和 `bin`），只运行相关包测试，覆盖率文件写入 `/tmp`：

```bash
HOME=/root go test -count=1 -coverprofile=/tmp/mig_cutover.out ./internal/migration ./cmd/flowtide-migrate
```

结果：

| 包 | 结果 | 语句覆盖率 |
| --- | --- | --- |
| `internal/migration` | 通过 | 96.2% |
| `cmd/flowtide-migrate` | 通过 | 82.9% |

新增 `internal/migration/cutover.go` 的关键函数覆盖率：`CheckQuiescence` 94.7%、`buildCutoverReport` 95.5%、`tableFingerprint`/`rowFingerprint`/`appendFingerprintText` 100%、`encodeFingerprintValue` 90.9%。未覆盖分支主要是取消与窗口结束后的重复防御性检查、未知驱动类型的个别类型分支。

测试覆盖：

- 指纹：行顺序/列顺序无关、内容变化、重复行、字符串与字节、数字、时间（含时区归一）、空值、布尔、浮点与未知类型；
- 静默判定：稳定、内容变化、行数变化、表集合变化、未知表同计数、Schema 版本变化；
- 错误路径：`window<=0`、已取消上下文、窗口内取消、第一次扫描失败、第二次扫描失败、非法方言、空连接；
- CLI：模式互斥、`-quiesce-window` 限定、退出码 0/2/1、JSON 字段、已有报告拒绝覆盖、目录与配置文件拒绝、`0600` 权限、输出失败、依赖错误不泄漏凭据；
- 源库配置：MySQL/PostgreSQL 配置缺失或无效时返回通用错误，有效 PostgreSQL DSN 可建立连接池。

未添加真实 MySQL/PostgreSQL 集成测试；本阶段使用 `go-sqlmock` 验证 SQL 交互，不需要真实数据库。若后续补充集成测试，必须沿用 `FLOWABLE_MYSQL_INTEGRATION`、`FLOWABLE_POSTGRES_INTEGRATION` 显式门控，并在门控开启时让失败直接失败，不得跳过掩盖。

## 7. 下一阶段

静默检查只能作为停写切换的一个证据点。后续仍需把以下步骤纳入同一次受控切换：冻结写入与后台作业、备份源库、执行 `-convert`、在观察窗口内确认 `stable=true`、切换执行者、验证 Go 续跑，并完成首次回退演练。上述任一步缺失时，不得仅凭本报告启用 Go 接管。
