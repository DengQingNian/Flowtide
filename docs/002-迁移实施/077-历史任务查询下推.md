# 077 历史任务查询下推

> 文档编号：002-077
> 更新日期：2026-10-30
> 对应任务：MySQL 行仓储模式下 ACT_HI_TASKINST 查询下推

## 1. 背景与目标

[075](075-实例与历史查询下推.md) 与 [076](076-租户查询下推.md) 完成实例与历史实例查询下推；历史任务查询仍遍历内存 `e.state.HistoricTasks`。历史任务是查询频度最高的历史域，本次按同一模式下推：

- 新增 `flowable.HistoricTaskInstanceQuery` 与 `(*Repository).QueryHistoricTaskInstanceIDs`，在 `ACT_HI_TASKINST` 上执行 COUNT 与分页 ID 查询；
- `api.HistoryService` 新增 `QueryHistoricTaskInstances` 分页方法：满足安全条件时使用 SQL 返回的任务 ID，再从内存映射 DTO 并做归属校验；否则回退内存过滤；
- REST 的 `POST /query/historic-task-instances` 与 `GET /history/historic-task-instances` 按 1000 条分页循环读取，后续内存过滤、排序、分页与 DTO 装配不变；
- 既有 `ListHistoricTaskInstances` 保持不变，零回归。

## 2. 下推字段与 SQL 形状

```sql
SELECT COUNT(*) FROM ACT_HI_TASKINST T <WHERE>;

SELECT T.ID_ FROM ACT_HI_TASKINST T <WHERE>
ORDER BY T.START_TIME_ ASC, T.ID_ ASC LIMIT <n> OFFSET <m>;
```

| Filter 字段 | SQL 条件 |
| --- | --- |
| `ID` | `T.ID_ = ?` |
| `Name` | `T.NAME_ = ?` |
| `Assignee` | `T.ASSIGNEE_ = ?` |
| `TaskDefinitionKey` | `T.TASK_DEF_KEY_ = ?` |
| `ProcessInstanceID` | `T.PROC_INST_ID_ = ?` |
| `ProcessDefinitionID` | `T.PROC_DEF_ID_ = ?` |
| `TenantID` | `T.TENANT_ID_ = ?` |
| `Finished` | `T.END_TIME_ IS NOT NULL / IS NULL` |
| `StartedAfter/Before` | `T.START_TIME_ >= / <= ?` |
| `FinishedAfter/Before` | `T.END_TIME_ >= / <= ?` |
| `ProcessDefinitionKey` | `INNER JOIN ACT_RE_PROCDEF P ON P.ID_ = T.PROC_DEF_ID_ AND P.KEY_ = ?` |

边界语义与 075 一致：时间下界与上界均含等于；`END_TIME_` 为空的历史任务不满足任何结束区间；排序键与内存路径一致（开始时间升序、ID 升序）。

## 3. 门禁与内存回退

- 下推条件：`RowRepository` 已配置；生效租户（`effectiveTenantOf`）为空时要求 `hasNonDefaultTenantTaskHistory` 为假——该守卫同时扫描历史任务 DTO 自身租户与历史实例租户；生效租户非空时直接下推（076 语义）。
- SQL 失败返回错误码 `ROW-0050`（不支持查询）、`ROW-0051`（统计）、`ROW-0052`（ID 查询）、`ROW-0053`（扫描/转换）、`ROW-0054`（遍历），不静默回退。
- 内存回退匹配：等值组 + `Finished`（以 `EndTime != nil` 判定，与 REST `filterQueryHistoricTasks` 一致）+ 时间边界 + `ProcessDefinitionKey` 经 `findDefinition` 反查流程定义 Key；`allowHistoricResource` 归属校验在下推与回退两条路径都执行。
- 未下推字段：`nameLike`、`assigneeLike`、`taskDefinitionKeyLike` 等模糊匹配仍由 REST 内存过滤。
