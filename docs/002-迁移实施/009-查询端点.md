# 009 POST 查询端点

> 文档编号：002-009  
> 更新日期：2026-10-28  
> 对应计划：011 REST API 与兼容契约

## 1. 背景

Flowable 同时提供 GET 列表端点与 POST `/service/query/*` 查询端点。前者适合简单条件，后者用 JSON 请求体承载组合过滤、分页与排序，是 Flowable UI 与部分客户端的主要调用方式。

本期补齐 6 个查询端点：

| 方法 | 路径 | 数据源 |
| --- | --- | --- |
| POST | `/service/query/process-instances` | 运行中流程实例 |
| POST | `/service/query/executions` | 运行中执行 |
| POST | `/service/query/tasks` | 运行中任务 |
| POST | `/service/query/historic-process-instances` | 历史流程实例 |
| POST | `/service/query/historic-task-instances` | 历史任务 |
| POST | `/service/query/historic-activity-instances` | 历史活动 |

## 2. 请求约定

- 请求体为 JSON 对象；空请求体等价于空过滤条件。
- 未知字段按兼容约定忽略，不返回 400。
- `start` 默认 0，`size` 默认 10，最大 1000。
- `order` 只接受 `asc`/`desc`，默认 `asc`。
- `sort` 必须是资源支持的字段，非法字段返回 400。
- 时间字段接受 RFC3339、带毫秒偏移与无时区三种格式，无时区按 UTC 解释。
- 租户：请求体 `tenantId` 优先，其次 `X-Tenant-Id` 或 `tenantId` 查询参数；任务与历史任务/活动通过所属流程实例的租户过滤。

响应统一为：

~~~json
{
  "data": [],
  "total": 0,
  "start": 0,
  "size": 10,
  "sort": "createTime",
  "order": "desc"
}
~~~

未指定 `sort` 时不输出 `sort`/`order`。

## 3. 支持的过滤条件

### 3.1 流程实例

`id`、`processDefinitionId`、`processDefinitionKey`、`processDefinitionKeyIn`、`businessKey`、`businessKeyLike`、`name`、`nameLike`、`tenantId`、`startedAfter`、`startedBefore`、`finished`、`suspended`。

排序字段：`id`、`processDefinitionId`、`processDefinitionKey`、`businessKey`、`name`、`startTime`、`endTime`。

### 3.2 执行

`id`、`processInstanceId`、`processDefinitionId`、`activityId`、`ended`、`active`、`waiting`。

排序字段：`id`、`processInstanceId`、`processDefinitionId`、`activityId`。

### 3.3 任务

`id`/`taskId`、`name`、`nameLike`、`description`、`descriptionLike`、`assignee`、`assigneeLike`、`owner`、`ownerLike`、`unassigned`、`candidateUser`、`candidateGroup`、`candidateGroupIn`、`involvedUser`、`priority`、`minimumPriority`、`maximumPriority`、`processInstanceId`、`processDefinitionId`、`processDefinitionKey`、`processInstanceBusinessKey`、`taskDefinitionKey`、`tenantId`、`createdAfter`、`createdBefore`、`dueAfter`、`dueBefore`、`finished`。

排序字段：`id`、`name`、`description`、`assignee`、`owner`、`priority`、`createTime`、`dueDate`。

### 3.4 历史流程实例

`id`、`processDefinitionId`、`processDefinitionKey`、`processDefinitionKeyIn`、`businessKey`、`businessKeyLike`、`name`、`nameLike`、`deleteReason`、`tenantId`、`finished`、`startedAfter`、`startedBefore`、`endedAfter`、`endedBefore`。

排序字段：`id`、`processDefinitionKey`、`businessKey`、`name`、`startTime`、`endTime`。

### 3.5 历史任务

`id`/`taskId`、`name`/`taskName`、`nameLike`/`taskNameLike`、`assignee`/`taskAssignee`、`assigneeLike`/`taskAssigneeLike`、`taskDefinitionKey`、`taskDefinitionKeyLike`、`processInstanceId`、`processDefinitionKey`、`tenantId`、`finished`、`startedAfter`、`startedBefore`、`endedAfter`、`endedBefore`。

排序字段：`id`、`name`、`assignee`、`startTime`、`endTime`。

### 3.6 历史活动

`id`、`processInstanceId`、`activityId`、`activityType`、`activityName`/`name`、`activityNameLike`、`processDefinitionKey`、`tenantId`、`finished`、`startedAfter`、`startedBefore`、`endedAfter`、`endedBefore`。

排序字段：`id`、`activityId`、`activityType`、`activityName`、`startTime`、`endTime`。

## 4. 匹配语义

- 精确字段：空串表示不过滤，否则严格相等。
- `*Like`：去掉首尾 `%` 后做大小写不敏感子串匹配，兼容 Flowable 的 `%value%` 写法。
- 布尔字段：`finished=true` 对运行中资源返回空集合；历史资源按结束时间是否存在判断。
- 时间范围：`After` 为闭区间下界，`Before` 为闭区间上界；历史资源结束时间为空时不匹配结束时间条件。
- `candidateUser`：仅匹配未签收且候选用户包含该用户的任务；当前未展开用户组候选。
- `candidateGroupIn`：候选组与集合有交集即匹配。

## 5. 错误码

| 场景 | HTTP | 错误码 |
| --- | --- | --- |
| 请求体不是合法 JSON | 400 | `REST-0120` |
| 整数字段类型错误 | 400 | `REST-0121` |
| 时间字段格式错误 | 400 | `REST-0122` |
| 排序列或方向非法 | 400 | `REST-0123` |
| 布尔字段类型错误 | 400 | `REST-0124` |
| 字符串数组字段类型错误 | 400 | `REST-0125` |
| 引擎已关闭 | 503 | `ENGINE-0002` |

## 6. 限制

1. 变量过滤（`variables`、`processVariableValueEquals` 等）尚未实现，字段会被忽略。
2. 任务查询先取最多 1000 条运行中任务再在 REST 层过滤分页，超出部分不可见；后续应下推到引擎查询。
3. 任务与历史任务/活动通过索引映射补充流程定义 Key、业务键与租户，实例数量大时内存占用线性增长。
4. `candidateUser` 不展开组成员关系；`ignoreAssignee`、`involvedUser` 的组语义未实现。
5. 历史任务 DTO 暂不包含优先级、分类、所有者与流程定义 ID，因此这些过滤条件未开放。
