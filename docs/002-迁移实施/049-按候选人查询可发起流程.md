# 049 按候选人查询可发起流程

> 文档编号：002-049  
> 更新日期：2026-10-28  
> 对应计划：015 流程定义候选发起人；011 REST API 与兼容契约

## 1. 背景

Flowable 支持 `GET /repository/process-definitions?startableByUser={userId}`，只返回该用户可发起的流程定义。此前本仓库忽略该参数。

本期补齐过滤。

## 2. 语义

- 流程定义**没有候选发起人**：对所有人开放，始终包含。
- 存在候选发起人时：
  - 候选用户包含该用户 → 可发起；
  - 候选组包含该用户所属任一租户组 → 可发起。
- 用户不存在或不属于任何组时，只剩“无候选”定义。
- 其他查询参数（key/version/tenant/分页）先应用，再按候选人过滤。

## 3. 示例

~~~http
GET /service/repository/process-definitions?startableByUser=alice&size=50
~~~

响应仍为分页结构：

~~~json
{
  "data": [{"id": "leave:1:...", "key": "leave", ...}],
  "total": 1,
  "start": 0,
  "size": 50
}
~~~

## 4. 限制

1. 每次定义调用候选发起人查询，定义较多时为 N+1；后续可批量加载。
2. 仅按 IDM 用户/组匹配，未支持“所有人”显式候选或表达式。
3. 用户组不区分租户（与现有身份模型一致）。
4. 未实现 Flowable 的 `startableByUser` 与其他候选人参数的组合语义。

## 5. 测试

- `internal/rest/definition_startable_test.go`：通用定义、候选用户、候选组（组成员）、无候选用户、分页。
- 覆盖率：`internal/rest` 90.7%。
