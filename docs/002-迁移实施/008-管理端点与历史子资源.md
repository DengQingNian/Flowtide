# 008 管理端点与历史子资源

> 文档编号：002-008  
> 更新日期：2026-10-28  
> 对应计划：011 REST API 与兼容契约、010 历史、事件与审计

## 1. 背景

Flowable 8.x 的管理端点（`/service/management/*`）用于运维排查：查看引擎属性、数据库表、表结构与表数据。历史端点则用于按流程实例聚合查询变量、身份链接与评论。

本期补齐以下能力：

- 引擎属性与引擎属性别名端点。
- ACT_* 表清单、单表行数、列元数据与表数据分页。
- 任务表单读取端点。
- 历史流程实例的变量、身份链接与评论子资源。

## 2. 引擎 API 扩展

`api.ManagementService` 新增四个方法：

| 方法 | 说明 |
| --- | --- |
| `Properties(ctx)` | 返回 `ACT_GE_PROPERTY` 常用键与引擎运行信息 |
| `TableCount(ctx)` | 返回全部 Schema 表的行数，未出现的表补 0 |
| `GetTableMetaData(ctx, table)` | 返回表名、列名与列类型 |
| `QueryTableData(ctx, table, start, size, sortColumn, order)` | 表数据分页与排序 |

实现要点：

- 表结构直接解析内嵌 DDL，避免维护第二份列清单。
- 行数来自 `SnapshotRows`，与 SQL 落盘使用同一份行映射，保证导出与查询口径一致。
- 表数据未写入的列补 `null`，与 `SELECT *` 的列集合保持一致。
- 排序列必须是 DDL 中的真实列，排序方向只接受 `asc`/`desc`，防止注入。

`api.TaskService` 新增：

| 方法 | 说明 |
| --- | --- |
| `ListInstanceComments(ctx, processInstanceID)` | 返回流程实例下全部评论，包含任务评论 |

`api.HistoryService` 新增：

| 方法 | 说明 |
| --- | --- |
| `ListHistoricProcessIdentityLinks(ctx, processInstanceID)` | 按流程实例查询历史身份链接 |

## 3. 新增端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/service/management/properties` | 引擎属性 |
| GET | `/service/management/engine-properties` | 引擎属性别名 |
| GET | `/service/management/tables` | 表清单与行数 |
| GET | `/service/management/tables/{name}` | 单表行数 |
| GET | `/service/management/tables/{name}/columns` | 列名与列类型 |
| GET | `/service/management/tables/{name}/data` | 表数据分页 |
| GET | `/service/runtime/tasks/{id}/form` | 任务表单 |
| GET | `/service/history/historic-process-instances/{id}/variables` | 历史变量 |
| GET | `/service/history/historic-process-instances/{id}/identitylinks` | 历史身份链接 |
| GET | `/service/history/historic-process-instances/{id}/comments` | 历史评论 |

表名大小写不敏感，响应统一返回大写表名。

### 3.1 属性响应

~~~json
{
  "common.schema.version": "8.1.0.3",
  "schema.version": "8.1.0.3",
  "schema.history": "create(8.1.0.3)",
  "next.dbid": "1",
  "engine.version": "0.1.0",
  "historyLevel": "audit",
  "tenantId": ""
}
~~~

### 3.2 表数据响应

~~~json
{
  "data": [
    {"ID_": "rest:1:abc", "KEY_": "rest", "VERSION_": 1, "TENANT_ID_": null}
  ],
  "total": 1,
  "start": 0,
  "size": 10,
  "sort": "KEY_",
  "order": "desc"
}
~~~

查询参数：

- `start`、`size`：分页，默认 0/10，最大 1000。
- `orderAscendingColumn`、`orderDescendingColumn`：二选一，同时出现返回 400。

## 4. 历史子资源语义

- 变量：返回该实例的全部历史变量实例，按名称与 ID 稳定排序。
- 身份链接：包含处理人、所有者、候选用户、候选组，按创建时间排序。
- 评论：包含流程级评论与任务级评论，按时间排序。
- 三个端点均先校验历史实例存在；请求租户与实例租户不一致时返回 404，避免泄露其他租户资源。

## 5. 错误码

| 场景 | HTTP | 错误码 |
| --- | --- | --- |
| 表不存在 | 404 | `ENGINE-0918` |
| 历史实例跨租户 | 404 | `ENGINE-0919` |
| 排序列不存在 | 400 | `ENGINE-0916` |
| 排序方向非法 | 400 | `ENGINE-0917` |
| 同时指定两个排序方向 | 400 | `REST-0405` |
| 任务无表单 | 400 | `REST-0406` |

## 6. 限制

1. 表数据来自内存快照，不是实时数据库查询；接入行仓储后应与数据库内容一致，但当前不读取外部写入。
2. 二进制列（`BYTES_`）按 JSON Base64 输出，暂不支持 `application/octet-stream` 下载。
3. 管理端点尚未单独做管理员权限校验，沿用全局 RBAC（`admin` 权限）。
4. 任务表单端点要求 `formKey` 非空，与 Flowable 新表单模型保持一致；旧版 `formProperty` 仍可通过 `/service/form/form-data` 读取。

## 7. 测试

- `internal/persistence/schema`：表列解析、约束过滤、未知表。
- `internal/engine`：属性、表行数、列元数据、分页/排序/越界/非法参数、实例评论与链接。
- `internal/rest`：端点成功路径、404/400/503、租户隔离、任务表单。
- 覆盖率：`internal/engine` 90.2%，`internal/rest` 90.4%，`internal/persistence/schema` 95.7%。
