# 036 无事件等待与执行触发

> 文档编号：002-036  
> 更新日期：2026-10-28  
> 对应计划：006 流程执行引擎 PVM 设计；011 REST API 与兼容契约

## 1. 背景

Flowable 允许接收任务或中间捕获事件不配置消息/信号/定时器，由外部通过 `runtimeService.trigger` 唤醒。此前本仓库：

- 接收任务缺少消息/信号时运行期直接报错；
- 中间捕获事件缺少事件定义时报错；
- 执行动作不支持 `trigger`。

本期补齐“无事件等待 + 显式触发”。

## 2. 模型与运行时

### 2.1 无事件接收任务

`<receiveTask id="recv"/>`（无 `messageRef`/`signalRef`）：

- 进入后设置 `Waiting=true`，不创建事件订阅。
- 只能通过 `TriggerExecution` 唤醒。

### 2.2 无定义中间捕获事件

`<intermediateCatchEvent id="wait"/>`（无消息/信号/定时器/条件/链接定义）：

- 同样进入等待，不创建订阅。
- 通过 `TriggerExecution` 唤醒。

### 2.3 触发语义

`TriggerExecution(ctx, executionID, variables)`：

1. 校验执行存在、实例未结束/未挂起、执行处于等待状态。
2. 校验当前活动是**可触发**的接收任务或中间捕获事件：
   - 带消息/信号/定时器/条件/链接定义的活动返回 400，要求使用对应事件接口。
3. 写入变量。
4. 结束当前活动历史、清除等待、沿当前活动出线继续。
5. 运行 Agenda，可能创建用户任务或结束实例。

## 3. 端点

`PUT /service/runtime/executions/{id}`

~~~json
{
  "action": "trigger",
  "variables": [{"name": "approved", "value": true}]
}
~~~

- `action` 可为 `trigger` 或 `signal`（Flowable 的 trigger action 名称）。
- 成功返回 200 与执行信息；若执行结束返回 204。
- 执行不存在 404；实例结束/挂起 409；活动不支持触发或并非等待状态 400。

## 4. 引擎 API

`RuntimeService` 新增：

```go
TriggerExecution(ctx context.Context, executionID string, variables []Variable) error
```

## 5. 限制

1. `transientVariables` 已支持，仅触发命令内可见；普通 `variables` 会持久化。
2. 只支持顶层活动，子流程内部等待执行需通过执行 ID 直接触发（能力接口相同）。
3. 触发用户任务返回 400，用户任务应通过完成/签收动作处理。
4. 带事件定义的活动必须使用消息/信号/定时器接口，trigger 不绕过。
