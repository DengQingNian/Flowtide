# 067 双库行服务与迁移闭环验收

验收日期：2026-10-29。对应进度总览 M7，服务范围为单执行者；集群、容量与生产迁移另行验收。

## 双库服务模式

```bash
./bin/flowable-migrate -dialect postgres -env .env -apply
./bin/flowable-server -storage postgres-rows -env .env -history full
```

PostgreSQL 配置支持环境优先的 `FLOWABLE_POSTGRES_DSN`，也支持 `.env` 中 `db_pg_host/port/user/pwd/db/schema/sslmode`。原开发文件的 `db_pg_schame` 拼写继续兼容，正确字段优先；原 libpq 键值连接串继续兼容。密码使用 URL 正确转义，连接失败不打印凭据。

PostgreSQL Schema 在事务中原子初始化并写入校验和标记；已有库校验版本、完整表数及脚本摘要，部分表、未知来源或不匹配版本拒绝自动接管。

`postgres-rows` 使用数据库会话独占锁。所有查询、写入、事务及提交归属检查均在同一持锁物理连接执行；连接终止后不会透明重连继续写入。释放时销毁物理连接，避免带锁会话回池。标准服务拒绝与 `-state`、旧 SQL 快照混用。

## 源库与状态核对

```bash
./bin/flowable-migrate -verify-state -verify-source \
  -dialect postgres -env .env -state prepared-state.json -out reconcile.json
```

`-verify-source` 必须配合 `-verify-state`。命令只读扫描源库，在隔离内存引擎重新转换源快照，并与待接管状态的规范行投影逐表比较。报告包括状态 SHA-256、预期与实际行数、内容指纹、差异表及边界，不含业务值、源码或凭据。支持与转换阶段一致的 `-tenant` 范围。

退出码：0 表示一致；2 表示数量或内容不同；1 表示预检阻断、读取、恢复或输出失败。已有报告不覆盖。测试以修改已有大整数但保持变量数量不变的方式验证内容差异会被发现。

## 真实数据库迁移演练

`TestIntegrationJavaDatabaseCutover` 在独立 MySQL/PostgreSQL 临时库执行：

1. 将固定 Java 引擎实际生成的 approve/review JDBC 黄金行写入目标方言 Schema。
2. 只读扫描形成真实源库快照，执行预检、转换、逐表状态核对及静默检查。
3. 将准备状态投影写入行仓储，由全新 Go 引擎从数据库恢复。
4. 核对任务、候选人、流程与任务局部变量、大整数、日期、JSON、字节及 audit 历史；完成当前任务并对照 Java 公共服务期望。
5. 再次从数据库启动独立引擎，确认续跑结果已提交。
6. 使用源快照还原临时数据库，重新只读扫描并核对备份指纹完全一致。

演练暴露并修复三项实际问题：官方身份版本表被误阻断；BLOB/bytea 完整评论无法恢复；Java 迁移顺序流历史模式在行恢复后丢失。身份版本表只放行固定版本标记，未知属性、缺失行及版本冲突仍阻断，身份业务表不因此获得迁移支持。

PostgreSQL 服务专项额外验证第二个执行者拒绝、重启续跑、full 明细保留及 `pg_terminate_backend` 断线事务回滚。

## 可重复执行与证据范围

```bash
make check
make race
make test-mysql
FLOWABLE_POSTGRES_DSN='由运行环境注入' make test-postgres
```

双库集成均只创建及删除测试生成的临时库；普通测试不连接业务库。CI 的 databases 任务在 push/pull_request 执行双库测试。

以上演练证明固定 Java H2 样本在双库的单执行者转换、行模式续跑及源快照还原，不是现场 Java 执行者停写、数据库物理备份或 Java 重新接管 Go 增量数据的演练。生产切换、反向转换、Java 续跑、集群与长稳仍须单独验收。简单用户任务之外的复杂作用域、Java 作业与订阅继续保守阻断。
