## 1. 兼容版本制品

参考 Java 提交固定为 `f6017e32a4bdd3e59a8881f58b0ee181652d1d9e`；数据库脚本标识 `8.1.0.3`。`8.1.0-SNAPSHOT` 只描述上游开发版本，不再作为可执行比较基线。`testdata/compatibility/baseline.json` 绑定官方规范副本、两份 DDL、变量类型、数据库验收版本和 BPMN 语料摘要；`make contract` 校验摘要及端点表。

修改任何基线资产需要更新清单，重新执行模型/运行路径/HTTP 三层验证。当前包含 Go 回归、184 个官方方法的路由与权限矩阵、Java 用户任务黄金样本的 Go HTTP 业务对照、六个异步变量方法的原版控制器 HTTP 回放、双库转换续跑与源快照还原演练；全量 Java REST 原始请求/响应逐字段验收仍未完成。不得将资产校验通过称为 Java 兼容通过。

## 4. 发布、实例归属与回退

首个生产试点采用受控停写切换，不使用按 HTTP 请求随机分配 Java/Go 的百分比灰度。切换前停止两个执行者及其后台作业，核对备份、预检和转换报告，明确租户/实例集合归属后启用唯一执行者。禁止双写。

后续灰度只能按独立数据库、租户或固定实例集合划分。启动、任务完成、定时器、消息、信号和后台作业必须使用同一归属路由；没有作业仲裁的共享库不得同时运行两个引擎。回退必须依靠备份恢复或已验证的反向转换与续跑，保留旧镜像本身不构成数据回退。

## 5. 资源与依赖重排

旧估算 483 人周与 6.5 FTE×70 周=455 人周存在 28 人周缺口。若范围和产能不变，最低需向上取整为 75 周；若保持 70 周则至少需要 6.9 FTE 的可用工程产能。两者都没有实际人员和新剩余工作量依据，不能直接转成日期承诺；暂停旧 W42/W70 与 GA 日历承诺，项目负责人在验收资料齐备后重估。

剩余依赖固定为：基础门禁和恢复隔离 → 行事务双库验收 → 既有库预检/转换与 Java 对照 → 停写迁移/回退演练 → 集群与容量 → 多引擎扩展。M10–M13 的发布验收依赖 M9 通过，设计研究可提前，不可提前宣布阶段退出。范围总览统一使用 M0–M13，不再引用不存在的 M15/M18。

## 6. 可重复执行的最小门禁

- `make check`：格式、中文命名函数注释、vet、普通测试、覆盖率、基线摘要、端点清单、独立 SDK 模块及构建。
- `make race`：单独使用 CGO 与 C 编译器执行竞争检测；环境不可用必须失败。
- `make test-mysql`：从 `.env` 或环境读取开发配置，只创建和删除测试生成的临时库。
- `make test-postgres`：通过 `FLOWABLE_POSTGRES_DSN` 注入连接，只创建和删除测试生成的临时库。
- `make bench`：运行引擎与行仓储基准；只用于容量观察和回归比较，不进入默认门禁，也不作为生产容量承诺。

Go 工具衡量的是语句覆盖率，采用执行语句加权的 90% 总量及逐核心库包阈值。`.coverignore` 只列 `cmd/` 与 `tools/` 两类可执行入口，接受构建、SDK 和集成检查；不存在隐式排除。95% 关键包/新增代码与真实行覆盖率不作为当前已实现能力宣称，后续需独立工具及固定增量基准。
