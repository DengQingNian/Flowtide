## 第五阶段：行仓储服务模式、静默检查与证书身份映射

本阶段继续并行推进持久化、迁移切换准备与安全收口；三项均只完成本地与真实 MySQL 临时库证据，不改变“未完成停写切换、回退、Java 行为对照和集群验收”的结论。

- 行仓储服务模式：`flowable-server -storage mysql-rows` 使用 ACT_* 行作为权威状态，启动从行表恢复，命令后增量写入；与快照模式共用数据库独占锁并拒绝混用，包装 DB 在每次读写/事务提交前校验锁归属。真实 MySQL 8.0.35 临时库验证部署、启动、完成任务、关闭后恢复、第二个实例取锁失败及快照混用拒绝，见 [058](../002-迁移实施/058-MySQL行仓储服务模式.md)。
- 停写静默检查：`flowable-migrate -cutover-check -quiesce-window` 在窗口前后各做一次独立只读扫描，比较表集合、行数、确定性内容指纹与 Schema 版本；稳定退出 0、变化退出 2、失败退出 1。它只证明观察窗口内未见写入，不替代停写、备份、执行者切换或回退，见 [059](../002-迁移实施/059-停写切换静默检查.md)。
- mTLS 证书身份：新增 `WithClientCertificateIdentity` 与 `-tls-client-identity`，在无 HTTP 凭据且证书链已通过 TLS 校验时，用 CN 作为身份、O/OU 作为租户，复用现有租户隔离；HTTP Basic/Bearer/JWT 保持优先且失败不回退。RBAC 角色、CRL/OCSP 与证书热加载仍未实现，见 [060](../002-迁移实施/060-mTLS证书身份映射.md)。
