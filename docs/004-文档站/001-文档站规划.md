## 1. 背景

仓库现有 82 篇中文文档：14 篇设计、64 篇实施、4 篇审计，另有 README。它们面向项目内部，记录的是设计取舍、实施证据和验收边界。外部开发者真正关心的问题——能不能用、怎么开始、能替代多少、哪里会踩坑——目前要跨多篇文档拼答案。

主要缺口：

| 缺口 | 现状 | 后果 |
| --- | --- | --- |
| 没有入门路径 | README 直接进入构建与 curl | 新用户不知道先做什么 |
| 没有落地页 | 只有 GitHub README | 选型者无法在 3 分钟内判断是否适合 |
| SDK 文档缺失 | 仅有「公共构造入口」测试 | Go 开发者只能读源码 |
| REST 文档偏对照 | 004 是端点审计表 | 缺少按业务域组织的请求/响应说明 |
| 状态表达分散 | README、003、004 各说一部分 | 容易把「路由已编码」误读为「生产可用」 |
| 迁移手册缺失 | 053–063 是实施记录 | 迁移团队缺少可执行的操作步骤 |
| 示例不可验证 | 文档片段散布在测试中 | 复制后可能跑不通 |

## 2. 目标与度量

### 2.1 用户目标

| 目标 | 度量方式 | 现状基线 | 目标 |
| --- | --- | --- | --- |
| 跑通第一个流程 | 从打开站点到任务完成 | 需阅读多篇文档 | ≤ 10 分钟 |
| 嵌入 Go 应用 | 从创建模块到 SDK 调用成功 | 需读源码与测试 | ≤ 30 分钟 |
| 判断能力边界 | 找到对应矩阵与限制 | 3–5 次跳转 | ≤ 3 次点击 |
| 完成迁移预检 | 从阅读到产出 preflight 报告 | 仅实施记录 | ≤ 30 分钟 |
| 找到 REST 用法 | 按域检索到方法、参数、错误 | 仅对照表 | 每次查询 ≤ 2 分钟 |

### 2.2 工程目标

- 文档、示例、生成器与代码同仓库，同一个 PR 评审。
- 所有 Go 示例可编译，所有 REST 示例可在临时服务上执行。
- 能力矩阵、REST 参考、配置表、错误码表由脚本生成，禁止手抄。
- 文档版本与 release tag 对齐，旧版本可访问。
- 文档构建、链接检查、示例检查进入 CI。

### 2.3 非目标

- 不翻译或复刻 Flowable 全量文档。
- 不做在线 BPMN 建模器、表单设计器。
- 不做社区论坛、评论系统。
- 首期不做完整英文版，只保留 i18n 骨架与术语表。

## 3. 读者与场景

| 读者 | 关心的问题 | 首屏入口 | 关键页面 |
| --- | --- | --- | --- |
| Go 应用开发者 | 能否嵌入、API 怎么用、数据怎么持久化 | 快速开始（SDK） | SDK 概览、服务、委托、配置 |
| 架构师/选型者 | 替代多少、性能如何、风险在哪 | 落地页 | 兼容性矩阵、架构、路线图 |
| Java Flowable 迁移团队 | 存量库能否接管、如何切换与回退 | 迁移指南 | 预检、转换、停写、回退 |
| 运维/SRE | 部署形态、指标、备份、限制 | 运维 | 存储模式、TLS、监控、容量 |
| 贡献者 | 代码结构、测试门禁、文档规范 | 贡献指南 | 架构、测试、文档规范 |

## 4. 内容原则

1. **状态可验证**：每页在 frontmatter 标注 `status`、`verifiedCommit`、`verifiedAt`；能力声明必须链接能力矩阵。
2. **代码即文档**：Go 片段来自 `examples/` 下可编译文件；REST 片段来自可执行脚本；输出来自真实运行。
3. **单一事实源**：设计细节留在 `docs/001`，实施证据留在 `docs/002`，公开站只做提炼与导航，不复制长文。
4. **先跑通再解释**：每篇 How-to 以可观察结果结尾，再做原理说明。
5. **诚实边界**：统一使用三档状态——已验证、原型可用、规划中；禁止无证据的「生产可用」。
6. **中文优先**：中文为默认语言，术语保留英文原名；英文版在 v1 发布后按流量排序翻译。

## 7. 技术方案

### 7.1 选型

| 关注点 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite 7 | 快、静态产物、生态成熟 |
| 框架 | Vue 3.5 + TypeScript 5.9 | 团队技术栈；类型安全 |
| 组件 | Naive UI | 用户指定；主题能力强，适合文档与落地页 |
| 路由 | vue-router 4 | 静态路由 + 懒加载 |
| 内容 | Markdown + `import.meta.glob` | 内容与代码分离，构建期解析 |
| 高亮 | Shiki | 构建期高亮，亮/暗双主题 |
| 搜索 | MiniSearch | 纯前端、无服务依赖、可离线 |
| 状态 | 组合式函数 | 站点简单，不引入 Pinia |
| 测试 | Vitest + Playwright | 组件、路由、可访问性冒烟 |

不使用 VitePress 的原因：需要 Naive UI 设计体系、定制落地页、生成式 API 参考与版本切换；VitePress 的主题定制成本更高。内容组织方式可借鉴 VitePress。

### 7.3 内容加载与渲染

- 构建期通过 `import.meta.glob('./content/**/*.md', { query: '?raw', eager: true })` 读取原文，`gray-matter` 解析 frontmatter，`markdown-it` 渲染，Shiki 负责代码块。
- 路由由内容清单生成：`/docs/{section}/{slug}`，sidebar 按 `order` 排序。
- Markdown 内可直接使用 Naive UI 组件：`<n-alert>`、`<n-tabs>`、`<n-steps>`、`<n-code>`，以及站点组件 `<CodeGroup>`、`<StatusBadge>`、`<CompatMatrix>`。
- 每个页面构建时抽取 h2/h3 生成右侧目录，滚动高亮。
- 代码块支持复制、文件名、行高亮；多语言用 `<CodeGroup>` 以 Tab 展示 Go / curl / JSON。

### 7.4 生成器

| 脚本 | 输入 | 输出 | 失败策略 |
| --- | --- | --- | --- |
| `gen-sdk-reference` | `go doc`/gomarkdoc，公开包 `flowable`、`api`、`bpmn/model` | SDK API Markdown | 公开符号缺注释即失败 |
| `gen-rest-reference` | 官方 `flowable-swagger-process.yaml` + `tools/contract` 端点表 | OpenAPI JSON + 分域页面 | 官方路径未覆盖即失败 |
| `gen-compat` | `docs/003` 能力矩阵、`docs/003-迁移审计/004` 状态统计 | `compat.json` | 表格解析失败即失败 |
| `gen-config` | `engine.Config`、`cmd/flowable-server` flag 定义 | 配置参考 | 字段缺注释即失败 |
| `gen-errors` | `api/errors.go` 错误码 | 错误码表 | 重复码即失败 |

生成文件带 `<!-- generated: do not edit -->` 标记，CI 重新生成后校验无差异。

### 7.5 交互与设计

- 亮/暗主题跟随系统，Naive UI 主题变量统一品牌色。
- 顶部导航 + 左侧分组侧栏 + 右侧目录；移动端抽屉。
- `Cmd/Ctrl + K` 搜索，支持标题、正文、代码片段。
- 版本选择器：`next` 与已发布版本；旧版本顶部提示。
- 页面底部：编辑此页、报告问题、上一页/下一页。
- 状态徽标：已验证（绿）、原型可用（黄）、规划中（灰）。
- 代码块：复制、Shell 提示符、输出折叠。
- 可访问性：跳过导航、焦点可见、对比度、键盘可达、语义标题层级。

### 7.6 部署

- 静态构建，产物部署到 GitHub Pages / Netlify / Cloudflare Pages。
- 每个 PR 生成预览链接；主分支部署 `next`。
- 发布 tag 时快照到 `/docs/v0.x/`，保留旧版本至少两个 minor。
- `sitemap.xml`、`robots.txt`、canonical、hreflang、OG 图。
- 404 页提供搜索与热门入口。

## 8. 内容生产流水线

| 内容 | 事实源 | 生产方式 | 校验 |
| --- | --- | --- | --- |
| 能力状态 | `docs/003` 能力矩阵 | `gen-compat` 生成 JSON | `make contract` + 生成差异 |
| REST 端点 | 官方 OpenAPI + `004` 对照表 | 生成 + 人工补充示例 | 路由清单校验 |
| SDK API | Go 注释与签名 | gomarkdoc 生成 | 编译 + 示例测试 |
| 配置项 | `engine.Config`、CLI flag | 生成 | 与代码一致 |
| 错误码 | `api/errors.go` | 生成 | 重复/缺失检查 |
| How-to 步骤 | `examples/` 可执行脚本 | 人工编写 + 脚本引用 | CI 执行 |
| 迁移命令 | `cmd/flowable-migrate` | 人工 + 帮助文本 | 命令快照测试 |

写作流程：

1. 在 `examples/` 增加最小可运行示例，并在 CI 中通过。
2. 在 `docs-site/src/content/` 写页面，引用示例文件。
3. 生成器更新参考页。
4. 技术评审：由对应模块负责人核对语义与限制。
5. 文档评审：术语、状态标签、链接、可执行性。
6. 合并后部署预览，发布时打版本快照。

## 9. 版本与国际化

- `next` 跟踪主分支；每个 release tag 生成只读快照。
- 页面 frontmatter 的 `since` 标注引入版本；破坏性变更在旧版本页顶部提示。
- 中文为默认 locale；英文版目录预留 `en/`，优先翻译落地页、快速开始、SDK 概览、REST 约定。
- 状态标签与限制说明不机器翻译，必须人工复核。

## 10. 质量门禁

| 检查 | 工具 | 阻断 |
| --- | --- | --- |
| 构建 | `vite build` + `vue-tsc` | 是 |

## 12. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 文档与代码漂移 | 用户按文档失败 | 示例 CI、生成器、`verifiedCommit` |
| 过度宣称 | 误用于生产，损害信誉 | 状态三档、措辞扫描、矩阵链接 |
| 示例腐化 | 复制即错 | 示例独立目录 + 编译/执行门禁 |
| 版本膨胀 | 维护成本高 | 只保留两个 minor，其余归档 |
| 中英文不同步 | 信息不一致 | 英文延后，先建术语表与骨架 |
| 截图维护 | 频繁过期 | 优先文本/代码，截图仅用于 UI 流程 |
| 生成器解析脆弱 | 构建失败 | 生成器单测 + 失败即阻断 |
