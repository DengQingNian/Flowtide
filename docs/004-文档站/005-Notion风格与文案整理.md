# Notion 风格与文案整理

## 调整范围

本次按 notion-style 整理首页、文档中心、进度看板、能力矩阵、REST 查询和公共导航。按 humanizer 检查页面介绍与技术文档中的套话、重复说明和长段落。

首页直接提供安装、Go SDK 和 Java 迁移三个阅读入口。使用范围、原型状态、单执行者与待验收工作仍在页面中显示。

## 视觉约定

| 项目 | 约定 |
| --- | --- |
| 正文背景 | 白色 |
| 辅助背景 | `#f7f6f3`，用于侧栏和阅读块 |
| 主文字 | `#37352f` |
| 边框 | `#e9e7e2`，圆角主要为 6 或 8 像素 |
| 悬停 | 背景变为 `#efedea`，边框、阴影和位置保持稳定 |
| 按下 | 背景变为 `#e3e1db` |
| 过渡 | 150 毫秒，限背景、文字和透明度等必要反馈 |
| 图标 | 保留现有线性图标，阅读块悬停时显示装饰性手柄 |
| 暗色 | 中性深灰背景，使用独立的文字、边框和状态色变量 |

移除渐变、光晕、网格装饰、大圆角和悬浮位移。普通卡片不使用阴影，搜索面板与移动目录保留轻阴影以区分遮罩层。手柄不提供拖动功能，不占用键盘焦点。

长代码与宽表格在自身容器中横向滚动。文档框架显式限制为可用宽度，避免在窄屏下被内容撑宽。

## 文案检查结果

### 检测

主要页面介绍存在中度机械感。问题集中在抽象标题、重复的否定铺垫，以及把多项实现和验收状态压进同一句话。配置字段、命令说明与大多数技术表格已经足够直接，保留其原意。

### 修改统计

- 调整五个主要页面及公共导航、页脚和搜索提示。
- 重点改写十一篇技术文档的介绍、段落或操作建议。
- 另外五篇技术文档只整理自然语言引号。
- 核对十六篇变更文档，围栏代码示例全部保持原样。

### 修改示例

| 原文 | 修改后 |
| --- | --- |
| 从一个可验证的事实开始 | 文档中心 |
| 进度是从提交里长出来的 | 最近更新 |
| 六条能力主线，各自带边界 | 已实现的功能 |
| 一项能力，四种证据 | 能力矩阵 |
| 找到端点，也看到差异 | REST 端点查询 |

进度总览原本把运行方式、已通过测试和未完成验收放在一个长句里。现在分成两段，先说明能运行哪些操作，再列出已通过和待完成的验收。

迁移总览先说明工具能检查什么，再说明需要人工完成的停写、备份和回退工作。已知问题中的操作建议也改为完整句子，直接写出接入前要做的检查。

### 质检记录

检查对象是本次重写的页面介绍与段落。技术标识、代码、结构化数据和已有参考表格按各自语法保留。

| 层次 | 检查结果 |
| --- | --- |
| L1 用词与句式 | 重写段落去掉空泛标题、否定铺垫和重复连接词；不添加宣传词或虚构数据 |
| L2 节奏与风格 | 长段落拆为可独立理解的短段；页面标题直接说明用途；不添加与技术说明无关的玩笑或自嘲 |
| L3 内容质量 | 保留功能限制、命令参数和验收范围；历史提交统计明确标注对应提交，当前数据链接到进度看板 |
| L4 通读 | 先写读者能查什么、要执行什么，再补充限制；同一页避免重复解释状态标签 |

完整修改内容见 `docs-site/src/pages/` 与 `docs-site/src/content/`。

## 数据与交互修正

- 文档中心的文档数量从内容索引计算。
- 进度页的阶段总数、部分完成数和未完成数从里程碑数组计算。
- 页面说明改为构建时更新，避免读者误以为数据会实时刷新。
- 搜索快捷键统一由搜索面板处理，修复顶部导航与面板重复监听导致打开后立即关闭的问题。
- 移动导航补充展开状态与受控区域标识。

## 验证方式

先补充页面和交互回归测试，再完成样式与文案修改。`npm test` 默认执行前端源码行覆盖率检查，最低要求为 90%。统计包括入口文件、路由、布局、组件和页面，排除类型声明与生成物。

浏览器检查包括九个主要路由、搜索、主题切换、能力筛选、REST 筛选、移动菜单、文档目录和 404。另检查卡片悬停前后的位置、边框与阴影，并在 320、390、768、1280 像素宽度下检查六个主要页面是否横向溢出。

截图保存在 `docs-site/screenshots/`，该目录不提交。生产构建和文档生成会检查站内路由与标题锚点。
