### 4.2 REST 快速开始

这是 P0 的核心页面，按「部署 → 启动 → 查询 → 完成 → 查历史」组织。以下命令已在 2026-10-29 的当前提交上验证通过。

**流程文件 `hello.bpmn20.xml`**：

~~~xml
<?xml version="1.0" encoding="UTF-8"?>
<definitions xmlns="http://www.omg.org/spec/BPMN/20100524/MODEL"
             xmlns:flowable="http://flowable.org/bpmn"
             targetNamespace="http://example.com">
  <process id="helloWorld" name="Hello World" isExecutable="true">
    <startEvent id="start" name="Start"/>
    <sequenceFlow id="flow1" sourceRef="start" targetRef="usertask"/>
    <userTask id="usertask" name="Hello" flowable:assignee="${initiator}"/>
    <sequenceFlow id="flow2" sourceRef="usertask" targetRef="end"/>
    <endEvent id="end" name="End"/>
  </process>
</definitions>
~~~

**部署**：

~~~bash
curl -sS -X POST 'http://localhost:8080/service/repository/deployments?deploymentName=hello' -H 'Content-Type: application/xml' --data-binary @hello.bpmn20.xml
~~~

预期：`201`，返回 `id`、`name`、`deployTime`。

**启动实例**：

~~~bash
curl -sS -X POST 'http://localhost:8080/service/runtime/process-instances' -H 'Content-Type: application/json' -d '{"processDefinitionKey":"helloWorld","variables":[{"name":"initiator","value":"alice"}]}'
~~~

预期：`201`，返回 `id`、`processDefinitionId`、`variables`，`ended=false`。

**查询待办**：

~~~bash
curl -sS 'http://localhost:8080/service/runtime/tasks?assignee=alice'
~~~

预期：`data` 中有一条 `name=Hello`、`assignee=alice` 的任务。

**完成任务**：

~~~bash
curl -sS -X POST 'http://localhost:8080/service/runtime/tasks/<taskId>' -H 'Content-Type: application/json' -d '{"action":"complete","variables":[{"name":"approved","value":true}]}'
~~~

预期：`204`。使用 `POST /runtime/tasks/{id}` 的 `action` 形式，与 Flowable 客户端一致。

**查询历史**：

~~~bash
curl -sS 'http://localhost:8080/service/history/historic-process-instances/<processInstanceId>'
~~~

预期：`ended=true`、`state=completed`、`durationMillis` 有值；活动历史包含 `start`、`usertask`、`end`。

**常见问题**：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 404 `/service/...` | 路径少了 `/service` 前缀 | 使用 `/service/runtime/...` |
| 启动报流程定义不存在 | 部署失败或 Key 不一致 | 查 `/service/repository/process-definitions` |
| 任务列表为空 | `assignee` 与变量不一致 | 检查 `flowable:assignee` 与启动变量 |
| 服务任务报 `ENGINE-0510` | 委托未注册 | 启动前调用 `RegisterDelegate` |

### 4.3 Go SDK 快速开始

页面结构：创建模块 → 安装依赖 → 最小程序 → 运行 → 解释 → 下一步。

示例流程为 start → serviceTask（委托名 notify）→ userTask（assignee 为 ${initiator}）→ end，完整 BPMN 放在 examples/bpmn/onboarding.bpmn20.xml。示例（已编译运行验证）：

~~~go
package main

import (
	"context"
	"fmt"
	"log"
	"os"

	"github.com/flowable-go/flowable"
	"github.com/flowable-go/flowable/api"
)

func main() {
	ctx := context.Background()
	app, err := flowable.New(flowable.Config{StatePath: "./data/engine.json"})
	if err != nil {
		log.Fatal(err)
	}
	defer app.Close(ctx)

	app.RegisterDelegate("notify", func(ctx context.Context, exec *flowable.Execution) error {
		exec.SetVariable("preparedBy", "system")
		return nil
	})

	xml, err := os.ReadFile("process.bpmn20.xml")
	if err != nil {
		log.Fatal(err)
	}
	if _, err := app.RepositoryService().Deploy(ctx, api.DeploymentRequest{
		Name:      "onboarding",
		Resources: map[string][]byte{"process.bpmn20.xml": xml},
	}); err != nil {
		log.Fatal(err)
	}

	pi, err := app.RuntimeService().StartProcessInstance(ctx, api.StartRequest{
		ProcessDefinitionKey: "onboarding",
		Variables:            []api.Variable{{Name: "initiator", Value: "alice"}},
	})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("started:", pi.ID)

	page, err := app.TaskService().ListTasks(ctx, api.TaskFilter{Assignee: "alice"})
	if err != nil {
		log.Fatal(err)
	}
	if len(page.Data) != 1 {
		log.Fatalf("期望 1 条任务，实际 %d", len(page.Data))
	}
	if err := app.TaskService().Complete(ctx, page.Data[0].ID, api.CompleteTaskRequest{
		UserID:    "alice",
		Variables: []api.Variable{{Name: "approved", Value: true}},
	}); err != nil {
		log.Fatal(err)
	}

	hist, err := app.HistoryService().GetHistoricProcessInstance(ctx, pi.ID)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("ended:", hist.Ended, "state:", hist.State)
}
~~~

运行：`go run .`，预期输出 `started: ...` 与 `ended: true state: completed`。

必须在页面中写明的 SDK 事实：

1. **委托与监听器是进程内注册**：引擎重启后需要重新调用 `RegisterDelegate`，否则服务任务会报 `ENGINE-0510`。
2. **状态文件可恢复**：`StatePath` 指向的文件保存流程定义、实例、任务与历史；重开引擎后可继续查询与操作。
3. **外部模块的持久化配置有限**：`flowable.Config` 目前引用内部包类型（行仓储、状态存储），仓库外模块只能使用内存或 `StatePath` 文件；MySQL/PostgreSQL 需使用服务端模式。该限制应作为已知问题跟踪。
4. **不承诺 API 稳定性**：当前为原型阶段，接口可能在版本间调整。

5. **为什么这样工作**：部署生成定义版本；启动创建执行树；用户任务挂起等待；完成推进到结束；审计级别写历史。
6. **验证清单**：实例 `ended=true`；历史活动三条；变量 `approved=true`。
7. **排错**：端口、路径、Key、assignee、委托未注册。
8. **下一步**：服务任务、网关、表单。

### 6.2 重点页面要点

**引擎配置**：

- 表格列出 `HistoryLevel`、`Clock`、`IDs`、`MaxAgendaSteps`、`TenantID`、`StatePath`、`StateStore`、`RowRepository`、`LoadRows`、`LoadTenant`、`RecordSequenceFlowHistory`。
- 明确哪些字段对仓库外模块可用（`StatePath` 可用；引用内部包类型的字段不可用）。
- 给出内存、文件、服务端数据库三种组合。

**委托与监听器**：

- 注册示例、执行上下文、变量读写、错误传播。
- 生命周期：进程内注册、重启需重新注册、同名覆盖规则。
- 与 Java `JavaDelegate` / `TaskListener` 的差异：需改写为 Go 函数，无类加载。

**表达式与变量**：

- 支持的类型与 UEL 子集；方法白名单；不支持 Groovy/Starlark。
- 变量作用域：实例、执行、任务局部、瞬态。
- 常见错误与排查。

**持久化**：

- 文件快照：单进程、全量写、适合开发与小规模。
- SQL 快照：`-storage mysql`，单执行者独占。
- 行仓储：`-storage mysql-rows`，行级写入、任务查询下推、单执行者。
- 明确：无集群租约、无故障转移、无多写者。

### 6.3 生成方式

- 使用 `gomarkdoc` 或等价工具，仅生成公开包：`github.com/flowable-go/flowable`、`/api`、`/bpmn/model`。
- 排除 `internal/`、`cmd/`、`tools/`。
- 生成结果按包分页，符号按类型/函数分组；注释已为中文，直接复用。
- 每个服务接口页顶部加「实现状态」徽标，链接兼容矩阵。
- 生成失败条件：公开符号缺中文注释、注释缺少 `@param/@return`（与 `make doccheck` 对齐）。

### 6.5 必须在 SDK 文档中公开的限制

1. MySQL/PostgreSQL 无法从仓库外配置（`Config` 字段引用内部类型）。
2. 委托/监听器不支持跨进程加载；重启后需重新注册。
3. 单执行者；无集群抢占、租约、故障转移。
4. 脚本仅表达式子集，不支持 Groovy/Starlark。
5. `serializable` 变量不支持，需迁移为 JSON/字节。
6. API 尚未承诺 semver 稳定性。
7. 异步历史、外部工作项、升级事件未实现。

## 7. REST 参考

### 7.1 组织方式

按业务域分页，每页包含：

1. 域说明与典型流程。
2. 方法表：方法、路径、用途、请求体、响应、状态码。
3. 通用参数：分页、排序、租户、变量过滤。
4. 示例：curl + JSON 响应。
5. 错误：该域常见错误码。
6. 兼容性：官方路径、实现路径、差异。

### 7.2 约定页

- Base path：`/service`。
- 内容类型：`application/json`；部署资源支持 XML/ZIP。
- 日期：RFC 3339。
- 分页：`start`、`size`；响应 `data`、`total`、`start`、`size`。
- 错误：`{"code":"ENGINE-xxxx","message":"..."}`。
- 空响应：删除/完成类返回 `204`。
- 认证：Basic、Bearer、JWT；租户头/参数。
- 已知差异：`variables-async` 为同步实现。

### 7.3 OpenAPI 浏览器

- 生成 `openapi.json`，合并官方 184 个方法与 58 个扩展方法（含 6 个同步实现的 variables-async）。
- 使用 Scalar 或等价只读渲染器，按 tag 分组。
- 每个操作显示「实现状态：已编码 / 待 Java 行为验收」。

## 9. 写作规范

### 9.1 Frontmatter

~~~yaml
---
title: Hello World
description: 10 分钟完成部署、启动、任务与历史查询
order: 10
section: how-to
status: verified        # verified | prototype | planned
since: v0.1.0
verifiedCommit: a8866c0
verifiedAt: 2026-10-29
tags: [bpmn, rest, sdk]
---
~~~

- `status` 三档：`verified`（当前提交可复现）、`prototype`（可用但有限制）、`planned`（未实现）。
- `verifiedCommit` 为短哈希；每次发布前批量更新。
- `description` 用于搜索结果与 OG 描述，不超过 80 字。

### 9.2 代码片段

1. 必须完整可运行，省略部分用注释明确标出，不用 `...` 糊弄。
2. 标注文件名或语言；命令使用 `bash`，响应使用 `json`。
3. 命令与输出分开；输出只保留关键字段，并注明「已截断」。
4. 变量占位符使用 `<taskId>` 这类尖括号，并在前后文说明来源。
5. Go 片段遵循 `gofmt`；错误必须处理，不用 `_` 忽略。
6. 不在文档中写真实密码、Token、数据库连接串。
7. 每段代码注明验证方式（CI 脚本或手动命令）。

### 9.3 状态与措辞

| 允许 | 禁止 |
| --- | --- |
| 「路由已编码，行为兼容待验收」 | 「完全兼容 Flowable」 |
| 「原型可用，生产待验收」 | 「生产可用」无证据 |
| 「单执行者」 | 「支持集群」 |
| 「部分支持：同步实现」 | 「已实现异步」 |
| 「当前提交验证通过」 | 「长期稳定」 |

所有能力声明必须附链接：能力矩阵、对应实施文档或测试命令。
