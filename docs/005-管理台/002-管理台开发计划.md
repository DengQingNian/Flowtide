# 002 管理台开发计划

> 文档编号：005-002
> 更新日期：2026-10-30
> 版本：v1.1（本期不实现权限控制）
> 状态：待评审
> 需求依据：[001 管理台需求清单](001-管理台需求清单.md)

## 1. 目标与原则

在不引入 JVM、Node 运行时依赖的前提下，把管理台作为静态资源嵌入 `flowtide-server`，通过 `/adminpage/#/` 提供运维、建模与排障能力。

实施原则：

1. **界面是 REST 的客户端**：不新增业务逻辑，所有校验与权限以服务端为准；前端只做展示与交互。
2. **嵌入不侵入引擎**：静态资源与 `internal/rest` 解耦，用一个独立 handler 挂载，删除该目录不影响引擎编译。
3. **先读后写**：每个模块先交付列表/详情，再补写操作，避免半成品入口。
4. **同域同源**：不使用跨域、代理或独立端口；浏览器直接访问同源 `/service`。
5. **可测优先**：API 客户端与纯函数先写测试；页面用组件测试覆盖主要交互；关键路径补 e2e。
6. **风格统一**：复用文档站的 Notion 令牌与 Naive UI 覆盖配置，不另起设计系统。
7. **本期不做权限控制**：不实现登录、会话、角色菜单、403 页与租户切换；服务端认证与 RBAC 保持原样，界面按 401/403 原样提示。

## 3. 总体架构

```
浏览器
  │  GET /adminpage/#/...            （静态资源，同源）
  │  GET/POST /service/...           （JSON，不额外注入认证头）
  ▼
flowtide-server（单二进制）
  ├── /adminpage/  → internal/rest/adminpage（go:embed 的 SPA）
  └── /service/    → 既有引擎 REST（认证、RBAC、租户、审计、指标）
```

- 前端不持有业务状态，页面数据全部来自 REST；路由参数即查询条件。
- 静态资源与 API 同源，无需 CORS；认证中间件只作用于 `/service/`，静态资源公开可读（不含敏感数据）。
- 服务端不新增模板渲染，不做 SSR。
- 管理台不读取、不保存凭据；浏览器是否携带认证信息由部署方式决定（服务端未启用认证，或前置代理注入请求头）。

## 5. 构建与嵌入

### 5.1 Vite 配置

| 配置 | 值 | 说明 |
| --- | --- | --- |
| `base` | `/adminpage/` | 资源前缀与路由前缀一致 |
| `build.outDir` | `dist` | 先产出到 `admin/dist` |
| `build.target` | `es2022` | 与文档站一致 |
| `build.sourcemap` | `false` | 生产不暴露源码 |
| `manualChunks` | `naive`、`bpmn` | 设计器拆包，首屏不加载 bpmn-js |
| `server.port` | 5174 | 开发时通过代理访问 8080 |

开发期 `vite.config.ts` 增加 `/service` 代理到 `http://localhost:8080`，保证 `npm run dev` 可直接联调。

### 5.2 产物复制

```make
admin-build:
	cd admin && npm ci && npm run build
	rm -rf internal/rest/adminpage/dist
	mkdir -p internal/rest/adminpage/dist
	cp -R admin/dist/. internal/rest/adminpage/dist/
	touch internal/rest/adminpage/dist/.keep
```

- `internal/rest/adminpage/dist/.keep` 入库；其余产物由 `.gitignore` 忽略：

```gitignore
internal/rest/adminpage/dist/*
!internal/rest/adminpage/dist/.keep
```

- 干净仓库直接 `go build` 可编译（只有 `.keep`），此时访问 `/adminpage/` 返回"未构建管理台"的占位页。
- `make build` 依赖 `admin-build`，保证正式产物带界面。

### 5.3 Go 侧挂载

```go
//go:embed all:dist
var assets embed.FS
```

`adminpage.go` 提供 `newAdminPage(fsys fs.FS) http.Handler`，测试注入 `fstest.MapFS`：

| 请求 | 行为 | 响应头 |
| --- | --- | --- |
| `GET /adminpage/` | 返回 `index.html` | `Cache-Control: no-store` |
| `GET /adminpage/assets/*` | 返回指纹资源 | `Cache-Control: public, max-age=31536000, immutable` |
| `GET /adminpage/<无扩展名路径>` | 回退 `index.html` | `no-store` |
| `GET /adminpage/<缺失资源>` | 404 占位页 | `no-store` |
| `GET /adminpage` | 301 到 `/adminpage/` | ServeMux 自动处理 |

统一响应头：

- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: same-origin`
- `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`

路由注册：

```go
s.mux.Handle("GET /adminpage/", newAdminPage(adminAssets))
s.mux.HandleFunc("GET /{$}", redirectToAdminPage)
```

### 5.4 版本注入

构建期通过 Vite `define` 注入：

- `__ADMIN_VERSION__`：`admin/package.json` 版本；
- `__COMMIT__`：`git rev-parse --short HEAD`；

"关于"页展示；Go 侧不读取，避免跨构建耦合。

## 7. 前端架构

### 7.1 入口与路由

- `createWebHashHistory()`，不依赖服务端重写。
- 路由表用 `meta` 标注标题、导航分组；不设置权限守卫。
- 404 路由显示站内提示与"回仪表盘"。
- 页面组件全部懒加载，设计器单独 chunk。

### 7.2 API 客户端约定

```ts
// request 发送同源请求并解析 Flowtide 错误体
// @param path /service 开头的路径
// @param init fetch 选项
// @return 解析后的 JSON 或空
```

- 不注入 `Authorization`、不注入 `X-Tenant-Id`；需要认证时由浏览器或前置代理提供。
- 错误体：`{code?, message, exception?}`，统一抛出 `ApiError(status, code, message, exception)`。
- 分页响应：`{data,total,start,size,sort,order}`；默认 `size=10`，最大 1000，管理台统一默认 50。
- 查询端点：`POST /service/query/*` 请求体为扁平过滤字段 + `start/size/sort/order`。
- 超时：默认 20s；设计器保存/部署 60s；**不自动重试写操作**。
- 取消：页面卸载时通过 `AbortController` 取消未完成请求。

### 7.3 状态

- `stores/ui`：侧栏折叠、主题、全局加载、服务可用性横幅。
- 页面状态留在组件内，跨页共享仅限筛选条件（写入 URL query）。
- 不保存用户身份、会话、租户；刷新后完全依赖服务端状态。

### 7.5 列表页规范

- 统一结构：`PageHeader` + `FilterBar` + `DataTable` + 分页。
- 查询条件写进 URL query（hash 内），刷新可还原。
- 列宽固定关键列，长文本省略 + tooltip；时间统一 `YYYY-MM-DD HH:mm:ss`。
- 状态列使用 `StatusTag`；空值显示 `—`。
- 行操作不超过 3 个直接按钮，其余收进"更多"。
- 危险操作红色文本按钮，必须二次确认并展示影响范围。

### 7.6 变量与 JSON

- 变量值按类型渲染：字符串原样、数字/布尔/日期只读展示、JSON 可展开、二进制提示"不可读，可下载"。
- 编辑时先校验 JSON 语法，再提交 `{name,type,value}`。
- 大值（>64KB）默认折叠，避免表格卡顿。

### 7.7 错误与空态

- 401：页面顶部常驻提示 + 重试；说明可能原因（服务端启用认证、代理未注入凭据），不清空页面、不跳转。
- 403：展示服务端 `message`，说明当前账号无该操作权限，页面保留。
- 404：资源不存在说明，提供返回列表。
- 5xx：展示 `message` 与可复制的 `exception`，提供重试。
- 网络错误：提示检查服务状态，不自动轮询。

## 8. BPMN 设计器

### 8.1 集成方式

- `bpmn-js/lib/Modeler` + `bpmn-js-properties-panel` + `@bpmn-io/properties-panel`。
- 样式按顺序引入：`diagram-js.css`、`bpmn-js.css`、`bpmn-font`、属性面板样式；字体随包，不引 CDN。
- 设计器组件只在进入 `/repository/models/:id/design` 时加载。

### 8.2 数据流

```
GET /service/repository/models/{id}            → 元信息
GET /service/repository/models/{id}/source     → XML（application/octet-stream）
        ↓ importXML
Modeler（画布 + 属性面板 + 校验）
        ↓ saveXML
PUT /service/repository/models/{id}/source     → multipart 文件字段（任意字段名）
POST /service/repository/models/{id}/deployment → 生成部署与定义
```

- 保存使用 `FormData`，字段名 `file`，文件名 `{key}.bpmn20.xml`。
- 新建模型：先 `POST /models` 得到 ID，再用 `bpmn-moddle` 生成带开始事件的最小 BPMN 写入 `source`，然后进入设计器。
- 从本地导入：`FileReader` 读取后 `importXML`，成功才替换画布；失败保留原图。
- 部署前若 `dirty`，先保存再部署，避免部署旧版本。

### 8.3 校验

- 导入：捕获 `bpmn-moddle` 警告与错误，按元素 ID 列出，可点击定位。
- 保存前：至少一个开始事件、流程 ID 与模型 Key 一致、无悬空连线。
- 部署：把服务端返回的 `code/message` 原样展示，并保留最后一次成功保存的 XML 供回退。
- 自动保存：不做；改为离开页面前提示未保存。

### 8.4 中文化与只读查看

- palette 与属性面板常用标签使用固定术语表（如 Start Event → 开始事件，User Task → 用户任务），BPMN 元素类型名保留英文。
- 只读查看器复用 `bpmn-js/lib/NavigatedViewer`，导入定义 XML，按活动 ID 添加 `highlight` 与 `marker`（完成/当前）。
- 实例详情的图例：已完成（灰）、当前（蓝）、异常（红）；无 DI 时不渲染空画布，提示"该定义缺少 BPMN DI 信息"。

### 8.5 性能与稳定性

- 设计器 chunk 懒加载；XML > 5MB 时提示并拒绝导入。
- 撤销栈限制 100 步；关闭页面前释放 `Modeler#destroy`。
- CSS 作用域限制在容器内，避免污染 Naive UI 弹层。

## 10. 认证与权限（本期不做）

| 场景 | 本期行为 | 后续版本 |
| --- | --- | --- |
| 服务端未启用认证 | 直接使用全部功能 | 不变 |
| 服务端启用 Basic/JWT/mTLS | 页面可打开，数据请求 401，顶部说明原因 | 登录页、令牌管理、登出 |
| RBAC 拒绝 | 展示服务端 `message`，页面保留 | 按权限隐藏菜单与操作 |
| 固定租户绑定 | 使用服务端默认租户 | 租户切换与越权提示 |
| 审计追溯 | 依赖服务端既有审计 | 界面按主体筛选 |

实现约束：

- 不新增 `/service/adminpage/session` 等会话端点，不增加 REST 端点数量。
- 不向 `sessionStorage`/`localStorage` 写入任何凭据；不解析 JWT。
- 不提供"模拟登录"或"跳过认证"的开关，避免误用。

| e2e | 建模型 → 保存 → 部署 → 启动 → 办理 → 历史 → 死信重试 | Playwright | 关键闭环 |
| Go | `adminpage` handler | `go test` | 缓存头、安全头、回退、404、遍历防护 |

覆盖率：

- `vitest.config.ts` 设置 `lines: 90`、`functions: 85`、`branches: 80`；
- 排除项仅限 `src/main.ts`、`src/router/index.ts`、`src/design/*.ts` 中的 bpmn-js 适配薄层，排除清单需评审并在文档登记；
- Go 侧不降低现有 0.90 门禁。

e2e 环境：

- `make admin-e2e` 先构建服务端，使用临时状态文件与开放认证启动，再用 REST 播种数据；
- 浏览器缺失时跳过并给出安装提示，不让 `make check` 依赖网络。

## 13. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 无认证暴露 | 能访问端口即可改数据 | 默认仅内网/回环；README 与启动日志提示；公网必须前置网关；权限控制在下一版本补齐 |
| 服务端启用认证后界面不可用 | 运维误判为故障 | 401 常驻说明与排查步骤；文档写明前置代理方案 |
| bpmn-js 包体大、样式冲突 | 首屏变慢、弹层错位 | 独立 chunk 懒加载；CSS 限定容器；构建后检查体积 |
| 模型保存无乐观锁 | 多人覆盖 | 保存前比对 `lastUpdateTime`，不一致时提示强制覆盖（Q2） |
| 列表接口为全量内存分页 | 大历史数据慢 | 强制筛选、默认 50 条、最大 1000；文档标注 |
| 表数据含敏感值 | 数据外泄 | 只读、默认不导出、部署内网；后续随权限控制收紧 |
| 端点行为与 Java 存在差异 | 界面报错 | 以契约测试与真实调用为准，错误原样展示 |
| 嵌入产物与源码不一致 | 发布旧界面 | `make build` 强制重建；index 不缓存；版本号显示 |
| 前端覆盖率难达 0.90 | 门禁阻塞 | 纯逻辑抽到 `lib/api`；页面用组件测试；排除薄适配层需评审 |
