## 1. 文档目的

本文是整个重构计划的入口文档，回答四个问题：

1. **为什么做**：把 Java 版 Flowable 工作流引擎重构为纯 Go 实现的动机与收益。
2. **做到什么程度**：功能边界、兼容性等级与阶段性目标。
3. **怎么衡量成功**：可量化、可验收的指标。
4. **后续怎么读**：其余 13 份子文档的导航关系。

本计划面向研发、测试、架构与运维团队，既是立项材料，也是后续迭代的基线。任何范围变更必须回到本文更新"范围矩阵"与"成功标准"，并在 014 文档登记决策记录。

2026-10-28 后续实施新增既有 Java 数据库只读预检阶段：在一致性只读事务中扫描 MySQL/PostgreSQL 的 `ACT_*` 表，输出存量实体和迁移阻断报告。该阶段不转换或写回数据，不使 Java 存量续跑与回退状态自动通过，具体边界见 [053 实施说明](../002-迁移实施/053-既有Java数据库只读预检.md) 与 ADR-016。

- Flowable 的**复杂度中心**在 BPMN 执行语义（行为类 + 命令 + 解析器），而不是 CRUD。

- REST 契约已有官方 OpenAPI，可据此做契约测试与代码生成，降低"接口漂移"风险。
- 现有 1,725 个 BPMN 测试流程是宝贵的兼容性语料，应尽可能移植为 Go 的黄金用例。

## 3. 项目目标

### 3.1 总目标

在**不依赖 JVM、不依赖 CGO** 的前提下，用 Go 重新实现一个与 Flowable 8.x 在数据、语义、接口三个层面高度兼容的 BPMN 2.0 工作流引擎，并提供可嵌入的 Go SDK、独立服务端、REST API、运维工具与完整测试体系。

### 3.2 分目标

| 编号 | 目标 | 验收口径 |
| --- | --- | --- |
| G1 | 纯 Go | `CGO_ENABLED=0` 可编译；运行时不加载任何 JVM/本地库 |
| G2 | BPMN 语义兼容 | 006 文档元素矩阵 100% 实现；移植用例通过率 ≥ 90% |
| G3 | 数据库兼容 | 可直接读写 Flowable 8.x 的 `ACT_*` 表；PostgreSQL/MySQL 全量回归 |
| G4 | REST 兼容 | 流程引擎 119 个端点全部实现；响应结构与官方 OpenAPI 一致 |
| G5 | 双形态交付 | 既可作为 library 嵌入，也可作为独立 server 部署 |
| G6 | 可运维 | 指标、追踪、日志、健康检查、优雅停机、集群作业执行 |
| G7 | 工程质量 | 行覆盖率 ≥ 0.90；race/vet/staticcheck/govulncheck 全绿 |
| G8 | 可扩展 | 委托、监听器、表达式函数、变量类型、作业处理器均可注册扩展 |

### 3.3 非目标（本计划明确不做）

- **不追求 Java 类级二方库兼容**：`org.flowable.engine.delegate.JavaDelegate` 等 Java 类无法在 Go 中加载。对应能力以 Go 接口 + 注册表提供，迁移时需改写委托代码。
- **不实现 Spring Boot Starter、CDI、OSGi、JMX**：以 Go 的配置、依赖注入与 `/metrics`、`/healthz` 等等价能力替代。
- **不实现 Flowable Design / Modeler 前端**：只提供模型解析、导出与 REST 能力。
- **不保证 Java 原生序列化对象可读**：`serializable` 类型变量在跨语言场景下需迁移为 JSON/字节；详见 007 文档。
- **不在首期支持全部 8 种数据库**：P0 为 PostgreSQL 16 与 MySQL 8.0；其余按阶段推进。

## 4. 重构原则

1. **语义优先于形似**：Go 代码不必逐行翻译 Java，但令牌推进、作用域、事务、历史写入时机必须一致。
2. **数据库是唯一事实源**：进程内缓存可丢，重启后必须能从 `ACT_*` 表恢复全部状态。
3. **一条命令一个事务**：所有状态变更经由 Command 进入，事务边界清晰，禁止在行为层直接提交。
4. **显式优于隐式**：不使用重量级 ORM；SQL、字段映射、刷新顺序均显式可查。
5. **兼容层与内核解耦**：Flowable Schema/REST 兼容逻辑集中在 adapter 层，内核使用自己的领域模型。
6. **小步可验证**：每个里程碑都有可运行的端到端切片，不做"最后一次性集成"。
7. **可测性设计**：时钟、ID 生成器、随机源、事件总线、数据库连接全部可注入。
8. **无全局可变状态**：引擎实例可多开；禁止包级单例保存租户/事务上下文。
9. **扩展点先于功能**：新增行为优先通过注册表接入，避免修改调度内核。
10. **文档即契约**：元素矩阵、REST 契约、错误码、表结构变更必须先改文档再改代码。

## 5. 范围界定

### 5.1 四层兼容性定义

| 等级 | 名称 | 含义 | 验收方式 |
| --- | --- | --- | --- |
| L1 | 数据兼容 | 表名、列名、类型、语义与 Flowable 8.x 一致，可指向同一数据库 | Schema 对比 + 双写读回测试 |
| L2 | 语义兼容 | 同一 BPMN 文件、同一操作序列产生相同的执行路径与历史记录 | 黄金路径用例 + 历史快照对比 |
| L3 | 接口兼容 | Go SDK 能力覆盖 Java Service API；REST 路径/参数/响应兼容 | API 对照表 + OpenAPI 契约测试 |
| L4 | 表现兼容 | 错误码、分页、日期格式、变量 JSON 表达一致 | 契约测试 + 抓包回归 |

本期目标：**L1、L2 完整达成；L3 覆盖 BPMN 引擎与核心 IDM；L4 覆盖流程 REST 119 个端点**。CMMN/DMN/Form/App 在二期达到 L2/L3。

## 7. 成功标准与量化指标

### 7.1 功能指标

- BPMN 元素矩阵（006 文档）实现率 **100%**。
- 从 Flowable 移植的 BPMN 用例通过率 **≥ 90%**；未通过项必须有书面差异说明。
- 流程 REST 端点实现率 **100%**（119/119），契约测试通过率 100%。
- 数据兼容：使用 Flowable 8.x 初始化的数据库，Go 引擎可直接启动并读取既有流程定义与运行实例。

### 7.2 性能指标（4 核 8G、PostgreSQL 16、SSD）

| 场景 | 目标 |
| --- | --- |
| 启动 1,000 个流程实例（含 2 个用户任务） | p95 ≤ 80 ms/实例 |
| 完成任务并推进到下一节点 | p95 ≤ 40 ms |
| 查询待办任务（10 万条数据） | p95 ≤ 30 ms |
| 历史流程实例分页查询（100 万条） | p95 ≤ 200 ms |
| 单节点持续吞吐 | ≥ 200 实例/秒 |
| 空闲内存占用 | ≤ 150 MB |

### 7.3 质量指标

- 行覆盖率 **≥ 0.90**（排除生成代码与 `cmd/` 入口，口径见 012 文档）。
- `go test -race`、`go vet`、`staticcheck`、`govulncheck` 零告警。
- 关键路径无 goroutine 泄漏、无连接泄漏。
- 所有导出符号具备中文注释与 `@param/@return` 标注。

### 7.4 运维指标

- 启动时间（空库建表）≤ 3 秒；已有库 ≤ 1 秒。
- 支持优雅停机：停止接收新命令，等待在途作业 ≤ 30 秒。
- 指标覆盖：命令耗时、作业执行、定时器延迟、连接池、缓存命中率、错误率。

## 8. 关键决策摘要

| 编号 | 决策 | 结论 | 备选与理由 |
| --- | --- | --- | --- |
| ADR-001 | 数据库 Schema | 复用 `ACT_*`，不新建表前缀 | 便于迁移与工具复用；新表仅限内部锁/指标 |
| ADR-002 | 持久化 | `database/sql` + 动态 SQL 构造器，不用 ORM | 可控、可测、贴近 Flowable 查询语义 |
| ADR-003 | 表达式 | 自研 UEL 兼容子集 | 三方库语义差异大，长期维护成本更高 |
| ADR-004 | 脚本 | 内嵌 goja（JS）、Starlark；Groovy 不支持 | 纯 Go、可沙箱、可超时 |
| ADR-005 | 执行模型 | 移植 Command + Agenda + 执行树 | 与 Flowable 语义最接近，降低行为偏差 |
| ADR-006 | 并发 | 一命令一事务一 goroutine；作业多 worker | 简单、可预测，避免细粒度锁 |
| ADR-007 | 主数据库 | PostgreSQL 16 / MySQL 8.0 | 云原生主流；其余按需扩展 |
| ADR-008 | 缓存 | 进程内 LRU + 版本戳；集群可选 Redis 广播 | 先保证正确性，再优化跨节点失效 |
| ADR-009 | 公共 API | 服务接口 + 泛型查询构造器 | Go 惯用、可发现性好 |
| ADR-010 | 兼容测试 | 移植 Flowable 用例 + OpenAPI 契约 | 以事实标准驱动，不靠主观判断 |

完整决策记录见 014 文档。

## 9. 术语表

| 术语 | 含义 |
| --- | --- |
| PVM | Process Virtual Machine，流程虚拟机，负责令牌推进与作用域 |
| Agenda | 操作队列，命令执行期间按序处理 Continue/TakeOutgoing/End 等操作 |
| Execution | 执行实例，构成树形结构，代表令牌与作用域 |
| Command | 命令，所有引擎操作的统一入口，绑定事务与上下文 |
| UoW | Unit of Work，工作单元，聚合本事务内的增删改 |
| 作业（Job） | 异步任务或定时器，持久化在 `ACT_RU_JOB`/`ACT_RU_TIMER_JOB` |
| 死信（Dead Letter） | 重试耗尽的作业，进入 `ACT_RU_DEADLETTER_JOB` |
| 历史级别 | none/instance/task/activity/audit/full，决定历史写入粒度 |
| 租户 | 多租户隔离标识，落在 `TENANT_ID_` 列 |
| 黄金用例 | 输入 BPMN + 操作序列 + 期望执行路径/历史快照的测试基线 |
