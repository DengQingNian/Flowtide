# 009 作业、定时器与异步执行

> 文档编号：009  
> 依赖：002 架构、004 数据模型、006 执行引擎  
> 目标读者：后端开发、运维、SRE

## 1. 作业体系总览

Flowable 把"不能或不应在当前请求内完成的工作"持久化为作业（Job），由后台执行器推进。作业既是**异步续跑机制**，也是**定时器机制**和**失败重试机制**。

| 作业类型 | 表 | 用途 |
| --- | --- | --- |
| 异步作业 | `ACT_RU_JOB` | asyncBefore/asyncAfter 的流程续跑 |
| 定时器作业 | `ACT_RU_TIMER_JOB` | 边界定时器、中间定时捕获、定时启动 |
| 挂起作业 | `ACT_RU_SUSPENDED_JOB` | 流程/定义挂起时暂存 |
| 死信作业 | `ACT_RU_DEADLETTER_JOB` | 重试耗尽 |
| 历史作业 | `ACT_RU_HISTORY_JOB` | 异步写历史 |
| 外部作业 | `ACT_RU_EXTERNAL_JOB` | 外部工作项（External Worker） |

~~~mermaid
flowchart LR
    NEW[创建作业] --> RUN[ACT_RU_JOB]
    RUN -->|到期| ACQ[被节点抢占]
    ACQ -->|成功| DONE[删除]
    ACQ -->|失败且可重试| WAIT[等待重试]
    WAIT --> RUN
    ACQ -->|重试耗尽| DL[ACT_RU_DEADLETTER_JOB]
    RUN -->|实例挂起| SUS[ACT_RU_SUSPENDED_JOB]
    SUS -->|恢复| RUN
    TIMER[ACT_RU_TIMER_JOB] -->|到期| RUN
~~~

## 2. 作业实体

~~~go
// JobEntity 对应 ACT_RU_JOB / ACT_RU_TIMER_JOB。
type JobEntity struct {
    ID                string
    Revision          int
    Type              string    // 消息/定时器类型
    HandlerType       string    // 处理器类型，决定执行逻辑
    HandlerConfig     string    // 处理器参数（JSON）
    ExecutionID       string
    ProcessInstanceID string
    ProcessDefinitionID string
    ElementID         string
    ElementName       string
    Retries           int
    ExceptionMessage  string
    ExceptionStackID  string    // 指向 ACT_GE_BYTEARRAY
    DueDate           *time.Time
    Repeat            string    // ISO-8601 重复表达式
    LockOwner         string
    LockExpiration    *time.Time
    Exclusive         bool
    CreateTime        time.Time
    TenantID          string
}
~~~

不变量：

- `RETRIES_` 初始为配置值（默认 3），失败递减；为 0 时进入死信。
- 同一执行上的独占作业不得并发执行。
- `LOCK_OWNER_` 与 `LOCK_EXP_TIME_` 必须同时为空或同时有值。
- `DUEDATE_` 为空表示立即可执行（异步作业）。
- 定时器作业的 `REPEAT_` 为空表示只触发一次。

## 3. 异步执行器

### 3.1 组件

~~~mermaid
flowchart TB
    subgraph node[节点]
        A[AcquireAsyncJobsRunnable] --> Q[本地队列]
        Q --> W1[Worker 1]
        Q --> W2[Worker N]
        W1 --> H[JobHandler]
        W2 --> H
        T[AcquireTimerJobsRunnable] --> Q
        R[ResetExpiredJobsRunnable] --> Q
        M[Metrics]
    end
    A --> DB[(ACT_RU_JOB)]
    T --> DB2[(ACT_RU_TIMER_JOB)]
    R --> DB
~~~

| 组件 | 职责 | 默认 |
| --- | --- | --- |
| `AcquireAsyncJobsRunnable` | 周期性批量抢占异步作业 | 5s |
| `AcquireTimerJobsRunnable` | 周期性批量抢占到期定时器 | 10s |
| `ResetExpiredJobsRunnable` | 回收锁过期的作业 | 5m |
| Worker Pool | 执行作业 | CPU × 2，可配置 |
| `JobAddedNotification` | 本节点新作业立即唤醒（减少延迟） | 开启 |

### 3.2 抢占算法

PostgreSQL / MySQL 8：

~~~sql
SELECT ID_, ... FROM ACT_RU_JOB
WHERE (LOCK_OWNER_ IS NULL OR LOCK_EXP_TIME_ < ?)
  AND (DUEDATE_ IS NULL OR DUEDATE_ <= ?)
ORDER BY DUEDATE_ ASC, ID_ ASC
LIMIT ?
FOR UPDATE SKIP LOCKED;
~~~

随后批量更新：

~~~sql
UPDATE ACT_RU_JOB
SET LOCK_OWNER_ = ?, LOCK_EXP_TIME_ = ?, REV_ = REV_ + 1
WHERE ID_ IN (...) AND (LOCK_OWNER_ IS NULL OR LOCK_EXP_TIME_ < ?);
~~~

回退方案（不支持 `SKIP LOCKED` 的数据库）：

~~~sql
UPDATE ACT_RU_JOB
SET LOCK_OWNER_ = ?, LOCK_EXP_TIME_ = ?
WHERE ID_ IN (
  SELECT ID_ FROM ACT_RU_JOB
  WHERE LOCK_OWNER_ IS NULL AND (DUEDATE_ IS NULL OR DUEDATE_ <= ?)
  ORDER BY DUEDATE_ LIMIT ?
);
~~~

- 抢占必须在短事务内完成，避免长事务阻塞。
- 每个节点有唯一 `lockOwner`（主机名 + 进程 ID + 随机后缀）。
- 锁时长 = 单作业最长执行时间 × 2 + 时钟偏差余量，默认 5 分钟。
- 作业执行期间定期续租（长作业），避免被其他节点回收。

### 3.3 执行流程

~~~go
// ExecuteJob 执行单个作业。
// @param ctx 上下文
// @param job 已抢占的作业
// @return error 执行错误
func (e *Executor) ExecuteJob(ctx context.Context, job *JobEntity) error {
    handler, ok := e.handlers.For(job.HandlerType)
    if !ok {
        return NewEngineError("ENGINE-0901", "未知作业处理器: "+job.HandlerType, nil)
    }
    // 每个作业独立命令与事务
    return e.commands.Execute(ctx, NewExecuteJobCmd(job.ID, handler))
}
~~~

处理器约定：

- 处理器必须幂等；重复投递不能产生重复副作用。
- 处理器内不得直接写作业表，由 JobManager 统一管理状态。
- 处理器返回 `*BusinessError` 时不重试，直接死信并记录原因。
- 处理器 panic 由 RecoveryInterceptor 转为错误，按可重试处理。

### 3.4 重试与死信

| 阶段 | 行为 |
| --- | --- |
| 第 1 次失败 | `RETRIES_ = 2`，`DUEDATE_ = now + retryWait`，记录异常 |
| 第 2 次失败 | `RETRIES_ = 1`，继续退避 |
| 第 3 次失败 | `RETRIES_ = 0`，移入 `ACT_RU_DEADLETTER_JOB` |
| 死信恢复 | 管理 API 设置重试次数并移回 `ACT_RU_JOB` |
| 不可恢复错误 | 直接死信，不消耗重试次数 |

重试周期：

- 默认重试 3 次；未配置 `failedJobRetryTimeCycle` 时，异步作业失败后等待 `asyncFailedJobWaitTime`（默认 10 秒），并临时移入 `ACT_RU_TIMER_JOB`，到期后回到可执行作业。
- 若 BPMN 配置了 `failedJobRetryTimeCycle`（如 `R3/PT10M`），按该周期计算下次到期时间；首次失败时用周期中的次数覆盖默认重试次数。
- 退避可配置为固定、指数、抖动；默认固定以贴近 Flowable。
- 重试等待时间必须可注入时钟，测试中可瞬间推进。

### 3.5 独占作业

- `EXCLUSIVE_=true` 的作业在同一流程实例内串行执行。
- 抢占时跳过"已有独占作业在执行"的流程实例，避免并发修改执行树。
- 非独占作业可并行，但仍需乐观锁保护。
- 同一执行上的多个异步续跑必须按创建顺序执行（FIFO）。

## 4. 定时器

### 4.1 定时器定义

| BPMN 配置 | 语义 |
| --- | --- |
| `timeDuration` | 相对当前时间，如 `PT5M` |
| `timeDate` | 绝对时间，ISO-8601 |
| `timeCycle` | 重复周期，ISO-8601 或 cron |

ISO-8601 重复表达式：

- `R3/PT10M`：重复 3 次，每次间隔 10 分钟。
- `R/PT1H`：无限重复，每小时。
- `R5/2026-01-01T00:00:00Z/PT1D`：从指定时间开始，5 次，每天。

cron：

- 五/六字段（秒 分 时 日 月 周），时区按流程定义或引擎配置。
- 使用 `robfig/cron/v3` 解析，禁止在解析阶段执行。

### 4.2 生命周期

1. 进入带定时器的元素时，计算首次到期时间，写入 `ACT_RU_TIMER_JOB`。
2. 定时器扫描器抢占到期作业，执行 `TimerEventHandler`。
3. 触发业务动作：
   - 边界定时器：触发边界出线（中断/非中断）。
   - 中间捕获：唤醒执行。
   - 定时启动：启动流程实例。
4. 若 `REPEAT_` 仍有剩余，计算下一次到期时间并更新作业；否则删除。
5. 活动结束/中断时，取消对应定时器。

### 4.3 时间计算

~~~go
// NextTimerDate 计算下一次触发时间。
// @param now 当前时间
// @param timer 定时器定义
// @param last 上次触发时间
// @return 下次触发时间
// @return 是否还有下一次
// @return 错误
func NextTimerDate(now time.Time, timer TimerDefinition, last time.Time) (time.Time, bool, error) { /* ... */ }
~~~

规则：

- `timeDate` 已过期：立即触发一次，之后删除。
- `timeDuration`：从进入时间起算，不受扫描延迟影响。
- `timeCycle`：从上次计划触发时间起算，避免漂移；若已错过多个周期，只触发一次并跳到下一个未来时间。
- 时区：cron 使用配置时区；ISO-8601 使用 UTC。
- 夏令时：cron 使用 IANA 时区，重复/跳过时间按库规则处理；文档记录行为。

### 4.4 定时器启动事件

- 部署时创建流程级定时器作业，`PROC_DEF_ID_` 指向定义，`EXECUTION_ID_` 为空。
- 触发时启动新实例；若为重复定时器，重新调度。
- 流程定义挂起时，定时器作业迁入 `ACT_RU_SUSPENDED_JOB`；激活时迁回并重算。

## 5. 异步历史

- 开启 `asyncHistory` 后，历史写入不阻塞主流程，而是创建 `ACT_RU_HISTORY_JOB`。
- 历史作业与业务事务同库，保证最终一致。
- 独立执行器（`asyncHistoryExecutor`）消费，避免与业务作业争抢。
- 顺序：同一流程实例的历史作业按创建顺序执行；跨实例可并行。
- 失败重试策略独立配置；耗尽后进入历史死信（或记录日志）。
- 查询历史时可能短暂滞后；REST 可返回 `X-History-Lag` 提示（可选）。

## 6. 外部工作项（External Worker）

### 6.1 模型

- BPMN 使用 `externalWorkerTask`（或 `serviceTask flowable:type="external-worker"`）。
- 进入时创建 `ACT_RU_EXTERNAL_JOB`，包含 `topic`、`lock`、`retries`、变量。
- 外部系统通过 REST 拉取（acquire）、完成（complete）、失败（fail）。

### 6.2 API

| 端点 | 作用 |
| --- | --- |
| `POST /external-job-api/acquire` | 按 topic 拉取作业，设置锁时长与 workerId |
| `POST /external-job-api/{jobId}/complete` | 完成，写变量 |
| `POST /external-job-api/{jobId}/fail` | 失败，设置重试与错误信息 |
| `POST /external-job-api/{jobId}/extend-lock` | 续租 |
| `POST /external-job-api/{jobId}/unlock` | 主动释放 |

### 6.3 锁与重试

- 锁时长由 worker 指定（默认 5 分钟），到期可被其他 worker 重新拉取。
- 完成时必须校验 `workerId` 与锁未过期，否则返回 409。
- 失败时按 `retries` 递减；为 0 进入死信。
- 外部工作项不占用引擎 worker 线程。

## 7. 批处理

| 表 | 作用 |
| --- | --- |
| `FLW_RU_BATCH` | 批次元数据（类型、状态、总数、创建人） |
| `FLW_RU_BATCH_PART` | 批次分片（每片的作业/结果） |

- 批量删除流程实例、批量迁移、批量改派等使用批处理。
- 批次由 seed job 驱动，分片并行执行；每片独立事务。
- 状态：`in-progress`、`completed`、`failed`、`cancelled`。
- 提供进度查询与取消 API。
- 大批量操作必须限流，避免打满数据库。

## 8. 集群与一致性

~~~mermaid
sequenceDiagram
    participant N1 as 节点 1
    participant N2 as 节点 2
    participant DB as 数据库
    N1->>DB: SELECT ... FOR UPDATE SKIP LOCKED
    DB-->>N1: 返回作业 A
    N2->>DB: SELECT ... FOR UPDATE SKIP LOCKED
    DB-->>N2: 返回作业 B（跳过 A）
    N1->>DB: 执行 A + 提交
    N2->>DB: 执行 B + 提交
~~~

保证：

1. **不重复执行**：同一作业同一时刻只被一个节点持有锁。
2. **至少一次**：节点崩溃后锁过期，作业被其他节点接管；处理器必须幂等。
3. **顺序**：同一执行上的独占作业串行；跨节点通过数据库锁保证。
4. **时钟**：锁过期使用数据库时间或统一 NTP；容忍 ±5 分钟偏差。
5. **脑裂**：数据库是唯一仲裁者，不依赖内存选主。
6. **滚动升级**：新旧节点可同时运行；作业处理器需向后兼容；Schema 变更必须兼容旧版本。

## 10. 可观测性

| 指标 | 类型 | 说明 |
| --- | --- | --- |
| `flowable_job_acquired_total` | Counter | 抢占数量 |
| `flowable_job_executed_total{result}` | Counter | 成功/失败 |
| `flowable_job_duration_seconds` | Histogram | 执行耗时 |
| `flowable_job_retries_total` | Counter | 重试次数 |
| `flowable_job_deadletter_count` | Gauge | 死信数量 |
| `flowable_timer_lag_seconds` | Gauge | 定时器延迟 |
| `flowable_job_queue_depth` | Gauge | 本地队列深度 |
| `flowable_job_lock_expired_total` | Counter | 过期锁回收 |

日志字段：`job_id`、`job_type`、`handler_type`、`process_instance_id`、`attempt`、`duration_ms`、`error_code`。

告警建议：

- 死信数量 > 0 持续 5 分钟。
- 定时器延迟 p99 > 60 秒。
- 作业失败率 > 5%。
- 本地队列深度持续 > 80% 容量。

## 11. 测试策略

| 类型 | 内容 |
| --- | --- |
| 单元 | 到期计算、重试策略、状态迁移 |
| 集成 | 单节点执行异步/定时/外部作业 |
| 集群 | 双节点并发抢占，断言无重复执行 |
| 故障 | 执行中 kill 节点，锁过期后恢复 |
| 时钟 | 假时钟推进，验证定时器与退避 |
| 幂等 | 同一作业重复投递，副作用只发生一次 |
| 性能 | 10 万作业积压下的吞吐与延迟 |

必测场景：

1. asyncBefore 创建作业 → 完成后继续。
2. 作业失败 3 次 → 死信 → 手工恢复 → 成功。
3. 定时器边界中断/非中断。
4. 定时启动重复触发。
5. 流程挂起时作业暂停、恢复后继续。
6. 双节点同时扫描，只有一方执行。
7. 外部工作项 acquire/complete/fail/续租/超时。
8. 异步历史开启后主流程延迟下降、历史最终一致。
9. 批处理 1 万实例删除，进度与失败分片可见。

## 12. 验收清单

- [ ] 六类作业表生命周期正确，无悬挂。
- [ ] 单节点/多节点均不重复执行同一作业。
- [ ] 重试、退避、死信、恢复符合配置。
- [ ] 定时器不漂移，错过周期只触发一次。
- [ ] 独占作业保证同一实例串行。
- [ ] 外部工作项锁与重试安全。
- [ ] 异步历史最终一致，失败可观测。
- [ ] 指标、日志、告警覆盖关键路径。
- [ ] kill -9 后作业可被其他节点接管。
