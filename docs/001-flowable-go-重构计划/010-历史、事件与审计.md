# 010 历史、事件与审计

> 文档编号：010  
> 依赖：004 数据模型、006 执行引擎、009 作业  
> 目标读者：后端开发、审计/合规、运维

## 1. 历史级别

| 级别 | 流程实例 | 活动 | 任务 | 变量 | 明细 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| `none` | 否 | 否 | 否 | 否 | 否 | 最高性能，无历史 |
| `instance` | 是 | 否 | 否 | 否 | 否 | 仅流程实例起止 |
| `task` | 是 | 否 | 是 | 否 | 否 | 实例 + 任务 |
| `activity` | 是 | 是 | 否 | 是（结束时快照） | 否 | 实例 + 活动 + 顶层变量 |
| `audit` | 是 | 是 | 是 | 是（持续同步） | 表单属性 | 默认级别 |
| `full` | 是 | 是 | 是 | 是 | 全部变量变更 | 最完整、最慢 |

> 注意：参考实现中 `activity` 级别对任务历史的判定有特殊分支（`hasTaskHistoryLevel` 只认 `task` 或 ≥ `audit`）。Go 版严格按源码行为实现，并用兼容测试锁定；不要凭直觉认为"activity 包含 task"。

配置：

- 引擎级 `historyLevel`，默认 `audit`。
- 流程定义级历史级别（可选）：通过扩展元素 `includeInHistory` / 定义元数据覆盖引擎级。
- 历史级别可在重启间变更，无需迁移；但降低级别不会删除已有历史。

## 2. 历史表与写入点

| 表 | 写入时机 | 关键字段 |
| --- | --- | --- |
| `ACT_HI_PROCINST` | 实例启动、结束、删除 | `START_TIME_`、`END_TIME_`、`DURATION_`、`DELETE_REASON_`、`START_USER_ID_`、`END_ACT_ID_` |
| `ACT_HI_ACTINST` | 活动进入、离开 | `ACT_ID_`、`ACT_TYPE_`、`START_TIME_`、`END_TIME_`、`DURATION_`、`TRANSACTION_ORDER_` |
| `ACT_HI_TASKINST` | 任务创建、签收、完成、删除 | `ASSIGNEE_`、`OWNER_`、`CLAIM_TIME_`、`END_TIME_`、`DURATION_`、`DELETE_REASON_` |
| `ACT_HI_VARINST` | 变量创建、更新、删除 | `NAME_`、`TYPE_`、`TEXT_`、`LONG_`、`DOUBLE_`、`CREATE_TIME_`、`LAST_UPDATED_TIME_` |
| `ACT_HI_DETAIL` | 变量变更/表单提交 | `TYPE_`、`NAME_`、`VAR_TYPE_`、`TIME_`、`TASK_ID_` |
| `ACT_HI_IDENTITYLINK` | 身份链接创建/删除 | `TYPE_`、`USER_ID_`、`GROUP_ID_`、`TASK_ID_` |
| `ACT_HI_ENTITYLINK` | 实体关联 | `TYPE_`、`SCOPE_ID_`、`REFERENCE_ID_` |
| `ACT_HI_COMMENT` | 评论 | `TYPE_`、`MESSAGE_`、`USER_ID_` |
| `ACT_HI_ATTACHMENT` | 附件 | `NAME_`、`TYPE_`、`URL_`、`CONTENT_ID_` |
| `ACT_HI_TSK_LOG` | 任务操作日志 | `TYPE_`、`TASK_ID_`、`USER_ID_`、`DATA_` |

### 2.1 流程实例历史

- 启动：写 `ACT_HI_PROCINST`，`START_TIME_`、`START_USER_ID_`、`START_ACT_ID_`、`BUSINESS_KEY_`、`TENANT_ID_`。
- 结束：写 `END_TIME_`、`DURATION_`、`END_ACT_ID_`、`DELETE_REASON_`。
- 删除：运行实例删除时，历史保留并写 `DELETE_REASON_`（可配置是否删除历史）。
- 超级流程（调用活动）：写 `SUPER_PROCESS_INSTANCE_ID_`。

### 2.2 活动实例历史

- 进入活动：插入，`TRANSACTION_ORDER_` 递增，用于稳定排序。
- 离开活动：更新 `END_TIME_`、`DURATION_`。
- 边界事件/补偿：记录 `ACT_TYPE_` 与 `TASK_ID_`/`CALL_PROC_INST_ID_`。
- 活动类型：`startEvent`、`userTask`、`serviceTask`、`exclusiveGateway`、`subProcess` 等（与 BPMN 元素类型一致）。
- 历史级别 `activity` 以下不写活动表。

### 2.3 任务历史

- 创建：写任务行，`START_TIME_`。
- 签收：更新 `ASSIGNEE_`、`CLAIM_TIME_`。
- 完成：写 `END_TIME_`、`DURATION_`、`COMPLETED_BY_`。
- 删除：写 `DELETE_REASON_`（如 `MI_END`、`boundary event`、`process instance deletion`）。
- 任务日志（`ACT_HI_TSK_LOG`）记录操作流水，默认关闭。

### 2.4 变量历史

- `audit`：变量每次变更同步到 `ACT_HI_VARINST`，保留最终值。
- `full`：额外写 `ACT_HI_DETAIL`，记录每次赋值（含旧值/新值）。
- `activity`：只在实例结束时复制顶层变量快照。
- 变量删除：写 `DELETE_REASON_` 或直接删除历史行（按配置）。
- 大文本/二进制：历史表存引用，内容在 `ACT_GE_BYTEARRAY`。

### 2.5 明细历史

`ACT_HI_DETAIL` 类型：

| 类型 | 说明 |
| --- | --- |
| `VariableUpdate` | 变量更新（full 级别） |
| `FormProperty` | 表单属性提交 |
| `VariableInitial` | 变量初始赋值 |

字段：`NAME_`、`TYPE_`、`VAR_TYPE_`、`REV_`、`TIME_`、`ACT_INST_ID_`、`TASK_ID_`、`TEXT_`、`LONG_`、`DOUBLE_`。

## 3. 历史查询

~~~go
// HistoricProcessInstanceQuery 查询历史流程实例。
type HistoricProcessInstanceQuery interface {
    // Finished 仅查询已结束实例。
    // @return 查询构造器
    Finished() HistoricProcessInstanceQuery
    // Unfinished 仅查询未结束实例。
    // @return 查询构造器
    Unfinished() HistoricProcessInstanceQuery
    // StartedAfter 按开始时间过滤。
    // @param t 起始时间
    // @return 查询构造器
    StartedAfter(t time.Time) HistoricProcessInstanceQuery
    // IncludeProcessVariables 结果包含变量。
    // @return 查询构造器
    IncludeProcessVariables() HistoricProcessInstanceQuery
    // List 分页查询。
    // @param ctx 上下文
    // @param offset 偏移
    // @param size 数量
    // @return 列表
    // @return 总数
    // @return 错误
    List(ctx context.Context, offset, size int) ([]HistoricProcessInstance, int64, error)
}
~~~

查询规则：

- 历史查询默认只读，使用只读事务或独立连接。
- 大表分页必须带时间范围或流程定义过滤，避免全表扫描。
- `includeVariables` 通过批量查询 `ACT_HI_VARINST` 组装，禁止 N+1。
- 删除历史使用批处理作业，分批提交。
- 时间范围查询使用 `START_TIME_`/`END_TIME_` 索引。

## 4. 异步历史

| 模式 | 事务 | 延迟 | 一致性 |
| --- | --- | --- | --- |
| 同步（默认） | 与业务同事务 | 无 | 强一致 |
| 异步 | 业务提交后独立事务 | 毫秒~秒 | 最终一致 |

- 异步模式下，业务命令只创建 `ACT_RU_HISTORY_JOB`，不直接写 `ACT_HI_*`。
- 历史作业按流程实例顺序执行，保证同一实例的历史顺序。
- 失败重试独立配置；耗尽后记录错误并告警，不阻塞业务。
- 查询接口可能读到滞后数据；提供 `X-History-Lag-Seconds` 响应头（可选）。
- 适用场景：高吞吐、历史表写入成为瓶颈；不适用于强审计要求。

## 5. 事件体系

### 5.1 事件分类

| 类别 | 示例 | 触发点 |
| --- | --- | --- |
| 引擎 | `ENGINE_CREATED`、`ENGINE_CLOSED` | 启动/关闭 |
| 实体 | `ENTITY_CREATED`、`ENTITY_UPDATED`、`ENTITY_DELETED` | 持久化 |
| 流程 | `PROCESS_CREATED`、`PROCESS_COMPLETED`、`PROCESS_CANCELLED` | 实例生命周期 |
| 活动 | `ACTIVITY_STARTED`、`ACTIVITY_COMPLETED`、`ACTIVITY_CANCELLED`、`SEQUENCEFLOW_TAKEN` | 令牌推进 |
| 多实例 | `MULTI_INSTANCE_ACTIVITY_STARTED/COMPLETED/CANCELLED` | 多实例 |
| 任务 | `TASK_CREATED`、`TASK_ASSIGNED`、`TASK_COMPLETED`、`TASK_UPDATED`、`TASK_DELETED`、`TASK_TIMEOUT` | 任务 |
| 变量 | `VARIABLE_CREATED`、`VARIABLE_UPDATED`、`VARIABLE_DELETED` | 变量 |
| 作业 | `TIMER_SCHEDULED`、`TIMER_FIRED`、`JOB_EXECUTION_SUCCESS`、`JOB_EXECUTION_FAILURE`、`JOB_MOVED_TO_DEADLETTER` | 作业 |
| 事件订阅 | `ACTIVITY_MESSAGE_WAITING`、`ACTIVITY_SIGNALED`、`ACTIVITY_ERROR_RECEIVED` | 订阅 |
| 历史 | `HISTORIC_ACTIVITY_INSTANCE_CREATED`、`HISTORIC_ACTIVITY_INSTANCE_ENDED` | 历史写入 |

### 5.2 监听器类型

| 类型 | 事务 | 异常影响 | 用途 |
| --- | --- | --- | --- |
| 同步 | 当前事务 | 回滚 | 校验、审计、派生数据 |
| 事务前 | 当前事务提交前 | 回滚 | 需要与业务原子 |
| 事务后 | 提交后 | 不影响业务 | 通知、消息发送 |
| 异步 | 独立执行 | 不影响业务 | 重活、外部系统 |

~~~go
// EventListener 是引擎事件监听器。
type EventListener interface {
    // OnEvent 处理事件。
    // @param ctx 上下文
    // @param event 事件
    // @return error 处理错误
    OnEvent(ctx context.Context, event Event) error
    // IsFailOnException 返回异常是否中断命令。
    // @return 是否中断
    IsFailOnException() bool
    // IsFireOnTransactionLifecycle 返回是否事务生命周期事件。
    // @return 是否事务事件
    IsFireOnTransactionLifecycle() bool
    // GetOnTransaction 返回事务阶段。
    // @return before-commit/after-commit/after-rollback
    GetOnTransaction() string
}
~~~

### 5.3 事件派发

~~~mermaid
sequenceDiagram
    participant C as Command
    participant D as Dispatcher
    participant S as 同步监听器
    participant T as 事务同步
    participant A as 异步监听器
    C->>D: dispatch(event)
    D->>S: onEvent
    S-->>D: ok/error
    D->>T: 注册 afterCommit
    C->>T: commit
    T->>A: 投递异步事件
~~~

规则：

- 同步监听器按注册顺序执行；任一失败回滚命令。
- 事务后监听器失败只记录日志/指标，不影响已提交事务。
- 异步事件进入内存队列或作业表；进程崩溃可能丢失，需业务幂等（可选持久化）。
- 事件对象不可变，包含 `executionId`、`processInstanceId`、`processDefinitionId`、`tenantId`、`timestamp`。

## 6. 事件注册表（Event Registry）

### 6.1 模型

| 表 | 作用 |
| --- | --- |
| `FLW_EVENT_DEPLOYMENT` | 事件定义部署 |
| `FLW_EVENT_DEFINITION` | 事件定义（名称、key、类型、payload） |
| `FLW_EVENT_RESOURCE` | 部署资源 |
| `FLW_CHANNEL_DEFINITION` | 通道定义（inbound/outbound、类型、配置） |

### 6.2 能力

- **入站**：HTTP Webhook、Kafka、RabbitMQ、NATS（按适配器）；收到事件后按 key 启动流程或触发等待中的执行。
- **出站**：流程中的发送事件任务/事件定义把消息投递到通道。
- **事件负载**：JSON；支持 payload 映射、头部、关联 ID、租户。
- **重试**：出站失败按通道策略重试；入站幂等键去重。

### 6.3 Go 适配器

| 通道 | 库 | 阶段 |
| --- | --- | --- |
| HTTP Webhook | 标准库 | T1 |
| Kafka | `franz-go` | T2 |
| RabbitMQ | `amqp091-go` | T2 |
| NATS | `nats.go` | T3 |

> Java 版的 Camel/JMS 通道不直接移植；以 Go 适配器 + HTTP 回调等价实现，文档给出迁移映射。

## 7. 审计与合规

### 7.1 审计数据

| 数据 | 来源 | 保留 |
| --- | --- | --- |
| 流程轨迹 | `ACT_HI_ACTINST` | 按策略（默认永久） |
| 任务操作 | `ACT_HI_TASKINST` + `ACT_HI_TSK_LOG` | 按策略 |
| 变量变更 | `ACT_HI_VARINST` + `ACT_HI_DETAIL` | 按策略 |
| 评论/附件 | `ACT_HI_COMMENT`/`ACT_HI_ATTACHMENT` | 按策略 |
| 引擎事件 | `ACT_EVT_LOG`（可选） | 短期 |
| 登录/认证 | 应用日志 | 按合规要求 |

### 7.2 敏感数据

- 变量值可能含 PII；提供 `variableMasking` 配置，对指定名称脱敏后写历史。
- 日志禁止打印变量值、密码、Token。
- 附件下载需鉴权；URL 附件不代理内容。
- 数据导出（GDPR）按流程实例 ID 聚合，提供删除接口（物理删除 + 审计记录）。

### 7.3 历史清理

- 默认关闭；开启后按 cron 执行（默认每天 01:00）。
- 保留期默认 365 天；按 `END_TIME_` 删除已结束实例及其关联历史。
- 使用批处理作业分片删除，避免长事务与锁表。
- 删除前校验是否有运行中的调用活动/子流程引用；有则跳过并告警。
- 清理动作写审计日志（批次 ID、删除数量、时间范围）。

## 8. 事件日志（ACT_EVT_LOG）

- 用途：可靠事件投递/外部系统集成，不是完整审计。
- 字段：`TYPE_`、`PROC_DEF_ID_`、`PROC_INST_ID_`、`EXECUTION_ID_`、`TASK_ID_`、`DATA_`、`LOCK_OWNER_`、`LOCK_TIME_`、`IS_PROCESSED_`。
- 写入与业务同事务；后台处理器扫描未处理记录并投递。
- 失败重试；超过阈值标记失败并告警。
- 默认关闭，避免写放大。

## 9. 查询与性能

| 场景 | 策略 |
| --- | --- |
| 流程实例列表 | `PROC_DEF_ID_` + `START_TIME_` 复合索引 |
| 活动轨迹 | 按 `PROC_INST_ID_` 查，按 `TRANSACTION_ORDER_` 排序 |
| 任务历史 | `ASSIGNEE_` + `END_TIME_` 索引 |
| 变量查询 | 按 `PROC_INST_ID_` + `NAME_`；避免 `LIKE '%x%'` |
| 明细查询 | 限定时间范围与任务 ID |
| 大结果集 | 游标分页；禁止深 offset |
| 历史清理 | 分批 + 低峰期 |

## 10. 测试策略

| 类型 | 内容 |
| --- | --- |
| 级别 | 六个级别下各表写入/不写入的断言 |
| 生命周期 | 启动/结束/删除/挂起/迁移的历史 |
| 变量 | create/update/delete、full 明细、快照 |
| 异步 | 开启异步历史后最终一致、失败重试 |
| 事件 | 顺序、事务阶段、异常回滚、异步投递 |
| 事件注册 | 入站启动/触发、出站投递、幂等 |
| 清理 | 保留期、批处理、引用保护 |
| 性能 | 100 万历史行的分页与轨迹查询 |

必测场景：

1. `none/instance/task/activity/audit/full` 各跑同一流程，断言表行数。
2. 流程删除后历史保留，`DELETE_REASON_` 正确。
3. 调用活动子实例结束后父历史轨迹完整。
4. 多实例任务的 `nrOfInstances` 与任务历史。
5. `full` 级别变量更新产生明细。
6. 异步历史积压后恢复，顺序不乱。
7. 事件监听器抛错导致命令回滚。
8. 历史清理不删除运行中实例。
