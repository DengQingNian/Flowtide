## 1. 用户任务生命周期

~~~mermaid
stateDiagram-v2
    [*] --> Created: 进入 UserTask
    Created --> Claimed: claim(user)
    Created --> Delegated: delegate(user)
    Claimed --> Delegated: delegate(user)
    Delegated --> Resolved: resolve()
    Resolved --> Completed: complete()
    Created --> Completed: complete()
    Claimed --> Completed: complete()
    Created --> Suspended: 流程/任务挂起
    Claimed --> Suspended: 流程/任务挂起
    Suspended --> Created: 激活（无签收人）
    Suspended --> Claimed: 激活（有签收人）
    Created --> Deleted: 删除实例/中断
    Claimed --> Deleted: 删除实例/中断
    Completed --> [*]
    Deleted --> [*]
~~~

状态与字段：

| 状态 | `ASSIGNEE_` | `OWNER_` | `DELEGATION_` | 可完成 |
| --- | --- | --- | --- | --- |
| Created | 空 | 空/设置 | 空 | 是（无签收限制时） |
| Claimed | 签收人 | 可能为空 | 空 | 是 |
| Delegated | 被委托人 | 原处理人 | `PENDING` | 否（需 resolve） |
| Resolved | 原处理人 | 原处理人 | `RESOLVED` | 是 |
| Suspended | 原值 | 原值 | 原值 | 否 |
| Completed/Deleted | — | — | — | — |

## 3. 任务创建

进入 `userTask` 时，`UserTaskBehavior` 执行：

1. 解析 `assignee`、`owner`、`candidateUsers`、`candidateGroups`、`dueDate`、`priority`、`category`、`formKey`（支持表达式）。
2. 创建 `ACT_RU_TASK`，写入 `TASK_DEF_KEY_`、`EXECUTION_ID_`、`PROC_INST_ID_`、`TENANT_ID_`。
3. 创建身份链接：
   - assignee → `TYPE_='assignee'`
   - owner → `TYPE_='owner'`
   - candidate user → `TYPE_='candidate'`, `USER_ID_`
   - candidate group → `TYPE_='candidate'`, `GROUP_ID_`
4. 写入任务局部变量（`flowable:taskListener` 的 create 事件可读写）。
5. 触发 `TASK_CREATED` 事件与 create 监听器。
6. 当前执行进入等待态。

默认值：

| 属性 | 默认 |
| --- | --- |
| priority | 50 |
| category | 流程定义的 category |
| dueDate | 空 |
| formKey | 空 |
| suspensionState | 1 |
| owner | 空 |

## 4. 签收、完成、委派

### 4.1 签收（Claim）

- 仅未签收任务可签收；已签收返回 `ErrTaskAlreadyClaimed`。
- 设置 `ASSIGNEE_=user`、`CLAIM_TIME_=now`、`CLAIMED_BY_`。
- 创建/更新 assignee 身份链接。
- 触发 `TASK_ASSIGNED` 与 assignment 监听器。
- 并发签收由 `REV_` 乐观锁保护，失败方返回 409。

### 4.2 完成（Complete）

~~~go
// Complete 完成任务并推进流程。
// @param ctx 上下文
// @param taskID 任务 ID
// @param userID 操作人
// @param vars 完成时写入的变量
// @param localVars 任务局部变量
// @return error 完成错误
func (s *TaskService) Complete(ctx context.Context, taskID, userID string, vars, localVars map[string]any) error {
    return s.commands.Execute(ctx, NewCompleteTaskCmd(taskID, userID, vars, localVars))
}
~~~

执行步骤：

1. 加载任务，校验存在且未挂起。
2. 校验处理人（可选：`assignee` 为空或等于 `userID`；REST 层默认开启）。
3. 写入变量（`localVars` 写任务作用域，`vars` 按作用域规则写）。
4. 触发 complete 监听器；监听器可抛 BPMN Error 阻止完成。
5. 删除任务、任务变量、身份链接、子任务。
6. 写历史：结束时间、持续时间、完成人、删除原因。
7. 调度 `TriggerExecutionOperation`，让流程继续。
8. 发布 `TASK_COMPLETED` 事件。

### 4.3 委派与解决

| 操作 | 前置 | 效果 |
| --- | --- | --- |
| `DelegateTask(taskID, userID)` | 任务已签收 | `OWNER_`=原 assignee，`ASSIGNEE_`=被委托人，`DELEGATION_='PENDING'` |
| `ResolveTask(taskID, vars)` | `DELEGATION_='PENDING'` | `ASSIGNEE_`=owner，`DELEGATION_='RESOLVED'`，可写变量 |

委派任务不能直接 complete；必须先 resolve。resolve 后任务回到原处理人。

### 4.4 其他操作

| 操作 | 说明 |
| --- | --- |
| `SetAssignee` | 管理员改派，触发 assignment 事件 |
| `SetOwner` | 设置所有者 |
| `SetPriority` | 修改优先级 |
| `SetDueDate` | 修改到期时间 |
| `AddCandidateUser/Group` | 追加候选人 |
| `DeleteCandidateUser/Group` | 移除候选人 |
| `DeleteTask` | 删除任务（不推进流程，需谨慎） |

## 5. 任务监听器

| 事件 | 触发时机 | 可修改 |
| --- | --- | --- |
| `create` | 任务创建后 | 名称、描述、assignee、dueDate、priority |
| `assignment` | 签收/改派/委派 | assignee、owner |
| `complete` | 完成前 | 变量；抛错可阻止完成 |
| `delete` | 删除前 | 无 |
| `update` | 属性变更 | 无 |
| `timeout` | 到期 | 无 |

监听器实现方式：

- `expression`：`${myListener}`，调用注册的 Go 函数/Bean 方法。
- `delegateExpression`：解析为 `TaskListener` 接口实现。
- `class`：Java 类，Go 版拒绝部署或迁移为注册名。

~~~go
// TaskListener 是任务监听器。
type TaskListener interface {
    // Notify 处理任务事件。
    // @param ctx 上下文
    // @param task 任务快照
    // @param event 事件类型
    // @return error 处理错误
    Notify(ctx context.Context, task *TaskEntity, event TaskEvent) error
}
~~~

监听器执行顺序：按 BPMN 中声明顺序；任一返回错误则中止并回滚当前命令。

## 6. 任务查询

### 6.1 查询维度

| 维度 | 方法 | 索引 |
| --- | --- | --- |
| ID | `TaskID` | 主键 |
| 名称 | `Name`、`NameLike` | `NAME_` |
| 处理人 | `Assignee`、`AssigneeLike` | `ASSIGNEE_` |
| 所有者 | `Owner` | `OWNER_` |
| 候选人 | `CandidateUser`、`CandidateGroup` | 身份链接 |
| 流程 | `ProcessInstanceID`、`ProcessDefinitionID`、`ProcessDefinitionKey` | 外键/索引 |
| 定义键 | `TaskDefinitionKey` | `TASK_DEF_KEY_` |
| 时间 | `CreatedBefore/After`、`DueBefore/After` | `CREATE_TIME_`/`DUE_DATE_` |
| 优先级 | `Priority`、`PriorityHigherThan` | `PRIORITY_` |
| 分类 | `Category` | `CATEGORY_` |
| 租户 | `TenantID` | `TENANT_ID_` |
| 挂起 | `Suspended` | `SUSPENSION_STATE_` |
| 父任务 | `ParentTaskID` | `PARENT_TASK_ID_` |
| 表单 | `FormKey` | `FORM_KEY_` |

### 6.2 候选查询

`CandidateUser("alice")` 的 SQL 语义：

~~~sql
SELECT DISTINCT T.*
FROM ACT_RU_TASK T
WHERE T.ASSIGNEE_ IS NULL
  AND (
    EXISTS (SELECT 1 FROM ACT_RU_IDENTITYLINK L
            WHERE L.TASK_ID_ = T.ID_ AND L.TYPE_ = 'candidate' AND L.USER_ID_ = ?)
    OR EXISTS (SELECT 1 FROM ACT_RU_IDENTITYLINK L
               JOIN ACT_ID_MEMBERSHIP M ON M.GROUP_ID_ = L.GROUP_ID_
               WHERE L.TASK_ID_ = T.ID_ AND L.TYPE_ = 'candidate' AND M.USER_ID_ = ?)
  )
~~~

- 候选人查询默认排除已签收任务（`ASSIGNEE_ IS NULL`），可通过 `IgnoreAssignee` 关闭。
- 用户组展开在 SQL 中完成，避免应用层 N+1。
- 大租户下使用 `EXISTS` 而非 `JOIN`，避免重复行。

### 6.3 排序与分页

- 排序字段白名单：`ID_`、`NAME_`、`CREATE_TIME_`、`DUE_DATE_`、`PRIORITY_`、`ASSIGNEE_`、`PROCESS_INSTANCE_ID_`。
- 默认排序：`CREATE_TIME_ DESC, ID_ ASC`，保证稳定。
- 分页最大 1,000；REST 默认 10。
- 总数查询与列表查询分离；候选查询的 count 使用 `COUNT(DISTINCT T.ID_)`。

## 7. 身份链接

`ACT_RU_IDENTITYLINK` 统一承载任务、流程实例、流程定义的参与者关系。

| `TYPE_` | 作用域 | 说明 |
| --- | --- | --- |
| `assignee` | task | 任务处理人 |
| `owner` | task | 任务所有者 |
| `candidate` | task | 候选用户/组 |
| `participant` | process instance | 流程参与者 |
| `starter` | process instance | 发起人 |
| `initiator` | process instance | 发起人变量 |
| `businessAdministrator` | task/process | 业务管理员 |
| `potentialStarter` | process definition | 可发起人 |
| `admin` | 任意 | 管理员 |

规则：

- 同一任务同一用户/组同一类型只保留一条。
- 删除任务时级联删除其身份链接；历史表保留。
- 查询候选人时按 `TYPE_='candidate'` 过滤，用户与组分别匹配。

## 8. 评论、附件与任务日志

| 能力 | 表 | API |
| --- | --- | --- |
| 评论 | `ACT_HI_COMMENT` | `AddComment`、`GetTaskComments`、`GetProcessInstanceComments`、`DeleteComment` |
| 附件 | `ACT_HI_ATTACHMENT` | `CreateAttachment`、`GetTaskAttachments`、`GetAttachmentContent`、`DeleteAttachment` |
| 任务日志 | `ACT_HI_TSK_LOG` | 查询任务操作历史（claim/complete/assign） |

- 评论类型：`comment`、`event`；支持 `userId`、`time`、`message`、`action`、`fullMessage`。
- 附件支持 URL 与二进制内容；二进制存 `ACT_GE_BYTEARRAY`。
- 任务日志由配置开关控制，默认关闭以避免写放大。
- 删除流程实例时，评论/附件按配置保留或删除。

## 9. 子任务与动态任务

- 子任务通过 `PARENT_TASK_ID_` 关联；完成父任务时，子任务按配置级联删除或阻止完成。
- 子任务共享流程实例，但不直接驱动流程；完成子任务不触发令牌推进。
- 动态任务（Ad-hoc）允许在运行时创建任务并挂到执行上；需要显式 `complete` 才会推进流程。
- 任务必须属于一个执行或流程实例；禁止孤立任务。

## 10. 身份管理（IDM）

### 10.1 表结构

| 表 | 作用 | 关键列 |
| --- | --- | --- |
| `ACT_ID_USER` | 用户 | `ID_`、`FIRST_`、`LAST_`、`EMAIL_`、`PWD_`、`TENANT_ID_` |
| `ACT_ID_GROUP` | 组 | `ID_`、`NAME_`、`TYPE_` |
| `ACT_ID_MEMBERSHIP` | 成员关系 | `USER_ID_`、`GROUP_ID_` |
| `ACT_ID_INFO` | 用户信息 | `USER_ID_`、`KEY_`、`VALUE_`、`PASSWORD_` |
| `ACT_ID_BYTEARRAY` | 头像等 | `ID_`、`BYTES_` |
| `ACT_ID_PRIV` | 权限 | `ID_`、`NAME_` |
| `ACT_ID_PRIV_MAPPING` | 权限映射 | `USER_ID_`/`GROUP_ID_`、`PRIV_ID_` |
| `ACT_ID_PROPERTY` | 引擎属性 | `NAME_`、`VALUE_` |
| `ACT_ID_TOKEN` | 记住我 Token | `TOKEN_VALUE_`、`TOKEN_DATE_`、`IP_ADDRESS_` |

### 10.2 API

~~~go
// IdentityService 提供用户、组与认证能力。
type IdentityService interface {
    // CreateUser 创建用户。
    // @param ctx 上下文
    // @param user 用户信息
    // @return 创建后的用户
    // @return 错误
    CreateUser(ctx context.Context, user User) (User, error)
    // CheckPassword 校验用户名密码。
    // @param ctx 上下文
    // @param userID 用户 ID
    // @param password 明文密码
    // @return 是否通过
    // @return 错误
    CheckPassword(ctx context.Context, userID, password string) (bool, error)
    // AddMembership 添加用户到组。
    // @param ctx 上下文
    // @param userID 用户 ID
    // @param groupID 组 ID
    // @return 错误
    AddMembership(ctx context.Context, userID, groupID string) error
}
~~~

### 10.3 密码与安全

- 密码使用 **bcrypt**（cost 12）或 **argon2id**；禁止明文/MD5/SHA1。
- `PWD_` 存储格式：`{bcrypt}$2a$...`、`{argon2id}$argon2id$...`，便于算法升级。
- 读取 Java 库时，若为未知格式，登录失败并记录迁移告警；提供一次性重置脚本。
- Token 使用加密随机值，存哈希；有效期默认 30 天。
- 认证失败统一返回"用户名或密码错误"，不区分用户是否存在。
- 登录失败计数与锁定由 REST 层实现（可选）。

### 10.4 外部身份源

- 定义 `IdentityProvider` SPI：`FindUser`、`CheckPassword`、`ListGroups`。
- LDAP 在 T3 实现，只读同步；本地表作为缓存。
- 外部 Provider 失败时，按配置降级到本地或拒绝登录。

## 11. 认证与授权

| 层 | 能力 |
| --- | --- |
| 引擎 | 不强制任务/流程权限；提供 `Authentication` 上下文 |
| REST | Basic/Bearer/JWT；租户解析；操作人注入 |
| 方法级 | `authorize(user, action, resource)` 钩子，可配置 |
| 数据级 | 按租户过滤；按流程定义候选发起人过滤 |

- `authenticatedUserId` 由 REST 中间件写入上下文，引擎用于 `startUserID`、任务完成人、评论作者。
- 引擎内部禁止信任请求体中的用户 ID；一律取认证上下文。
- 管理端点（作业、表、迁移）要求管理员角色。

## 12. 表单

### 12.1 表单类型

### 12.2 API

~~~go
// FormService 提供启动表单与任务表单数据。
type FormService interface {
    // GetStartFormData 获取流程启动表单。
    // @param ctx 上下文
    // @param processDefinitionID 流程定义 ID
    // @return 表单数据
    // @return 错误
    GetStartFormData(ctx context.Context, processDefinitionID string) (FormData, error)
    // GetTaskFormData 获取任务表单。
    // @param ctx 上下文
    // @param taskID 任务 ID
    // @return 表单数据
    // @return 错误
    GetTaskFormData(ctx context.Context, taskID string) (FormData, error)
    // SubmitTaskFormData 提交任务表单。
    // @param ctx 上下文
    // @param taskID 任务 ID
    // @param values 字段值
    // @return 错误
    SubmitTaskFormData(ctx context.Context, taskID string, values map[string]any) error

~~~

### 12.3 表单属性

| 属性 | 说明 |
| --- | --- |
| `id` | 字段名，写入变量 |
| `name` | 显示名 |
| `type` | string/long/boolean/date/enum |
| `required` | 是否必填 |
| `readable`/`writable` | 权限 |
| `value` | 默认值 |
| `enumValues` | 枚举值 |

校验：

- 必填为空 → 400，返回字段错误。
- 类型转换失败 → 400。
- 只读字段被修改 → 400。
- 表单字段名不得覆盖系统变量（`execution`、`task` 等）。

## 13. 事件

| 事件 | 触发点 | 可取消 |
| --- | --- | --- |
| `TASK_CREATED` | 任务创建后 | 否 |
| `TASK_ASSIGNED` | 签收/改派/委派 | 否 |
| `TASK_COMPLETED` | 完成提交后 | 否 |
| `TASK_UPDATED` | 属性变更 | 否 |
| `TASK_DELETED` | 删除 | 否 |
| `TASK_TIMEOUT` | 到期 | 否 |
| `ENTITY_CREATED/UPDATED/DELETED` | 通用实体事件 | 部分 |

事件在事务内派发；监听器异常导致命令回滚。异步事件监听器在提交后执行。

## 14. 测试要点

- 任务创建：assignee/candidate/owner 表达式、默认值、身份链接。
- 签收并发：10 个请求同时 claim，仅 1 个成功。
- 完成：变量写入、监听器、历史、令牌推进。
- 委派/解决：状态机与权限。
- 候选人查询：直接候选、组候选、组嵌套、排除已签收。
- 任务查询：组合条件、排序、分页、租户隔离。
- 评论/附件：增删查、权限、级联。
- IDM：密码哈希、错误密码、Token 过期、组成员。
- 表单：必填、类型、只读、枚举。
- 事件：顺序、回滚、异步。
