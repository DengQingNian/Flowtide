## 1. 架构目标与约束

| 目标 | 架构手段 | 约束 |
| --- | --- | --- |
| 语义与 Flowable 对齐 | 移植 Command + Agenda + 执行树模型 | 不引入与 Flowable 冲突的隐式状态机 |
| 纯 Go、零 CGO | 标准库 + 纯 Go 三方库 | 禁止 JDBC、JNI、本地 XML 库 |
| 可嵌入、可独立部署 | 引擎核心不依赖 HTTP/框架 | `internal/` 不反向依赖 `cmd/` |
| 数据库兼容 | 显式 SQL + 方言层 | 不自动改表、不做隐式迁移 |
| 可测试 | 时钟/ID/事件/DB 全部注入 | 禁止包级单例与 `time.Now()` 直调 |
| 可观测 | 统一拦截器埋点 | 业务代码不散落打点逻辑 |

1. `api/` 只依赖标准库与 `bpmn/model`，不依赖 `internal/`。

- **无状态节点**：除进程内缓存外，所有状态在数据库；节点可水平扩展。
- **作业竞争**：多节点通过数据库行锁/乐观锁抢占作业，同一作业同一时刻只被一个节点执行。
- **定时器**：每个节点均可扫描，但通过 `LOCK_OWNER_`/`LOCK_EXPIRATION_TIME_` 保证互斥。
- **缓存失效**：本地 LRU + 流程定义版本戳；跨节点通过短 TTL 或可选 Redis Pub/Sub 广播。

启动失败的分类：

| 错误 | 处理 |
| --- | --- |
| 连接失败 | 快速失败，返回 `ErrDatabaseUnavailable` |
| Schema 版本不匹配 | 默认拒绝启动；`schemaUpdate=true` 时升级 |
| 引擎版本高于库版本 | 拒绝启动，提示升级二进制 |

## 5. Command 模式

所有写操作与需要事务的读操作都封装为 Command。Command 是事务、上下文、拦截器、指标的最小单元。

~~~go
// Command 表示一条引擎命令。
// 命令在事务内执行，返回值透传给调用方。
type Command interface {
    // Execute 在命令上下文中执行命令。
    // @param ctx 命令上下文，包含会话、议程、服务与事务
    // @return 命令结果
    // @return error 执行错误
    Execute(ctx *CommandContext) (any, error)
}

// CommandFunc 将函数适配为 Command。
type CommandFunc func(ctx *CommandContext) (any, error)

// Execute 调用底层函数。
// @param ctx 命令上下文
// @return 命令结果
// @return error 执行错误
func (f CommandFunc) Execute(ctx *CommandContext) (any, error) { return f(ctx) }
~~~

### 5.1 拦截器链

~~~go
// Next 表示拦截器链的下一环。
type Next func(ctx context.Context, cmd Command) (any, error)

// Interceptor 是命令拦截器。
// 拦截器可执行前置/后置逻辑，决定是否调用 next。
type Interceptor func(ctx context.Context, cmd Command, next Next) (any, error)

// Chain 按顺序组合拦截器，最后一个拦截器负责真正执行命令。
// @param interceptors 拦截器列表，顺序即执行顺序
// @return 组合后的执行函数
func Chain(interceptors ...Interceptor) func(context.Context, Command) (any, error) {
    return func(ctx context.Context, cmd Command) (any, error) {
        var run Next
        run = func(c context.Context, command Command) (any, error) {
            return command.Execute(CommandContextFrom(c))
        }
        // 从后向前包裹，保证第一个拦截器最外层
        for i := len(interceptors) - 1; i >= 0; i-- {
            current, next := interceptors[i], run
            run = func(c context.Context, command Command) (any, error) {
                return current(c, command, next)
            }
        }
        return run(ctx, cmd)
    }
}
~~~

标准拦截器顺序（外 → 内）：

1. **RecoveryInterceptor**：panic 转错误，记录堆栈，避免进程崩溃。
2. **LoggingInterceptor**：命令名、耗时、结果大小；慢命令告警。
3. **TenantInterceptor**：解析并校验租户，写入上下文。
4. **CommandContextInterceptor**：创建/复用 `CommandContext`，绑定服务与议程。
5. **TransactionInterceptor**：开启事务；嵌套命令复用当前事务。
6. **SchemaInterceptor**：首次访问时校验 Schema 版本（仅启动后首命令）。
7. **CommandInvoker**：终止链，执行命令本体。
8. **MetricsInterceptor**（可选，位于 Logging 内层）：Prometheus 指标。

> 与 Flowable 的差异：Flowable 把 CommandContext 与 Transaction 分成两个拦截器；Go 版保持相同顺序，但事务使用 `database/sql`，嵌套命令通过上下文复用，不引入 JTA。

### 5.2 CommandContext

~~~go
// CommandContext 保存一条命令执行期间的全部可变状态。
// 它只在单 goroutine 内使用，不跨命令共享。
type CommandContext struct {
    Ctx        context.Context
    Services   *Services
    Session    *Session
    Agenda     Agenda
    Clock      Clock
    IDGen      IDGenerator
    TenantID   string
    Auth       AuthContext
    Events     EventDispatcher
    Tx         *sql.Tx
    attributes map[string]any
    closed     bool
}

// GetService 获取强类型服务实例。
// @param name 服务名
// @return 服务实例
// @return 是否存在
func GetService[T any](ctx *CommandContext, name string) (T, bool) { /* ... */ }
~~~

上下文字段的生命周期：

- `Session`：命令开始时创建，命令结束时 `Flush` + `Close`。
- `Agenda`：命令开始时创建，命令结束时必须为空（否则视为引擎缺陷）。
- `Events`：事务内缓存事件，提交后派发；`transactional` 监听器在提交前执行。
- `Tx`：由 TransactionInterceptor 注入；只读命令可使用只读事务。

## 6. Agenda 操作循环

Agenda 是 Flowable 语义的核心：行为（Behavior）不直接递归推进流程，而是把"下一步做什么"封装为 Operation 放入队列，由循环串行执行。这样做的好处是：

- 调用栈浅，长流程不会栈溢出。
- 每个操作是一个可测试的最小单元。
- 便于插入调试、审计与中断。

~~~go
// Operation 是议程中的一个原子操作。
type Operation interface {
    // Run 执行操作，可向议程追加后续操作。
    // @param ctx 命令上下文
    // @return error 执行错误
    Run(ctx *CommandContext) error
}

// Agenda 串行执行操作队列。
type Agenda interface {
    // Schedule 追加操作到队尾。
    // @param op 操作
    Schedule(op Operation)
    // Run 循环执行直到队列为空。
    // @param ctx 命令上下文
    // @return error 执行错误
    Run(ctx *CommandContext) error
}
~~~

核心操作（与 Flowable 对应）：

| Operation | 职责 |
| --- | --- |
| `ContinueProcessOperation` | 从当前元素继续，执行行为或沿顺序流推进 |
| `TakeOutgoingSequenceFlowsOperation` | 计算并选择出线，处理条件与默认流 |
| `ExecuteActivityBehaviorOperation` | 调用行为并处理同步/异步边界 |
| `EndExecutionOperation` | 结束执行，触发结束监听器，清理作用域 |
| `DestroyScopeOperation` | 销毁作用域及其子执行、任务、变量 |
| `ContinueMultiInstanceOperation` | 多实例下一轮 |
| `TriggerExecutionOperation` | 定时器/消息/信号触发等待中的执行 |
| `EvaluateConditionalEventsOperation` | 条件事件求值 |

循环约束：

1. 单条命令最多执行 **100 万** 个操作；超过则 panic 并记录 `ErrAgendaOverflow`。
2. 操作必须是幂等的（重试安全）；数据库写操作在 Flush 阶段统一执行。
3. 操作内部不得调用 `tx.Commit`；不得启动新的 goroutine。
4. 每个操作执行前后可采样耗时，超过 50ms 记录慢操作。

~~~go
// DefaultAgenda 是 Agenda 的默认实现。
type DefaultAgenda struct {
    operations []Operation
    maxOps     int
}

// Run 串行执行队列中的操作。
// @param ctx 命令上下文
// @return error 执行错误
func (a *DefaultAgenda) Run(ctx *CommandContext) error {
    executed := 0
    for len(a.operations) > 0 {
        op := a.operations[0]
        a.operations = a.operations[1:]
        if executed++; executed > a.maxOps {
            return ErrAgendaOverflow
        }
        // 单个操作失败立即中止，事务回滚
        if err := op.Run(ctx); err != nil {
            return err
        }
    }
    return nil
}
~~~

## 7. 持久化会话与工作单元

Go 版不复制 Hibernate 的脏检查，而采用**显式仓储 + 语句缓冲**：

~~~go
// Session 聚合一条命令内的持久化操作，并在 Flush 时按顺序写出。
type Session struct {
    db       *sql.DB
    tx       *sql.Tx
    inserts  []Entity
    updates  []Entity
    deletes  []Entity
    batcher  Batcher
    clock    Clock
}

// Insert 登记一个待插入实体。
// @param entity 实体
func (s *Session) Insert(entity Entity) { s.inserts = append(s.inserts, entity) }

// Flush 按依赖顺序执行插入、更新、删除，并校验乐观锁版本。
// @return error 持久化错误
func (s *Session) Flush() error { /* ... */ }
~~~

Flush 顺序：

1. **插入**：按实体依赖拓扑排序（部署 → 流程定义 → 执行 → 任务 → 变量 → 作业 → 历史）。
2. **更新**：同一实体只保留最后一次；带 `REV_` 乐观锁。
3. **删除**：按依赖逆序。
4. **批量**：每 100 条或 1MB 触发一次批量语句。
5. **事务同步**：提交后派发 `afterCommit` 回调（作业通知、事件、缓存失效）。

> 设计取舍：不实现自动脏检查，要求所有变更通过实体管理器方法完成。代价是代码略啰嗦，收益是行为可预测、SQL 可审计、测试更容易。

## 8. 事务与同步回调

~~~go
// TransactionManager 管理命令事务与提交后回调。
type TransactionManager interface {
    // Execute 在事务中执行函数；嵌套调用复用当前事务。
    // @param ctx 上下文
    // @param fn 事务函数
    // @return error 执行错误
    Execute(ctx context.Context, fn func(tx *sql.Tx) error) error
    // AfterCommit 注册提交后回调；回滚时不执行。
    // @param fn 回调
    AfterCommit(fn func())
    // AfterRollback 注册回滚后回调。
    // @param fn 回调
    AfterRollback(fn func())
}
~~~

事务传播规则：

| 场景 | 行为 |
| --- | --- |
| 服务方法调用服务方法 | 复用当前 Command/事务（REQUIRED） |
| 作业执行 | 新 Command/新事务 |
| 事件监听器（同步） | 当前事务；异常导致回滚 |
| 事件监听器（异步） | 提交后投递，独立事务 |
| REST 请求 | 一条命令一个事务，读完即提交 |

隔离级别默认 **READ COMMITTED**；流程定义部署使用行锁避免并发版本冲突。禁止在事务内进行 HTTP 调用；HTTP 任务通过异步作业执行。

## 9. 并发模型

~~~mermaid
flowchart LR
    REQ1[HTTP 请求] --> POOL[goroutine]
    POOL --> CMD1[Command]
    CMD1 --> TX1[(事务 1)]
    JOB1[作业 worker] --> CMD2[Command]
    CMD2 --> TX2[(事务 2)]
    TIMER[定时器扫描] --> CMD3[Command]
    CMD3 --> TX3[(事务 3)]
~~~

规则：

1. **一命令一 goroutine**：命令内部的所有操作串行执行，不并行推进同一执行树。
2. **执行树不共享**：不同命令操作不同流程实例时天然隔离；同一实例的并发操作由乐观锁或行锁保护。
3. **任务完成并发**：两个请求同时完成同一任务，只有一个成功，另一个返回 `409 Conflict`。
4. **作业执行器**：固定大小 worker pool，每个 worker 独立命令与事务；作业通过数据库抢占。
5. **缓存并发**：`sync.Map` 或 RWMutex + LRU；缓存条目不可变，更新通过替换指针。
6. **禁止**在行为/监听器中启动 goroutine；需要异步请创建作业。

## 10. 缓存设计

| 缓存 | Key | 内容 | 失效 |
| --- | --- | --- | --- |
| 流程定义缓存 | `definitionID` | 解析后的 `BpmnModel`、行为映射、定时器声明、事件订阅声明 | 部署/删除/挂起时按 key 失效；TTL 兜底 |
| 流程定义版本缓存 | `key + tenant + version` | definitionID | 部署后更新 |
| 表达式缓存 | 表达式文本 + 函数集版本 | 编译后的 AST | 引擎重启；函数注册变更时清空 |
| 部署缓存 | `deploymentID` | 资源清单 | 删除部署 |
| Schema 版本 | 单例 | 当前库版本 | 启动时读取 |

缓存条目必须**不可变**：行为对象在构建后只读，避免并发修改。集群场景下，节点 A 部署后节点 B 可能短暂读到旧版本；通过以下手段收敛：

- 流程定义 ID 含版本与 UUID，运行中实例始终按 ID 取模型，不受新部署影响。
- 按 key 启动新实例时，每次从数据库读取最新版本号（可缓存 1 秒）。
- 可选 Redis Pub/Sub：部署事件广播，节点收到后失效本地缓存。

## 12. 错误模型

~~~go
// EngineError 是引擎统一错误类型。
type EngineError struct {
    Code      string // 稳定错误码，如 ENGINE-0404
    Message   string // 面向开发者的中文说明
    Op        string // 操作名
    Retryable bool   // 是否可重试
    Cause     error  // 底层错误
}

// Error 实现 error 接口。
// @return 错误字符串
func (e *EngineError) Error() string { return e.Code + ": " + e.Message }

// Unwrap 返回底层错误，支持 errors.Is/As。
// @return 底层错误
func (e *EngineError) Unwrap() error { return e.Cause }
~~~

错误分类：

| 类别 | 示例 | HTTP | 重试 |
| --- | --- | --- | --- |
| 参数错误 | 流程 Key 为空 | 400 | 否 |
| 未找到 | 流程定义不存在 | 404 | 否 |
| 冲突 | 乐观锁、任务已被签收 | 409 | 视场景 |
| 禁止 | 无权限、租户不匹配 | 403 | 否 |
| 业务错误 | BPMN Error 抛出 | 500/400 | 否 |
| 暂时故障 | 连接超时、死锁 | 503 | 是 |
| 引擎缺陷 | Agenda 溢出、状态非法 | 500 | 否 |

禁止用字符串比较判断错误；调用方使用 `errors.Is` 或错误码。

  conn-max-lifetime: 30m
  schema-update: true           # false|true|create-drop
  table-prefix: ACT_
server:
  addr: ":8080"
  base-path: /service
  read-timeout: 30s
  write-timeout: 60s
observability:
  log-level: info
  log-format: json
  metrics: true
  tracing: false
~~~

校验规则示例：

- `workers` 必须在 1–1024。
- `history-level` 必须是枚举值。
- `lock-duration` 必须大于单次作业最长执行时间。
- `schema-update=create-drop` 仅允许在 `env=dev` 使用，生产环境启动直接拒绝。

## 15. 关键时序：启动流程实例

~~~mermaid
sequenceDiagram
    participant C as 调用方
    participant R as RuntimeService
    participant CM as CommandInvoker
    participant TX as 事务
    participant S as Session
    participant A as Agenda
    participant B as Behavior

    C->>R: StartProcessInstanceByKey(key, vars)
    R->>CM: execute(StartProcessInstanceCmd)
    CM->>TX: begin
    CM->>S: 读取最新流程定义 + 构建执行树
    CM->>S: insert 流程实例/执行/变量
    CM->>A: schedule(ContinueProcessOperation)
    loop 直到议程为空
        A->>B: execute(behavior)
        B->>A: schedule(下一个操作)
    end
    CM->>S: flush (批量写)
    CM->>TX: commit
    TX-->>C: 流程实例 DTO
~~~

关键点：

- 事务内只写数据库一次（Flush），减少往返。
- 遇到用户任务时，行为创建 `ACT_RU_TASK` 并结束当前令牌推进。
- 流程在第一个等待状态返回；变量在提交后可见。

## 16. 非功能设计

### 16.1 可观测性

- **日志**：`trace_id`、`command`、`process_instance_id`、`task_id`、`tenant_id` 为固定字段。
- **指标**：命令总数/耗时、Agenda 操作数、作业成功率/重试数、定时器延迟、连接池、缓存命中率。
- **追踪**：REST → Command → SQL → 作业 链路；SQL 语句做脱敏。
- **健康检查**：`/healthz`（进程）、`/readyz`（数据库 + Schema + 作业执行器）。

### 16.2 安全

- SQL 全部参数化；动态排序字段使用白名单。
- 表达式引擎禁止反射调用任意方法，只允许白名单类型与方法。
- 脚本沙箱限制执行时间、内存与可用全局对象。
- 反序列化仅允许注册类型，禁止 `gob` 任意类型。
- 部署包大小、资源数量、XML 深度均有限制，防止 Zip Bomb / XXE。

### 16.3 多租户

- 所有查询默认追加 `TENANT_ID_ = ?`；`tenantId=""` 表示默认租户。
- 流程定义按 `(key, tenant, version)` 唯一。
- 作业执行时携带租户，作业处理器不得跨租户写数据。
- REST 通过 `X-Tenant-Id` 或认证信息解析租户。

### 16.4 集群

- 节点无共享内存；数据库是协调点。
- 作业抢占使用 `SELECT ... FOR UPDATE SKIP LOCKED`（PG/MySQL 8）。
- 时钟偏差容忍：锁过期时间 = 作业最长执行时间 × 2 + 时钟偏差余量。
- 部署并发：对 `(key, tenant)` 加数据库行锁，版本号自增。

## 17. 架构验收清单

- [ ] 引擎可在 `CGO_ENABLED=0` 下编译并运行。
- [ ] 一条命令只开启一个事务；嵌套命令复用事务。
- [ ] Agenda 空队列是命令结束的必要条件。
- [ ] 所有 SQL 经过方言层，无硬编码占位符。
- [ ] 时钟、ID、事件、数据库均可注入，单元测试无真实依赖。
- [ ] 进程内无包级可变单例。
- [ ] 缓存条目不可变，部署后旧实例不受影响。
- [ ] 作业执行器可在多节点同时运行且不重复执行。
- [ ] 所有错误带稳定错误码，可被 `errors.Is` 识别。
