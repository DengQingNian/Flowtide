# 006 流程执行引擎（PVM）设计

> 文档编号：006  
> 依赖：002 总体架构、004 数据模型、005 BPMN 解析  
> 目标读者：引擎开发  
> 关键词：执行树、Agenda、ActivityBehavior、多实例、边界事件、补偿、迁移

## 1. 执行模型总览

Flowable 的运行时本质是一棵**执行树（Execution Tree）**加一个**操作队列（Agenda）**：

- 执行（Execution）代表一个令牌或一个作用域。
- 行为（ActivityBehavior）决定遇到某个 BPMN 元素时做什么。
- 行为不递归调用下一个元素，而是把后续动作封装为操作（Operation）放入 Agenda。
- 命令结束时，Agenda 必须为空，执行树处于稳定状态（等待外部事件或已结束）。

~~~mermaid
flowchart TD
    CMD[Command] --> CTX[CommandContext]
    CTX --> AG[Agenda]
    AG --> OP1[ContinueProcessOperation]
    OP1 --> B[ActivityBehavior.Execute]
    B -->|等待| WAIT[创建任务/订阅/作业]
    B -->|继续| OP2[TakeOutgoingSequenceFlowsOperation]
    OP2 --> OP3[ContinueProcessOperation]
    OP3 --> OP4[EndExecutionOperation]
    OP4 --> AG
~~~

## 2. 执行树

### 2.1 核心字段与不变量

| 字段 | 含义 | 不变量 |
| --- | --- | --- |
| `ID_` | 执行 ID | 全局唯一 |
| `PROC_INST_ID_` | 流程实例 ID | 同一棵树的根 ID 相同 |
| `PARENT_ID_` | 父执行 | 根为空；子执行必须指向同实例执行 |
| `PROC_DEF_ID_` | 流程定义 | 同一实例内一致（迁移除外） |
| `ACT_ID_` | 当前活动 | 等待态指向任务/事件；运行态可为空 |
| `IS_SCOPE_` | 是否作用域 | 流程实例、子流程、多实例根为 true |
| `IS_CONCURRENT_` | 是否并发分支 | 并行网关分叉后为 true |
| `IS_ACTIVE_` | 是否活跃 | 非活跃执行在汇聚时被忽略 |
| `IS_EVENT_SCOPE_` | 是否事件作用域 | 边界事件/事件子流程使用 |
| `IS_MI_ROOT_` | 是否多实例根 | 保存 `nrOfInstances` 等变量 |
| `SUSPENSION_STATE_` | 挂起状态 | 1 正常，2 挂起 |

### 2.2 树的形态

**单令牌流程**（无并发）：

~~~text
ProcessInstance (root, scope)
└── (根执行自身移动到 userTask，不创建子执行)
~~~

**并行网关分叉**：

~~~text
ProcessInstance (root, scope)
├── Execution A (concurrent, active) → userTask A
└── Execution B (concurrent, active) → userTask B
~~~

**子流程**：

~~~text
ProcessInstance (root)
└── SubProcess Execution (scope)
    └── Child Execution → userTask
~~~

**调用活动**：

~~~text
Parent ProcessInstance
└── CallActivity Execution (scope, superExecution=parent)
    └── Child ProcessInstance (root)
~~~

规则：

1. 只有 `IS_SCOPE_=true` 的执行可以拥有子执行与变量作用域。
2. 并发分支的父执行保持 `IS_ACTIVE_=false`，等待所有分支结束。
3. 汇聚时删除分支执行，恢复父执行为活跃。
4. 根执行结束即流程实例结束；子执行结束只结束当前作用域。

### 2.3 变量作用域

- 变量可挂在执行或任务上；查找沿 `parent` 链向上，直到流程实例。
- `local` 变量只写当前作用域；`global` 变量写到流程实例根。
- 瞬态变量（transient）只存在于当前命令，不落库。
- 变量读取优先级：任务局部 → 当前执行 → 父执行 → 流程实例。

## 3. Agenda 操作详解

### 3.1 操作列表

| 操作 | 触发时机 | 主要职责 |
| --- | --- | --- |
| `ContinueProcessOperation` | 进入一个 FlowNode | 执行行为；无等待则调度出线 |
| `TakeOutgoingSequenceFlowsOperation` | 行为完成或网关判断 | 条件求值、默认流、分叉 |
| `ExecuteActivityBehaviorOperation` | 需要异步/事务边界 | 在独立命令中执行行为 |
| `EndExecutionOperation` | 到达结束事件/无出线 | 结束监听器、销毁作用域、通知父级 |
| `DestroyScopeOperation` | 中断/删除/补偿 | 级联删除子执行、任务、变量、作业、订阅 |
| `ContinueMultiInstanceOperation` | 多实例下一轮 | 创建/推进实例，检查完成条件 |
| `TriggerExecutionOperation` | 消息/信号/定时器到达 | 唤醒等待中的执行 |
| `EvaluateConditionalEventsOperation` | 变量变化/到达 | 评估条件事件并触发 |
| `EvaluateVariableListenerEventDefinitionsOperation` | 变量变化 | 触发变量监听器 |

### 3.2 单步推进伪代码

~~~go
// ContinueProcess 从当前执行继续推进。
// @param ctx 命令上下文
// @param execution 当前执行
// @return error 执行错误
func ContinueProcess(ctx *CommandContext, execution *ExecutionEntity) error {
    element := execution.CurrentFlowElement()
    if element == nil {
        return ctx.Agenda.Schedule(NewEndExecutionOperation(execution, ""))
    }
    // 1. 执行进入监听器
    if err := ExecuteListeners(ctx, execution, element, EventStart); err != nil {
        return err
    }
    // 2. 取行为；没有行为说明模型非法
    behavior, ok := ctx.Behaviors.For(element)
    if !ok {
        return NewEngineError("ENGINE-0501", "元素缺少行为: "+element.GetID(), err)
    }
    // 3. 异步边界：先落作业，命令结束
    if IsAsyncBefore(element) {
        return CreateAsyncJob(ctx, execution, element, JobAsyncBefore)
    }
    // 4. 行为自行决定等待或继续
    return behavior.Execute(ctx, execution)
}
~~~

### 3.3 出线选择

~~~go
// TakeOutgoing 计算并调度出线。
// @param ctx 命令上下文
// @param execution 当前执行
// @param element 当前元素
// @return error 执行错误
func TakeOutgoing(ctx *CommandContext, execution *ExecutionEntity, element FlowNode) error {
    flows := element.Outgoing()
    if len(flows) == 0 {
        return ctx.Agenda.Schedule(NewEndExecutionOperation(execution, ""))
    }
    selected := make([]*SequenceFlow, 0, len(flows))
    var defaultFlow *SequenceFlow
    for _, f := range flows {
        if f.DefaultFlow {
            defaultFlow = f
            continue
        }
        if f.ConditionExpression == "" {
            selected = append(selected, f)
            continue
        }
        ok, err := ctx.Expressions.EvalBool(execution, f.ConditionExpression)
        if err != nil {
            return err
        }
        if ok {
            selected = append(selected, f)
        }
    }
    if len(selected) == 0 && defaultFlow != nil {
        selected = append(selected, defaultFlow)
    }
    if len(selected) == 0 {
        return NewEngineError("ENGINE-0502", "没有可走的出线: "+element.GetID(), nil)
    }
    return ForkAndContinue(ctx, execution, selected)
}
~~~

### 3.4 分叉与汇聚

- **单出线**：根执行移动到目标节点。
- **多出线**：父执行置为非活跃，为每条出线创建并发子执行；子执行继承变量作用域。
- **汇聚**：子执行到达网关时，若仍有其他活跃分支，则结束自身并等待；最后一个分支负责继续。

并发子执行的创建必须在一个事务内完成，避免其他节点读到"半棵树"。

## 4. 启动、推进与结束

### 4.1 启动流程实例

1. 解析 `processDefinitionKey` + `tenant`，取最新版本。
2. 校验流程定义未挂起、可执行。
3. 创建根执行：`IS_SCOPE_=true`、`IS_ACTIVE_=true`、`START_TIME_`、`START_USER_ID_`。
4. 写入启动变量（`global`）。
5. 设置 `currentFlowElement` 为开始事件。
6. 调度 `ContinueProcessOperation`。
7. 执行 `startProcessInstance` 监听器。
8. Flush + 提交；返回流程实例（若已结束则 `ended=true`）。

启动选项：

| 选项 | 说明 |
| --- | --- |
| `BusinessKey` | 业务键，写根执行 |
| `Name` | 实例名称 |
| `TenantID` | 租户 |
| `StartUserID` | 发起人 |
| `Variables` | 启动变量 |
| `TransientVariables` | 瞬态变量 |
| `CallbackID/Type` | 外部回调 |
| `ReferenceID/Type` | 业务引用 |
| `BusinessStatus` | 业务状态 |

### 4.2 推进到等待态

当行为创建用户任务、消息订阅、定时器作业或外部工作项后，当前执行进入等待态，Agenda 清空，命令提交。

### 4.3 结束

- **无出线的 FlowNode**：结束当前执行。
- **结束事件**：执行结束监听器 → 销毁作用域 → 通知父执行。
- **根执行结束**：流程实例结束，写历史结束时间与持续时间。
- **Terminate**：忽略作用域层级，直接结束整个流程实例；正在执行的并行分支全部销毁。
- **Error End**：抛出 BPMN Error，沿作用域向上寻找错误边界事件；找不到则流程实例失败（历史标记 `deleteReason`）。

## 5. 网关语义

### 5.1 排他网关（ExclusiveGateway）

- 按出线顺序求值，选择**第一条**条件为 true 的流。
- 无条件出线视为 true；若都不满足，走默认流；无默认流则报错。
- 多条入线视为**合并**，不等待其他分支（可能造成令牌重复，需建模保证）。

### 5.2 并行网关（ParallelGateway）

- 分叉：为每条出线创建并发执行，全部继续。
- 汇聚：等待所有**能到达该网关**的活跃分支；最后一个到达者继续。
- 若某分支被终止/中断，汇聚需要重新计算可达分支，避免死锁。

### 5.3 包容网关（InclusiveGateway）

- 分叉：所有条件为 true 的出线都走；默认流仅在无其他选择时走。
- 汇聚：等待所有"可能到达"的活跃分支。实现步骤：
  1. 从网关反向遍历，收集所有上游分支。
  2. 过滤仍在活跃执行中的分支。
  3. 若没有其他活跃分支可到达，则继续。
- 这是最容易出现语义偏差的网关，必须有覆盖"嵌套并行 + 条件分支 + 中断边界"的用例。

### 5.4 事件网关（EventBasedGateway）

- 为每条出线创建事件订阅/定时器。
- 第一个事件到达时，取消其他订阅，沿对应出线继续。
- 只允许出线连接中间捕获事件或接收任务。

### 5.5 复杂网关（ComplexGateway）

参考实现只解析模型、未提供运行时行为。Go 版在部署校验阶段直接拒绝，错误码 `BPMN-1014`，避免"能部署但不能跑"。

## 7. 多实例

### 7.1 变量约定

| 变量 | 作用域 | 含义 |
| --- | --- | --- |
| `nrOfInstances` | 多实例根执行 | 总实例数 |
| `nrOfActiveInstances` | 多实例根执行 | 活跃实例数 |
| `nrOfCompletedInstances` | 多实例根执行 | 已完成实例数 |
| `loopCounter` | 每个子执行 | 当前序号，从 0 开始 |

### 7.2 创建算法

~~~go
// CreateMultiInstance 创建多实例执行。
// @param ctx 命令上下文
// @param execution 多实例根执行
// @param mi 多实例配置
// @return error 创建错误
func CreateMultiInstance(ctx *CommandContext, execution *ExecutionEntity, mi *MultiInstanceLoopCharacteristics) error {
    // 1. 计算实例数：collection 优先，其次 loopCardinality
    count, err := ResolveInstanceCount(ctx, execution, mi)
    if err != nil {
        return err
    }
    // 2. 零实例：直接完成，不创建子执行
    if count == 0 {
        return CompleteMultiInstance(ctx, execution)
    }
    // 3. 设置根变量
    execution.SetVariableLocal("nrOfInstances", count)
    execution.SetVariableLocal("nrOfActiveInstances", count)
    execution.SetVariableLocal("nrOfCompletedInstances", 0)
    // 4. 并行：一次性创建；串行：只创建第一个
    n := count
    if !mi.Parallel {
        n = 1
    }
    for i := 0; i < n; i++ {
        if err := CreateInstanceExecution(ctx, execution, mi, i); err != nil {
            return err
        }
    }
    return nil
}
~~~

### 7.3 完成与提前结束

- 每个实例完成时 `nrOfCompletedInstances++`、`nrOfActiveInstances--`。
- 若设置了 `completionCondition`，每次完成后求值；为 true 时：
  1. 标记多实例根完成。
  2. 中断并删除剩余实例（若为并行）。
  3. 继续多实例根之后的路径。
- 串行多实例：完成条件满足后不再创建下一个。
- 变量聚合（`variableAggregation`）：按目标变量收集各实例结果，支持 `sum/min/max/collect` 等聚合器；聚合在完成时执行，结果写回父作用域。

### 7.4 边界事件与多实例

- 中断型边界事件作用于整个多实例：取消所有子实例，沿边界出线继续。
- 非中断型边界事件：为每个实例分别触发，还是整体触发，需按 Flowable 语义实现（默认整体触发一次，创建并发执行）。
- 多实例内部的错误：先匹配内部边界，再向外传播。

## 8. 子流程、事件子流程与调用活动

### 8.1 嵌入式子流程

1. 创建子执行（`IS_SCOPE_=true`），父执行置为非活跃。
2. 在子作用域内从 none 开始事件推进。
3. 子作用域无活跃执行时结束子执行，恢复父执行，继续出线。
4. 子作用域内的变量默认隔离；`global` 变量写流程实例。

### 8.2 事件子流程

- 在作用域启动时创建事件订阅（message/signal/timer/error/escalation/conditional）。
- **中断型**：触发时销毁作用域内所有执行，再启动事件子流程。
- **非中断型**：创建并发执行，原执行继续。
- 错误事件子流程优先于边界事件匹配；同一作用域只能有一个错误事件子流程。

### 8.3 调用活动

| 配置 | 行为 |
| --- | --- |
| `calledElement` | 按 key 取最新版本；或按 definitionId 指定 |
| `inheritVariables` | true 时复制父变量到子实例 |
| `in` | 显式入参映射（sourceExpression/target） |
| `out` | 子流程结束后映射回父 |
| `sameDeployment` | 优先在相同部署中查找 |
| `fallbackToDefaultTenant` | 子租户无定义时回退默认租户 |
| `businessKey` | 子实例业务键表达式 |
| `processInstanceName` | 子实例名称表达式 |

调用活动执行步骤：

1. 解析被调用流程定义；不存在则抛 `ENGINE-0404`。
2. 计算入参变量。
3. 创建子流程实例（`superExecution` 指向调用活动执行）。
4. 父执行等待；子实例结束后，通过 `out` 映射变量，恢复父执行。
5. 子实例删除时，父执行收到取消信号，按错误/终止语义处理。

> 调用活动是跨流程边界，必须防止循环调用；默认最大调用深度 20，可配置。

## 9. 边界事件与错误传播

### 9.1 生命周期

1. 活动进入时，若配置边界事件，创建订阅/定时器，记录 `activityId` 与 `executionId`。
2. 活动正常结束时，取消订阅/定时器。
3. 事件到达：
   - **中断型**：取消活动执行及其子执行 → 删除边界订阅 → 沿边界出线继续。
   - **非中断型**：创建并发执行 → 沿边界出线继续 → 原活动保持等待。
4. 边界事件的作用域是其依附活动的执行。

### 9.2 错误匹配

~~~mermaid
flowchart TD
    A[抛出 BPMN Error] --> B{当前作用域有匹配错误边界?}
    B -- 是 --> C[中断活动, 走边界出线]
    B -- 否 --> D{当前作用域有错误事件子流程?}
    D -- 是 --> E[启动事件子流程]
    D -- 否 --> F{父作用域存在?}
    F -- 是 --> A
    F -- 否 --> G[流程实例失败, 记录历史]
~~~

- 错误码为空表示捕获所有错误。
- 未捕获的技术异常不回滚已提交的历史；当前命令事务回滚。
- 错误边界事件执行后，原活动的补偿处理器不自动执行，除非显式抛出补偿。

### 9.3 升级（Escalation）

- 与错误类似，但语义是"非致命"；未捕获时不使实例失败，而是记录并继续。
- 用于跨子流程通知，不触发补偿。

### 9.4 取消（Cancel）

- 仅用于事务子流程：取消结束事件触发 cancel 边界，执行补偿后结束事务子流程。
- 非事务子流程使用 cancel 边界属于建模错误，部署期拒绝。

## 10. 补偿与事务子流程

### 10.1 补偿注册

- 带 `isForCompensation=true` 的活动不参与正常令牌流。
- 补偿边界事件通过 association 指向补偿处理器。
- 活动成功完成后，若存在补偿处理器，登记到当前作用域的补偿栈。

### 10.2 触发补偿

1. 抛出补偿事件（中间抛出或结束事件）。
2. 在当前作用域内查找已完成的、带补偿处理器的活动。
3. 按完成顺序**逆序**执行补偿处理器。
4. `waitForCompletion=true` 时等待所有补偿完成再继续。
5. 补偿处理器内的错误按普通错误传播。

### 10.3 事务子流程

- 事务子流程是一个作用域，内部活动完成后进入取消/补偿逻辑。
- 取消结束事件 → 取消边界 → 执行补偿 → 事务子流程结束。
- 事务子流程不等同于数据库事务；它是业务补偿边界。

## 11. 异步续跑与作业边界

| 配置 | 行为 |
| --- | --- |
| `asyncBefore=true` | 进入活动前创建作业，命令在此结束 |
| `asyncAfter=true` | 活动完成后创建作业，出线在下一个命令执行 |
| `exclusive=true` | 同一执行上的作业串行执行 |
| `failedJobRetryTimeCycle` | 覆盖默认重试策略 |

约束：

- 异步边界是**事务边界**：作业执行时重新加载执行树，不能依赖内存状态。
- 作业创建与流程状态在同一事务内，保证"要么都成功，要么都不发生"。
- 异步作业可能重复投递（至少一次语义），处理器必须幂等；流程推进通过执行状态与锁避免重复。

## 12. 挂起、删除与迁移

### 12.1 挂起/激活

- 流程定义挂起：新实例不能启动；已有实例可继续或挂起（取决于参数）。
- 流程实例挂起：任务不可完成、作业迁移到 `ACT_RU_SUSPENDED_JOB`、定时器暂停。
- 恢复时作业迁回原表，并重新计算到期时间。

### 12.2 删除

- `deleteProcessInstance(id, reason, deleteHistory)`：
  1. 校验存在。
  2. 级联删除执行、任务、变量、身份链接、事件订阅、作业。
  3. 写历史结束时间与删除原因。
  4. 发布删除事件。
- 运行中删除必须在一个事务内完成；大批量删除走批处理作业，避免长事务。

### 12.3 流程实例迁移

迁移是把运行中的实例从旧定义移到新定义，需保证活动可映射。

| 步骤 | 内容 |
| --- | --- |
| 1 | 加载源/目标定义，校验租户一致 |
| 2 | 构建活动映射（自动按 ID + 手工覆盖） |
| 3 | 校验目标活动存在、类型兼容、无多实例/调用活动限制 |
| 4 | 批量更新 `ACT_RU_EXECUTION.PROC_DEF_ID_`、`ACT_ID_` |
| 5 | 迁移任务、活动实例、变量、作业、订阅 |
| 6 | 记录迁移历史（可选） |

限制（首期）：

- 不支持跨租户迁移。
- 不支持迁移到含不同多实例配置的活动。
- 不支持迁移事件子流程内部的等待态（需先结束）。
- 迁移失败必须整体回滚，不允许部分迁移。

## 13. 兼容性陷阱清单

| 陷阱 | 正确做法 |
| --- | --- |
| 在行为中直接递归调用下一个节点 | 一律通过 Agenda 调度，避免栈溢出 |
| 在行为中提交事务 | 事务只由 Command 层控制 |
| 用 `DELETE` 物理删除执行但忘记计数 | 使用计数列或同事务重算，避免悬挂任务 |
| 并行网关汇聚条件用"入线数量" | 使用"可达且活跃"的分支集合 |
| 包容网关忽略被中断的分支 | 汇聚前重新计算可达分支 |
| 非中断边界事件复用原执行 | 必须创建并发执行 |
| 多实例完成条件满足后继续创建实例 | 先标记完成，再取消剩余实例 |
| 调用活动子实例失败被吞掉 | 明确传播为父级错误或边界事件 |
| 异步作业重复执行导致重复任务 | 作业处理器幂等 + 状态校验 |
| 删除实例只删运行表 | 同时处理历史、作业、订阅、身份链接 |
| 迁移只改 `PROC_DEF_ID_` | 同步活动 ID、任务定义、订阅、作业 |
| 依赖数据库默认排序 | 所有分页查询显式排序 |
