## 1. 架构决策记录（ADR）

### ADR-001 复用 Flowable 数据库 Schema

- **背景**：Flowable 8.x 已有成熟的 `ACT_*` 表结构与升级脚本。
- **决策**：完整复用表名、列名、索引与版本号，不新建平行 Schema。
- **备选**：
  - 全新 Schema：更干净，但迁移、报表、回滚成本高。
  - 视图适配：复杂度高，性能不可控。
- **后果**：
  - 正面：平滑迁移、工具复用、Java 回滚可行。
  - 负面：受既有列语义约束，不能随意重构；需处理 Java 序列化等历史包袱。
- **状态**： Accepted

### ADR-002 不使用 ORM

- **背景**：Flowable 使用 MyBatis + 实体缓存；Go 生态 ORM 在复杂查询与性能上不可控。
- **决策**：`database/sql` + 显式仓储 + `squirrel` 动态 SQL + 工作单元。
- **备选**：GORM、ent、sqlc。
  - GORM：隐式行为多，复杂查询难优化。
  - ent：代码生成重，动态过滤不便。
  - sqlc：静态 SQL 优秀，但 Flowable 查询高度动态。
- **后果**：SQL 可审计、可测试；需要手写更多代码。
- **状态**：Accepted

### ADR-003 自研 UEL 兼容表达式引擎

- **背景**：BPMN 条件、赋值、监听器大量使用 JUEL；三方 Go 表达式库语义不同。
- **决策**：实现 UEL 子集，自研词法/语法/求值，支持变量、属性、方法白名单、内置函数。
- **备选**：`expr-lang/expr`、`cel-go`、`govaluate`。
  - 它们不支持 Java 风格方法调用/空值语义，长期兼容成本更高。
- **后果**：前期投入约 4–6 人周；可精确控制安全与语义。
- **状态**：Accepted

### ADR-004 移植 Command + Agenda + 执行树

- **背景**：Flowable 的语义集中在这三层；重写为状态机会产生大量隐性差异。
- **决策**：保留概念与顺序，Go 化实现；行为通过注册表接入。
- **备选**：基于事件溯源/状态机重写。
- **后果**：学习曲线较陡，但兼容性最好、可对照调试。
- **状态**：Accepted

### ADR-005 脚本引擎选择

- **背景**：Flowable 支持 Groovy/JUEL/JavaScript。
- **决策**：JavaScript 用 goja，Starlark 作为确定性脚本；Groovy 不支持，给出迁移错误。
- **备选**：嵌入 GraalJS（需要 JVM/本地库，违背纯 Go）；Lua（生态弱）。
- **后果**：部分存量 Groovy 脚本需改写；安全边界更清晰。
- **状态**：Accepted

### ADR-006 ID 生成策略

- **背景**：Flowable 使用 UUID/自增；ID 列 `varchar(64)`。
- **决策**：默认 UUIDv7；可选 snowflake/sequence。
- **备选**：数据库自增、ULID。
- **后果**：时间有序、索引友好；需处理时钟回拨（UUIDv7 影响小）。
- **状态**：Accepted

### ADR-007 首期数据库

- **背景**：Flowable 支持 8 种数据库；全量适配成本高。
- **决策**：GA 支持 PostgreSQL 16 与 MySQL 8.0；MSSQL/Oracle 在 M13；H2/HSQL 仅测试不承诺。
- **后果**：覆盖主流云原生场景；传统客户需等待或使用兼容模式。
- **状态**：Accepted

### ADR-008 缓存策略

- **背景**：流程定义解析成本高，集群缓存失效复杂。
- **决策**：进程内不可变 LRU + 版本戳；集群 TTL 兜底，可选 Redis 广播。
- **备选**：集中式缓存（Redis 存模型）。
- **后果**：简单、快；跨节点短时不一致可接受（按 ID 取模型不受影响）。
- **状态**：Accepted

### ADR-009 REST 兼容策略

- **背景**：Flowable REST 有 119 个流程端点，客户端依赖字段细节。
- **决策**：以官方 OpenAPI 为契约；DTO 生成 + Handler 手写；契约测试 + Java 回放。
- **备选**：重新设计 REST（更现代，但破坏兼容）。
- **后果**：兼容性高；需要维护 Swagger 2.0 → OpenAPI 3 的转换链。
- **状态**：Accepted

### ADR-010 多租户模型

- **背景**：Flowable 使用 `TENANT_ID_` 列，默认空串。
- **决策**：所有查询强制租户过滤；`tenantId=""` 为默认租户；REST 从认证/参数解析。
- **后果**：隔离清晰；跨租户管理需显式管理员权限。
- **状态**：Accepted

### ADR-011 错误模型

- **背景**：需要区分可重试/不可重试、客户端/服务端错误。
- **决策**：统一 `EngineError` + 稳定错误码；HTTP 映射表；`errors.Is` 支持。
- **后果**：可观测、可测试；错误码需长期维护。
- **状态**：Accepted

### ADR-012 覆盖率门禁

- **背景**：AGENTS 要求 0.9 行覆盖率；引擎代码分支多、IO 多。
- **决策**：总覆盖率 0.90；核心包 0.95；排除生成代码/入口；增量 0.95。
- **后果**：测试投入大；需从设计阶段保证可测性。
- **状态**：Accepted

### 2.1 高风险应对计划

**R02（语义复杂）**：

1. M3 开始前完成包容网关/多实例/补偿的原型与设计评审。
2. 每个复杂语义建立"参考实现路径 + Go 路径"对照用例。
3. 引入外部 Flowable 专家做 2 次评审（M3、M7）。
4. 预留 2 周缓冲。

**R01（UEL）**：

1. 第 1 周建立表达式兼容矩阵（运算符/类型/方法/函数）。
2. 用 Java 生成期望结果集，Go 侧表驱动比对。
3. 不支持语法在部署期报错，不静默降级。

**R05（范围）**：

1. 阶段门禁：未通过退出标准不进入下一阶段。
2. 变更单必须说明对排期/人力/质量的影响。
3. MVP 只承诺 T0 核心，T2/T3 单独签约。

## 4. 验收标准

### 4.1 功能验收

- [ ] BPMN 元素矩阵 P0/P1 100% 实现，P2 有明确计划。
- [ ] 1,725 个参考 BPMN 文件中，解析成功率 ≥ 98%，可执行率 ≥ 90%。
- [ ] 用户任务、服务任务、脚本任务、网关、子流程、多实例、边界事件端到端可用。
- [ ] 补偿、事务子流程、事件子流程、调用活动、流程迁移可用。
- [ ] 历史六级行为与参考实现一致。
- [ ] 异步作业、定时器、外部工作项、批处理可用。
- [ ] 流程 REST 119 个路径全部实现。
- [ ] 迁移工具可扫描并报告不兼容项。

### 4.2 数据验收

- [ ] 使用 Flowable 8.x 初始化的数据库可直接启动。
- [ ] 建表/升级/回滚在 PG16、MySQL 8.0 通过。
- [ ] 32 张 BPMN 表 + 9 张身份表读写正确。
- [ ] 乐观锁、外键、唯一约束行为一致。
- [ ] Java 引擎可读取 Go 写入的数据（同一 MAJOR）。
- [ ] 迁移后流程实例可继续执行。

## ADR-015 当前原型范围与 ADR 偏差收敛

- 替代 ADR-005 的当前实施口径：脚本仅支持表达式子集，未接入 goja/Starlark；完整 JavaScript、Groovy 和 Starlark 明确拒绝。引入沙箱需要独立评审与资源限制验证。
- 限定 ADR-001/002/007/009 的当前状态：复用表名和 DDL 不代表 Java 存量互接；行模式使用 Go 续跑字节扩展，尚未实现受影响实体工作单元和查询下推。双库本地验收已完成，Java 对照及回退仍未验收。
- ADR-010 的空租户只表示引擎默认租户；REST 从可信认证身份绑定，普通用户不能覆盖；跨租户选择须显式配置授权。
- 首期只允许单执行者，MySQL 快照服务以独占会话拒绝重复实例；禁止在共享库启动 Java/Go 双写或未经仲裁的多个执行者。
- 状态：当前实施采用；生产发布仍受 003-003 的迁移退出门槛约束。
