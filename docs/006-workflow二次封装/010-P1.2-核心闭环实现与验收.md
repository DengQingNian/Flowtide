## 1. 交付内容

### 1.1 发起（start.go，对位 publishAndGetFirstTaskByKey:987）
五参校验 → isProcessDeployed（GetProcessDefinitionByKey + 租户上下文）→ 变量注入（initiator/businessKey/title/processDefinitionKey/remark + 业务变量）→ 引擎发起 → 首任务执行者解析（executorList 优先 / assignee / candidateUsers / candidateGroups 组展开）→ SaveFirstTaskUser（used=1、taskId=首任务，对位 :1142）→ TJ 意见 → TJ 操作记录 → 待办生成 → 已办镜像 → 表单落位。任一步失败补偿回滚（删实例 + 清台账）。

### 1.2 执行人重写（executor_rewrite.go，对位 TaskExecutorConfigListener）
- 门控：任务快照变量 operationType ∈ {agreeComplete, completeToTarget}；
- **架构约束（重要）**：钩子在引擎命令内同步执行，调用引擎公有 API（含 GetBpmnModel）会与写锁重入死锁——模型元数据经 **Warmup 只读缓存**读取；未命中降级保留模型默认并 Defer 延迟预热。部署新定义后应调 `RegisterExecutorRewriteHook(ctx)`（含 WarmupAll，锁外）；
- 非会签：ListUnusedByInstanceAndActivity → SetAssignee/SetCandidateUsers/SetCandidateGroups → MarkUsedAndWriteBack（used=1 + taskId 回写）；无记录保留模型默认（兜底）；
- 会签：每实例创建触发一次、按序消费恰好一条记录（版本→创建时间→记录 Id 三级排序保证确定性），executorType person/group 分支。

### 1.3 办结（complete.go，对位 generalComplete:3979）
校验链 → saveAgreeNextForComplete（Request 协议携带，end 跳过）→ 挂起拒绝 → 权重会签累计（totalWeight，weightList 指针化解析区分"未配置"与 0）→ 引擎 Complete（变量并入请求，operationType 注入触发钩子门控）→ 自由选路兜底（办结后比对实际推进节点与 TargetActivityID，不一致经 ChangeActivityState 迁移 + 落 workflow_complete_to_activity；P2.4 引擎级化前注释标注）→ 委派 PENDING 分支（克隆子任务/完成/归还/下一步还原 owner）→ 加签父任务联动（子任务全完成 resolve；scopeType=after 再 complete）→ 收尾九连（删当前 next_activity/意见/操作记录/删旧待办/已办完成时间/新待办/表单状态机）。

### 1.4 委派/转办/归还（对位 delegateTask:1793/transferTask:1848/resolveTask:1904）

## 3. 已知差异与遗留

1. 委派分支意见/操作记录挂原任务（Java 挂克隆子任务）——引擎 CreateTask 无法携带流程实例，注释登记；
2. 自由选路为"办结后迁移"兜底（Java 为办结前改内存出线），多产生一条误入分支的活动历史，P2.4 引擎级 CompleteToTarget 化；
3. 多实例执行人重写在门控变量缺失时不触发（负向测试覆盖）；
4. 引擎级 UpdateTask/Complete 等失败容错分支约 8 语句单测不可达（覆盖率 0.945 而非 1.0）；
5. 钩子 WarmupAll 按调用方租户上下文过滤定义——多租户部署场景由 REST 租户中间件逐请求懒预热自愈（Defer 机制）。
