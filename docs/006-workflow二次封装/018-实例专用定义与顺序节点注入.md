# 实例专用定义与顺序节点注入

`RuntimeService.InjectUserTaskAfter` 在一个指定运行实例的用户节点后插入新节点。原节点先办结，再生成插入节点的运行任务；新增节点办结后沿原出线继续执行。原 `InjectUserTask` 仍表示立即创建的独立任务，两者各有独立契约。

新命令在同一事务中改写独立的BPMN副本、建立实例专用派生定义并切换运行和历史引用。转移原条件出线，保留命名空间、节点扩展、监听器及同一子流程作用域。源模型及其他实例不改写。派生序号按流程键、普通版本及租户的唯一键分配；派生定义不参与普通最新版本选择，不允许用于发起新实例或被其他实例迁入。派生XML与来源信息通过标准ACT部署、字节数组、定义和运行历史行恢复，不需要新增数据库列。

命令拒绝不匹配的预期定义、挂起/结束实例、非用户节点、空白字段、重复节点ID和跨租户访问。命令或落盘失败回滚全部状态。图形坐标与BPMN业务结构分别维护：保留已有图形信息，本命令不重新布局。

兼容 `POST /workflow/process/inject/node` 接收 `userTaskId`、`name`、`assginee`、`processInstaceId`、`processDefinitionId`，也接受正确拼写的 `assignee`、`processInstanceId`。成功HTTP 200空体，参数或业务失败遵循工作流错误信封。租户取可信上下文。接线后95条工作流路由中85条已接线，10条仍是501占位。

验证覆盖原任务办结顺序、其他实例隔离、派生唯一性、按键及按ID发起保护、持久化失败回滚、前缀与条件出线、跨租户、旧DTO和真实MySQL关停重启后续办。标准行使用现有 `DERIVED_FROM_`、`DERIVED_FROM_ROOT_`、`DERIVED_VERSION_` 字段，不自动执行DDL。

用户任务声明的 `default` 出线由XML解析器标记为默认流。验证插入后条件命中只走匹配边，条件未命中才使用默认边。
