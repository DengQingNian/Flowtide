# 013 P5.B 审阅影子任务与流程图高亮实现记录

> 对应交付：`internal/workflow/review.go`（审阅影子任务）、`internal/workflow/highlight.go`（流程图高亮）、
> `internal/workflow/review_sql.go`（SQL 适配器）及三个测试文件。表结构依据 003 文档
> §workflow_review_task / §workflow_act_extend。

## 1. 审阅影子任务（workflow_review_task）

### 1.1 实体与状态

- `ReviewTask`：字段对齐 003 表结构（start_time/task_id/task_name/process_instance_id/
  process_definition_id/task_key/business_key/process_name/process_definition_key/_name/
  sender/_name/reviewer/review_time/remark/opinion/tenant_id/status + BaseColumns 审计列）。
  列名映射约定：`sender` 列存发送人身份 Id、`sender_name` 存姓名（对齐 creator/creator_name
  的"值/名"约定）；`process_name` 存实例名称（与 process_definition_name 区分）。
- `ActExtend`：workflow_act_extend 审阅人绑定（activity_id/activity_name/
  process_definition_key/owner_type/owner_value/step_id）。
- 状态常量：`ReviewStatusPending=0`（待审阅）、`ReviewStatusDone=1`（已办结，对齐线上语义）、
  `ReviewStatusUnresolved=2`（待解析，Go 侧扩展：org/role 展开失败时 reviewer 保留原组/角色值）。
- owner_type 常量：`ActOwnerTypePerson/Org/Role`（person/org/role）。

### 1.2 端口与实现

| 端口 | 方法 | 内存实现 | SQL 适配器 |
| --- | --- | --- | --- |
| ReviewTaskStore | Insert/Get/Update(办结回写)/ListByReviewer(分页)/ListByInstance/DeleteByInstance/CountUnread | MemReviewTaskStore | SQLReviewTaskStore |
| ActExtendStore | GetByDefinitionKeyAndActivity/ListByDefinitionKey/Save/Delete | MemActExtendStore | SQLActExtendStore |

- SQL 适配器复用 `store_sql.go` 的 sqlCore 共享内核；`ListByReviewer`/`CountUnread`/
  `ListByDefinitionKey` 在 pwf 仓储暂无对应方法，经裸 SQL 只读下推补齐（需要连接池，
  经 `NewSQLReviewStoresWithDB(store, db)` 注入，缺池时明确报错）。
- `Update` 办结回写按主键更新 status/opinion/review_time/remark/updater/update_time，
  review_time 为 nil 时显式置 NULL；主键不存在影响 0 行（与 SQL UpdateByPK 语义一致）。
- 未读计数只统计 status=待审阅（0）；待解析（2）不计入，由业务系统二次解析后重新同步。

### 1.3 服务（ReviewTaskService）

- `NewReviewTaskService(engine, tasks ReviewTaskStore, extends ActExtendStore, c clock.Clock)`。
- `SyncForTask(ctx, task *api.Task, senderID, senderName)`：
  1. 定义解析（RepositoryService.GetProcessDefinition）；
  2. 按（定义 Key + task.TaskDefinitionKey）读取 act_extend 绑定，无绑定返回空列表；
  3. 逐绑定解析审阅人：person 直用 owner_value（空 owner_type 按 person 兼容）；
     org/role 经 `IdentityService().ListMembers` 展开，**查询报错或展开零成员视为展开失败**，
     保留原值并置 status=待解析；
  4. 幂等键 = task_id + reviewer（同实例既有记录 + 本批次展开结果统一去重），
     重复调用不产生重复影子任务；
  5. 实例信息（business_key/process_name）运行态优先、已结束回退历史，双查失败报错。
- `Complete(ctx, reviewTaskID, opinion, operator)`：回写 review_time/opinion/status=已办结，
  operator 非空时回写 updater；影子任务不存在报 WORKFLOW-3002。
- 查询：`ListByReviewer`（分页 + 租户过滤，空租户不过滤）/`ListByInstance`/
  `CountUnreadByReviewer`/`Get`。

### 1.4 错误码（30xx 段专用）

| 码 | 含义 |
| --- | --- |
| WORKFLOW-3001 | 审阅同步/办结参数缺失或引擎未注入 |
| WORKFLOW-3002 | 审阅影子任务不存在 |
| WORKFLOW-3003 | 流程定义不存在 |
| WORKFLOW-3004 | 流程实例不存在（运行态与历史双查失败） |

## 2. 流程图高亮（HighlightService）

### 2.1 数据结构 HighlightData

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| CompletedActivityIDs | HistoryService.ListHistoricActivityInstances | 历史活动去重；取 EndTime 非空的**节点**，sequenceFlow 连线剔除（连线由 TakenFlowIDs 单独表达） |
| ActiveActivityIDs | RuntimeService.ListActivityInstances | 运行态活动（EndTime 为空）去重；已结束实例为空。说明：引擎 ListActivityInstances 直接可用，无需"当前任务所在 activity"近似；并行分叉网关执行仍活跃时会一并返回（以引擎运行态为准） |
| TakenFlowIDs | BPMN 拓扑推断 | 连线两端 activity 都已出现于历史则视为已走；子流程内部连线递归纳入（hlCollectTakenFlows） |
| TodoActivityIDs | TaskService.ListTasks | 当前待办任务 taskDefinitionKey 去重；已结束实例为空 |

- 全部列表去重 + 字典序排序，多次查询输出稳定（断言与前端快照友好）。
- 已结束实例回退全历史：运行态查不到（SQL 引擎 404）回退历史实例并视为已结束；
  内存引擎已结束实例运行态仍可查，按 `Ended` 标记判断。回退时 Active/Todo 为空、
  Completed 取全部历史节点。
- BPMN process 定位：优先按定义 Key 匹配 process id，回退首个流程。

### 2.2 入口与错误码

- `NewHighlightService(engine)`；`FlowHighlight(ctx, processInstanceID)` /
  `FlowHighlightByTask(ctx, taskID)`（先解析任务归属实例）。
- 31xx 段：3101 参数缺失/引擎未注入、3102 实例双查不存在、3104 BPMN 模型读取失败、
  3105 任务不存在。

## 4. 接线注意事项（主线程装配）

1. 门面装配（facade.go components）建议新增两个字段：`reviews *ReviewTaskService`、
   `highlights *HighlightService`。
2. 内存模式：`NewReviewTaskService(engine, NewMemReviewTaskStore(c), NewMemActExtendStore(), c)`
   （MemActExtendStore 无时钟参数）；SQL 模式：`set := NewSQLReviewStoresWithDB(store, db)` →
   `NewReviewTaskService(engine, set.Tasks, set.Extends, c)`。db 为 nil 时
   ListByReviewer/CountUnread/ListByDefinitionKey 不可用（报 SQL-ADAPTER-001）。
3. 高亮服务无存储依赖：`NewHighlightService(engine)` 直接装配。
4. 触发时机建议：任务创建全局钩子（TASK_CREATED，对位 `AddTaskCreatedHook`）内调用
   `SyncForTask(ctx, task, senderID, senderName)`；实例删除/级联清理处调用
   `ReviewTaskStore.DeleteByInstance`。
5. 命名隔离：本批新增辅助函数均带 rv/hl 前缀（rvCloneReview/rvCloneActExtend/
   hlSortedKeys/hlSortStrings/hlCollectTakenFlows/hlSequenceFlowType/hlTaskQuerySize），
   错误码占用 30xx/31xx 段，均不与既有文件冲突。
