# 宿主嵌入 SDK 与验证记录

日期：2026-11-01。基线：已有 workflow 业务封装实现。状态：公共 SDK、外部模块验证及隔离 MySQL 发起办结验证已完成；原 Java 存量库切换未执行。

## 一、目标与边界

Go 业务系统可直接复用 Flowtide 的 BPMN 内核和已经实现的 workflow 二次封装，无需在宿主重复实现审批逻辑。根包原先只导出内存/状态文件引擎构造，SQL 行仓储、workflow 门面和 REST 装配都位于 internal 包，仓库外调用方无法完成生产接线。本次补齐这些公共装配入口。

本次不宣称解决 016 号审计中的引擎命令与 workflow 多表统一事务、全部 SQL 业务规则、Java 存量兼容、集群或反向回退问题。SQL 发起后的补偿边界沿用现有实现。

## 二、公共接口

| 接口 | 用途 |
| --- | --- |
| `NewEmbedded(ctx, EmbeddedConfig)` | 构造完整 SQL 或显式内存运行时 |
| `Embedded.Engine()` | 获取 `api.Engine` 原生服务 |
| `Embedded.Workflow()` | 获取 `api.WorkflowFacade` 业务门面 |
| `Embedded.Handler()` | 获取已注入真实 workflow 服务的 HTTP Handler |
| `Embedded.RunDueJobs(ctx)` | 由宿主驱动到期作业 |
| `Embedded.Close(ctx)` | 先关闭内核，再释放数据库写者锁，幂等且保留首次错误 |
| `WithExecutionContext(ctx, tenantID, actorID)` | 注入宿主已认证的业务租户和办理身份，不执行认证 |
| `EnsureMySQLSchema(ctx, db, initialize)` | 只读核验，或在显式允许时初始化引擎及 workflow 结构 |

`EmbeddedConfig.DB` 的所有权属于宿主，关闭 SDK 不关闭连接池。`Database` 必须与连接实际库名一致。生产不允许缺连接后回退内存；只有 `InMemory=true` 才启用内存，且与数据库配置互斥。连接池最大连接数为一时拒绝启动，避免持锁会话占满连接池。

`DecorateIdentity` 接收内核原身份服务，返回宿主装饰后的 `api.IdentityService`，公共引擎、workflow 门面和 HTTP 共用该身份视图。具体内核扩展方法及事件钩子通过嵌入具体 Engine 保留，避免会签监听器因接口包装而丢失。

## 三、生产装配顺序

1. 校验配置与实际库名。
2. 只读校验已有 ACT 与 workflow 结构、版本及独立完成标记；不自动建表。
3. 获取与独立服务一致的全库单写者锁；拒绝与另一行模式或快照模式写者共存。
4. 拒绝混用快照数据，构造 ACT 行仓储、workflow 行仓储并恢复引擎状态。
5. 使用新增严格构造器 `NewWorkflowServiceChecked`，SQL 装配失败返回错误。
6. 注册执行人重写、会签运行时和业务回调三组钩子；预热失败终止启动。
7. 构造 HTTP Handler。端口监听、认证、授权、开放路径和作业循环由宿主管理。

引擎新增 `Config.StartupContext`，将嵌入初始化上下文传递到状态加载与行恢复，避免恢复阶段使用 Background 绕过宿主超时。完成初始化后不保留该上下文。

## 四、验证

- 先新增公共 SDK 测试并确认缺失符号导致失败，再实现入口。
- 单测覆盖配置冲突、实际库名不一致、单连接池、结构失败、写者锁冲突、快照拒绝、恢复错误、关闭错误及锁释放、重复关闭、身份装饰与取消初始化。
- 根包普通单测语句覆盖率 94.0%，达到 90% 要求；真实 MySQL 验证另行运行。
- `testdata/sdk` 独立模块验证门面与 HTTP 入口，无 internal 包导入。
- 隔离临时 MySQL 库验证：完整结构初始化、门面发起与办结、workflow 扩展行落库、任务停启恢复、重复写者拒绝及宿主连接池保留。临时库由测试创建并清理。
- 全仓普通测试通过，中文函数注释门禁、静态检查随交付复核。

Windows 命令示例：

```powershell
$env:GOOS='windows'
go test ./... -count=1 -p=2
go test . -count=1 -coverprofile=tmp/embedded-unit.out
go run ./tools/quality -doccheck
go vet ./...
Push-Location testdata/sdk
go test -mod=mod ./... -count=1
Pop-Location
```

真实库测试设置 `FLOWABLE_MYSQL_INTEGRATION=1`，从开发配置或环境变量读取连接，只在本次创建的 `flowtide_embed_it_*` 临时库写入。

## 六、存量迁移边界

SDK 可嵌入与存量数据库可迁移分别验收。接入方应在自身工程维护源库预检、版本差异、变量类型、扩展数据、双端回放、停写与回退演练记录。Flowtide 仅维护通用接口、兼容性边界和不含接入方信息的测试。
