# 006 系列文档之十三：P2-C/P3/P4/P5 门面统一接线实现记录

> 承接：010（P1.2 核心闭环）、011（P3.A）、012（P2.B）。
> 范围：阶段 0 桩 → 全量门面接线（引擎能力 + 域服务 + 调度器），REST 路由切换与 P5 集成另行记录。

## 1. 装配结构

`components`（internal/workflow/facade.go）在 P1.2 基础子服务之上扩充能力子服务，统一由
`assembleCapabilities`（facade_ops.go）装配，内存模式与 SQL 模式各传一套存储族：

| 子服务 | 构造来源 | 存储依赖（内存 / SQL） |
| --- | --- | --- |
| steps / StepRuleService | steprules.go | MemStepStore / SQLStepStore（his_step 快照） |
| back（退回） | back.go | 复用基础子服务 + steps |
| direct（直送） | direct.go | 复用基础子服务 + completeTo |
| reset（重置） | reset.go | 复用基础子服务 |
| rollback（撤回） | rollback.go | 复用基础子服务 |
| terminate（软终止/挂起/重激活/删除） | terminate.go | 复用基础子服务 |
| addSign（加签减签） | addsign.go | 复用基础子服务 + WithAddSignUsers |
| counter（会签） | countersign.go | 引擎 + meta |
| delegate（委托规则） | delegate.go | MemTaskDelegateStore+MemDelegateTaskMirrorStore / SQL 对应适配器 |
| remind（催办） | remind.go | MemRemindStore+MemRemindTargetStore+MemTodoSource / SQL 对应（TodoSource 暂空源） |
| exception（任务异常） | exception.go | MemTaskExceptionStore / SQLTaskExceptionStore |
| simulate（下一步推演器） | simulate.go | 基础子服务 + WithSimulateSteps |
| scheduler（调度器） | schedulers.go | TodoSource/Rules/Complete/Next/Back/Remind/Exceptions 注入 |

## 2. 门面方法（阶段 0 桩替换 + 新增）

- **桩替换**：BackToStepTask、BackTask、DoRollbackTask、CompleteToTargetActivity、DoResetProcess、GetNextUserTaskAndUserList。
- **P2.C**：DoStopProcessInstance、DoStopTaskByTaskID、DoDeleteProcessInstance、DoDeleteProcessByBusinessID、DoSuspendProcessInstance、DoActivateProcessInstance、DoReactivateProcess（原实例复活，ID 不变）。
- **P3.A**：AddExecution、DelExecution（DTO 上移 api 包，workflow 包别名兼容）、AddMultiInstanceMember、RemoveMultiInstanceMember、CompleteSign。
- **P5.B**：GetNextUserTaskAndUserListByKey。
- **P4**：Add/Edit/Delete/List/Enable/Disable/RetireDelegateTask、Add/Edit/Delete/Get/GetRemindPageList Remind、ListTaskExceptions、HandleTaskExceptions。
- **辅助**：GetBackNodes（可退节点）、StartSchedulers/StopSchedulers（调度器生命周期，宿主显式调用）。

`api.WorkflowFacade` 契约同步扩充（除委托/催办 CRUD 外，后两者为 internal 域类型，保留在 *Service 上由 REST 直接消费）。

## 5. P5 集成（模型/步骤/模板/快照/审阅/高亮）

`facade_mgmt.go` 承载 P5 集成门面，装配于 `assembleCapabilities`：

| 门面方法 | 能力 |
| --- | --- |
| Add/Edit/Delete/List/GetModelCategory、GetModelCategoryTree/ByCode/ByID | 模型/分类一表两用 CRUD 与树投影 |
| Add/Edit/Delete/ListStepDesignByModel | 设计时步骤（workflow_step）管理 |
| Add/Edit/Delete/ListTemplateDefs | 设计器模板（workflow_template）管理 |
| DeployModel(tenantID, modelID) | 部署链路：引擎模型源 → 引擎部署 → SnapshotForDeploy 步骤快照 → 最近部署时间回写 |
| ListHisSteps(deploymentID) | 运行期规则字典只读 |
| Sync/Complete/Get/ListReviewTasksByReviewer/ByInstance、CountUnreadReviews | 审阅影子任务（workflow_review_task） |
| GetFlowHighlight / GetFlowHighlightByTask | 流程图高亮数据（已走/在途/待办节点 + 已走连线） |

装配要点：hisSteps 单实例同时满足 `StepStore` 超集语义——推演规则读取与快照写入必须同源，
否则出现"快照写入成功、规则查询为空"的读写分离缺陷（已在集成测试覆盖）。
