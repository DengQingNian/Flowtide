## 1. BackUserTaskCmd 逐段解剖（JAVA\process\cmd\BackUserTaskCmd.java，210 行）

### 1.1 主流程 execute (L48-153)
1. 校验 targetActivityId 非空（L49）；取 TaskEntity（L54），sourceActivityId=task.getTaskDefinitionKey()（L58）。
2. source 必须是 UserTask（L64）；目标到当前必须可达 FlowUtils.isReachable(process, target, source)（L69，不满足抛 "Cannot back to"）。
3. **子流程内外映射** FlowUtils.getSourceAndTargetRealActivityId（FlowUtils.java L666-681）：
   - 对 source/target 各取 getParentProcessIds（L715-732）：沿 ParentContainer 上溯收集 SubProcess/Process id，reverse 后第 0 层=主 Process。
   - getDiffLevel（L741-770）求两链首个分叉层级：等长且全同→-1（同层）；否则返回分叉下标，一方是另一方前缀时返回 minSize（浅方自身长度）。
   - diffLevel==-1 → 原样返回；否则 sourceReal = (sourceList.size()==diffLevel) ? source 自身 id : sourceList[diffLevel]（提升到分叉处容器 id），target 同理。
   - 主流程 generalBack 另有分支：目标在子流程内、当前不在时，取 parentId(processInstanceId) 的全部 execution 调 moveExecutionsToSingleActivityId（ProcessesUtil.java L2607-2619）。
4. **特殊网关识别** getSpecialGatewayElements（FlowUtils L683-713）：后缀约定 `_begin`/`_end`（FlowConstant.java L40-41）。算法：遍历容器元素，id 以 `_begin` 结尾且是 Parallel/Inclusive/ComplexGateway → 剥后缀得 gatewayId，findElementsBetweenSpecialGateway（L829-845）从 _begin 沿 outgoing 深度优先收集途经元素 id（含 _begin 与目标 _end，遇 _end 先 add 再停）；SubProcess 递归。按包含元素数降序排列（外层在前，L709-712）。
5. **四分支**（execute L93-138；setSpecialGatewayList L155-167 收集 source/target 落在哪些 gateway 集合）：
   - 分支1 双方都不在并行块内：sourceRealActivityIds={sourceRealActivityId}（L95）。
   - 分支2 目标不在、当前在：取当前节点最内层（包含元素最少者）整块元素集合（L99）。
   - 分支3 目标在、当前不在：**直接抛"并行流转已结束，不允许退回"**（L102-104）。
   - 分支4 双方都在：getDiffLevel（L111）；==-1（同块同分支）→ 单点；否则 source 侧在块外层→单点，否则取 sourceList[diffLevel]；target 侧在块外→不处理，否则 targetRealSpecialGateway=targetList[diffLevel]（L131-136），退回后补 _end 汇聚 execution。
6. **execution 收集** getRealExecutions（L194-210）：
   - findChildExecutionsByProcessInstanceId 取全量；
   - getParentExecutionIdsByActivityId（FlowUtils L772-805）：按 sourceRealActivityId 找活动 execution；**多实例特殊处理**——存在 MultiInstanceRoot 执行则只取 root 的 parentId，否则取首个 execution 的 parentId（L791-803）；
   - getParentExecutionIdFromParentIds（L847-861）：从 task 的 execution 沿 parent 链上溯找第一个命中 parentExecutionIds 的祖先；
   - findExecutionsByParentExecutionAndActivityIds(realParentExecutionId, sourceRealActivityIds) → realExecutions（同一父作用域下落在需重算节点集合里的全部 execution）。
7. 迁移（L144-146）：moveExecutionsToSingleActivityId(realExecutionIds, targetRealActivityId).changeState()——**N 条 execution 汇到单目标**。
8. targetRealSpecialGateway != null → createTargetInSpecialGatewayEndExecutions（见 1.2）。

### 1.2 createTargetInSpecialGatewayEndExecutions（L169-192）
- realExecutions 首个的 parentId 为 parentExecutionId（L174-176）。
- 从 targetRealSpecialGateway 下标开始**逐层向外**循环（L178-179）：拼 `_end` 节点 id，nbrOfExecutionsToJoin=_end.getIncomingFlows().size()（L183）；循环 nbrOfExecutionsToJoin-1 次：createChildExecution(parentExecutionEntity)、setCurrentFlowElement(_end)、**直接调用 _end 的 ActivityBehavior.execute(childExecution)**（L185-190）——伪造"其余分支已到齐"的汇聚信号。

### 1.3 入口包装
- generalBack（ProcessesUtil.java L2557-2637）：saveBackToStepNextActivity 预存 → allowReturn=0 拒绝（L2584）→ 暂停校验（L2590）→ getNextActivitys 收集全部后继+目标，删 ACT_RU_ACTINST/ACT_HI_ACTINST（L2594-2604）→ 子流程分支判定 → addComment(TH)/操作记录/删下一步/删待办/更新已办/新增待办（L2621-2634）。

## 2. 撤回（Rollback）策略族

### 2.1 入口 RollbackCmd（L61-113）
taskId 查 HistoricTaskInstance（L69）；endTime==null 拒绝（L77）；assignee 缺省取历史办理人（L84-89）；实例必须运行中（L97-102）；factory.createStrategy(hisTask) → setAssigneeExpr("executor","executorList") → strategy.process(commandContext, assignee)。

### 2.2 工厂（process\bean\DefaultRollbackStrategyFactoryBean.java）
RollbackParamsTemplate：hisTask、currentTaskElement、nextFlowIdList(Set，含连线id+节点id)、outGoingMap、nextUserTaskList、gatewayMap、subProcessMap、callActivityMap、currentSubProcess。
- createStrategy（L40-64）：getThisUserTask 先主 Process 后 SubProcess（L217-242）；**直送记录**（workflowCompleteToActivityService.getNextElementByHisTask，L51）追加进 nextFlowIdList/nextUserTaskList；getNextElementInfo（L160-208）沿 outgoing 递归收集。
- **策略选择伪代码**（createStrategyInstance L96-151，顺序即优先级）：

```
if currentMultiInstanceTaskUnfinished(t):   return ActiveMultiInstanceTask...
if loopChar==null && gatewayMap空 && nextUserTaskList非空: return NextDefaultUserTask
if loopChar==null && gatewayMap空 && subProcessMap非空:   return NextSubProcess
if loopChar==null && gatewayMap空 && callActivityMap非空: return NextCallActivity
if loopChar==null && gatewayMap非空:                      return DefaultTaskNextGateway
if loopChar!=null && gatewayMap空 && nextUserTaskList非空: return CompletedMultiInstanceTaskAndNextDefaultTask
return null
```

### 2.3 模板方法 AbstractRollbackOperateStrategy.process（L64-80）
1. **existNextFinishedTask**（L140-158）：历史任务 proc_inst=pi and end_time_>hisTask.endTime and task_def_key_∈nextFlowIdList → 抛"任务已被处理，无法进行流程节点撤回"。
2. **setAssignee**（L221-225）：变量键 `ROLLBACK_ASSIGNEE_PREFIX_+piId+taskDefKey`；多数子类再放 `ROLLBACK_TASK_TYPE_PREFIX_+piId+actKey=策略类SimpleName`（提交后由全局监听消费）。
3. **createExecution**（默认 L128-137）：newExecution.setActive(true)、setVariablesLocal、setCurrentFlowElement(currentTaskElement)，agenda.planContinueProcessInCompensation。
4. **deleteRuntimeTasks**（L197-218）：piId 全部运行任务，taskDefinitionKey∈nextFlowIdList → removeRuntimeTaskOperate（L116-125：删 IdentityLinks、deleteVariablesByExecutionId、deleteTasksByExecutionId、删 execution）；历史任务同 key → deleteHistoricTask。
5. **deleteHisActInstance**（L161-194）：piId 活动历史，删 startTime>hisTask.createTime 且 actId∈nextFlowIdList 的行 + actId==hisTask.taskDefKey 且 endTime>createTime 的行；自写 mapper.delete（L192）。
6. 辅助 getExecutionEntity（L86-104）：按 hisTask.executionId 找 execution，找不到按 piId+nextFlowIdList 搜现存取第一个；removeHisTask（L106-110）。

## 4. Go 引擎能力对照与缺口

### 4.1 现有原语（GO）

- **agenda**（agenda.go）：仅 continueOperation 与 takeOutgoingOperation 两种操作（runtime.go L176/L423），串行+maxSteps。**无 planContinueMultiInstanceOperation 等价物**——多实例推进统一走 takeOutgoing→finishMultiInstanceChild（runtime.go L1351-1391）。

- **并行网关**：handleParallelGateway（L649-654）+ joinBranches（L661-677）：到达子执行置 Ended，parent.PendingBranches--，归零后父执行从网关继续。**Go 无 _begin/_end 模型约定**，但 join 行为语义等价。
- **ChangeActivityState**（change_state.go L15-94）限制：①仅单目标（L55-57）；②根执行兜底要求恰好一个活动子执行（L34-50）；③迁移前对 descendantsOf 全量清场（cancelExecutionTasks+cancelBoundaryTimers+removeSubscriptionsForExecution+recordActivityEnd，L76-86）——等效"清场"但**只移动单条 execution 及后代，不支持多条兄弟 execution 一起迁移**；④不补造汇聚 execution、不改 PendingBranches。
- **ChangeProcessInstanceState**（L101-120）：取第一个 ParentID=="" 的根执行转调——实例多并行分支时报 ENGINE-0663。
- **任务**：createUserTask（task.go L21-86）；cancelExecutionTasks（change_state.go L126-138）：recordTaskLog+recordTaskEnd+DeleteReason+删任务；Complete（task.go L459/471）。
- **变量**：setVariable（engine.go L435，向上找作用域）、setVariableLocal（L468）、variablesOf（L479）；公有 SetExecutionVariable（variable_ops.go L46）。nrOf* 三计数与 loopCounter 由 enterMultiInstance/finishMultiInstanceChild 维护（L1242-1244/L1359-1365）。

## 5. Go 实现方案建议

### 5.1 引擎层（internal/engine/workflow_ext.go，全部 e.execute 风格）
- BackUserTaskToActivity(ctx, taskID, targetActivityID) (string, error)：
  1) 校验 source UserTask + IsReachable(G2) + getSourceAndTargetRealActivityID(G3)；
  2) 四分支 sourceRealActivityIds / targetRealSpecialGateway；
  3) realExecutions := findActiveExecutionsByActivityIDs(G8) + 多实例 root 归并；
  4) moveExecutionsToSingleActivity(G1)；
  5) targetRealSpecialGateway != nil: createJoinBranchExecutions(G4)。
- RollbackTask(ctx, taskID, assignee) error：工厂判定（§2.2 伪代码）→ 内部函数 rollbackExistNextFinishedTask / rollbackSetAssigneeVars（变量键与 Java 逐字一致：`ROLLBACK_ASSIGNEE_PREFIX_+pi+actKey`、`ROLLBACK_TASK_TYPE_PREFIX_+pi+actKey`）/ rollbackCreateExecution / rollbackDeleteRuntimeTasks / rollbackDeleteHisTaskAndActs(G7) / rollbackActiveMultiInstance(G5) / rollbackCompletedMultiInstance(G6) / rollbackGateway（processGateway 双态）。
- Go 侧撤回可不做策略对象，工厂判定后直调内部函数；变量键必须与 Java 完全一致（下游监听兼容）。

### 5.2 workflow 层
- BackTask/BackToStepTask：SaveBackToStepNext → hisStep allowReturn 校验 → 引擎 BackUserTaskToActivity → NextActivityService.DeleteByProcessInstanceAndActivityIDs + HistoryExtendService.DeleteByProcessInstanceAndActivityIDs + UpdateFinishTime；goBackNodes 计算放 workflow/backnodes.go（引擎 QueryHistoricActivityInstances finished + G2）。
- DoRollbackTask：引擎 RollbackTask + NextActivityService.DeleteForRollback。
- CompleteToTargetActivity：直接 G1 迁移（不需要 Java 改出线黑科技）+ workflow_complete_to_activity 落库（撤回工厂依赖）。
- DoResetProcess：见 §6。

### 5.3 风险点
1. **并行汇聚卡死**：G1 清场后 parent.PendingBranches 必须与新造 join execution 数自洽——迁出后按"块内已迁移分支数"重算 parent.PendingBranches = len(incoming) - 1，再由 G4 补其余。
2. **多实例计数修正**：nrOf* 是父执行局部变量（runtime.go L1242-1244），修正必须落在正确的 MI root；MIValues 顺序与 assigneeList 对齐；串行"前一位"校验依赖 MIIndex==completed（finishMultiInstanceChild L1386-1388），回退后 index 语义重新对齐。
3. **历史一致性**：recordTaskStart 按 ActivityID+TaskID=="" 回填活动历史（history.go L155-160），多实例同 key 多行会错配；G7 删除须同时处理 HistoricLinks/TaskLogs/Details；ChangeActivityState 清场只 recordActivityEnd 不写删除原因，撤回语义建议直接删行（对齐 Java mapper.delete）。
4. **命令原子性**：所有修改必须在单个 e.execute 命令内（快照回滚保证），撤回"建新+删旧+删历史"不可拆多次公有 API。

## 6. 重置 / 直送 / 终止的最小 Go 等价路径
