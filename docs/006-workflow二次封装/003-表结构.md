# 006 系列文档之三：workflow_* 表结构设计

> 21 张保留表 + 1 张新增表（workflow_business_system）= **22 张**（对齐开发计划 §3.3 保留清单枚举；该计划标题"29 → 24 张"中 24 为笔误，以清单为准）。字段语义来自调研 002 文档（表结构），DDL 落地于 `internal/persistence/schema/sql/{mysql,postgres}/002-workflow-1.0.sql`。
> 类型约定：id/creator/updater/tenant_id 等用 varchar(64)（Go idgen 字符串 ID，替代 Java Long 雪花，兼容前端无精度问题）；时间 datetime（PG timestamp）；decimal(10,2) 用于权重/比例；tinyint/smallint（PG smallint/int）用于 0/1 标记。

## 2. 公共列（除 workflow_remind/remind_target 自带 creator 外全部包含）

`id varchar(64) PK`、`creator varchar(64)`、`creator_name varchar(128)`、`create_time datetime`、`updater varchar(64)`、`update_time datetime`、`tenant_id varchar(64)`；document/remind/remind_target 另有 `deleted tinyint default 0`（手工过滤）。

## 3. 索引（最低集）

- next_activity：(process_instance_id, next_activity_id, used)、(task_id)、(pre_task_id)；his_next_activity 同构 + (process_instance_id, task_id, version)
- task_message_extend：task_id 唯一、(process_instance_id)、(business_id, tenant_id)、(owner_id)
- task_history_extend：task_id 唯一、(process_instance_id)
- document：(business_id, tenant_id) 唯一、(flow_instance_id)
- operation_record：(task_id)、(business_id)
- his_step：(deployment_id)、(model_id)
- task_delegate：(owner_id)、(source_code)；consigners/consign_obj：(delegate_id)
- remind：(pid)；remind_target：(pid)
- task_exception：(handle_status)（异常处理状态列，Go 新增）、(process_instance_id)
- business_system：system_symbol 唯一
- model：(model_code, tenant_id) 唯一、(parent_id)

## 4. DDL 落地要求

1. 文件：`internal/persistence/schema/sql/mysql/002-workflow-1.0.sql` 与 `postgres/002-workflow-1.0.sql`，表名/列名一致，仅类型与占位差异；
2. `internal/persistence/schema` 的 embed 模式（`sql/*/*.sql`）自动纳入；EnsureSchema 需支持多文件按序执行（001 引擎表 → 002 workflow 表），workflow DDL checksum 独立计算（文件名区分）；
3. 双库集成测试：FLOWABLE_MYSQL_INTEGRATION / FLOWABLE_POSTGRES_INTEGRATION 环境下执行 DDL 并抽查建表；
4. 引擎 ACT_* 行仍由引擎差分持久化管理，workflow 仓储独立连接复用（同一 *sql.DB）。
