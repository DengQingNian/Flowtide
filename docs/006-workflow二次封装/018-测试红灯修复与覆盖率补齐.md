# 测试红灯修复与覆盖率补齐

日期：2026-11-01。基线：v0.1.1 发布后 master（3c587ca）。状态：两处既有测试失败与三条覆盖率门禁缺口已修复，`make cover`、`make lint` 全绿。

## 一、问题

文档站发布流水线在 master 上执行 `make cover` 失败，暴露三件事：

| 现象 | 根因 |
| --- | --- |
| `TestChecksumStable`：MySQL 引擎校验和与基准不一致 | 基准常量在 016 号审计整改中被改成按 CRLF 内容计算的哈希（`b684…`/`6a0f…`），而仓库统一 LF，001 脚本自 0644acf 引入后从未改动，实际值为 `f8a484…`/`f57f3c…` |
| `TestSchedulerTriggerFunctions`：`timeout=171100` | 超时提醒用注入的固定假时钟（2026-10-31 08:00 UTC）计算 `time.Until`，再交给真实 `time.Timer`；当假时钟早于真实时间时等待时长为负，定时器立即触发并不断重排，形成忙循环 |
| 覆盖率门禁失败：`api` 36.8%、`bpmn/model` 80.2%、`internal/workflow` 86.9% | 10 月 31 日合入的 workflow 二次封装、公共 VO 与模型扩展缺少对应单测，逐包 0.90 门禁不达标 |

测试失败与覆盖率门禁此前互相遮蔽：`go test` 先失败，门禁工具根本没执行。

## 二、修改

1. **校验和基准**：恢复为 001 脚本 LF 原始字节的 SHA-256（`f8a484…` / `f57f3c…`），并在注释中写明 `Checksum` 不做归一化、可用 `sha256sum` 复核。
2. **调度器计时**：超时提醒的等待时长改由真实时钟计算（`timeoutWaitDuration`），新增同包 `timeoutWait` 注入点供测试固定等待时长；`time.Timer` 只认真实流逝时间，注入时钟不再参与定时器时长计算。新增 `TestTimeoutWaitDuration` 锁定"注入时钟滞后时等待时长仍为正"。
3. **覆盖率补齐**：新增四个测试文件，全部使用固定假时钟与 sqlmock，不依赖真实时间、网络或数据库：
   - `api/workflow_test.go`：会签结论"未传/显式 0/显式 1/null"解析语义、统一返回结构。
   - `bpmn/model/model_test.go`（追加）：扩展属性/字段读取、元素类型、容器查询未命中。
   - `internal/workflow/store_sql_cover_test.go`：五大 SQL 存储适配器与行转换的语句拼装、参数、错误码。
   - `internal/workflow/facade_cover_test.go`：门面薄封装的成功与守卫分支。
   - `internal/workflow/simulate_delegate_cover_test.go`：流程图推演、代理人、催办的内存实现与边界分支。
4. **格式**：补齐 `cmd/flowtide-server/storage.go` 与 `internal/rest/workflow_routes_accounting_test.go` 的 gofmt 差异（既有问题，阻塞 `make lint`）。
