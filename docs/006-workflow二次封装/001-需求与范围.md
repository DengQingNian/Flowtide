# 006 系列文档之一：workflow 二次封装需求与范围

> 本系列文档是 Flowtide（Go）实现"复杂流程二次封装"（对标 example-base-workflow）的项目文档。
> 规格来源：`<本地参考路径>`（7 篇，禁止入库）与 `002-flowtide集成开发计划\001-详细开发计划.md`。
> 行为规格以调研文档为准；本文登记范围与已锁定决策。任务编号 P{阶段}.{序号}，与开发计划一致。

## 1. 目标

把 example-base-workflow 对 Flowable 的二次封装能力在 Flowtide 中**原生重实现**（Go、同进程、无 JVM）：

1. **复杂流程全能力**：发起、办结/驳回、任意节点退回、撤回（策略族）、直送、加签/减签、普通/权重/比例退回会签、委托/转办/待办调整、催办、超时自动办结、终止/删除/挂起/重激活/重置、下一步推演、历史步骤/轨迹；
2. **workflow_\* 系列表**（29 张 → 裁剪为 24 张 + 1 张新增）与全部相关逻辑（预生成-消耗模型、执行人重写、表单状态、操作留痕、异常落库）；
3. **业务集成协议**：业务系统注册 + HTTP 回调、发起/办结门面 API、业务-流程绑定三元组（tenantId=系统代号、businessKey=单据 ID、processDefinitionKey）；
4. **管理台界面**：流程分类/模型/步骤/设计器/待办已办/实例/委托/催办/异常九大页面 + 审批弹窗、流程图预览等公共组件。

**不做**（本期明确排除）：

- Dubbo/Seata/Nacos（以 HTTP 门面 + 引擎内嵌 + 本地事务替代）；
- xjar 加密打包、多数据源动态路由（多租户方案见 D3）；
- 旧版遗留四表（workflow_task/history/record/example）与 workflow_model_discard、workflow_rule（裁剪）；
- 管理台按钮权限控制（menuCode 透传但服务端忽略，见 D7）。

## 3. 核心设计铁律（实现时必须遵守）

1. **"下一步预生成-消耗"模型**：所有写操作（发起/办结/退回/转办/委派/直送）先写 `workflow_next_activity`（目标节点+处理人+版本号）并双写 `workflow_his_next_activity`(used=0)，再操作引擎；任务创建时执行人重写钩子读 used=0 记录回填 assignee/候选并置 used=1、回写 taskId；
2. **ACT_\* 行禁止直改 SQL**：Flowtide 引擎以内存状态为权威、行差分持久化；workflow 层一切引擎数据操作必须走引擎状态 API（新增引擎方法补齐能力），否则会被下次 persistRows 差分覆盖；
3. **钩子在命令内同步执行**：引擎命令持互斥锁不可重入；需要再次驱动引擎的联动（相邻同人自动办结等）必须通过"命令后延迟动作"队列执行；
4. **显式 context 传操作人**：不用 ThreadLocal 模式，操作人经参数/上下文传递；
5. **意见/变量协议逐字兼容**：26 种 CommentTypeEnum、operationType（agreeComplete/completeToTarget）、initiator/businessKey/title/entity、ROLLBACK_\* 变量、Sign\*/Draft/end 保留步骤代号，见 006-流程变量与意见类型约定（规格附录）；
6. **TDD + 覆盖率 0.9 + 中文注释**（AGENTS.md 全量适用）；文档编号续编本目录。
