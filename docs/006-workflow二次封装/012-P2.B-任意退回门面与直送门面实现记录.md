## 1. 步骤规则服务（steprules.go）

- 端口 `StepStore`（`GetByDeploymentAndActivity` / `ListByDeployment`）+ 内存实现 `MemStepStore`
  + SQL 适配 `SQLStepStore`（组合 pwf HisStep 仓储，行结构经 `stepRuleFromRow` 映射）。
- `StepRuleService` 规则读取语义（对位 Java WorkflowHisStepEntity 字段解释）：
  - `AllowReturn`：仅 `allow_return=="0"` 显式禁止，其余/缺失允许（Java L2584 判定）；
  - `BackStepCodes`：逗号拆分白名单（剔空段）；
  - `SortOf` / `StepNameOf`：展示排序号与步骤名；
  - `ReturnPercentOf`：`countersign_percent_return=="1"` 启用 + `return_percent` 百分数解析；
  - `PercentReturnRule(ctx, taskID)`：实现 P3-A `StepRuleProvider` 接口位——任务 → 定义 → 部署 →
    his_step 链定位（此前 countersign.go 的比例退回规则端口为空位，本服务首次落地）。

## 2. 可退节点计算（BackNodes，五道过滤链）

对位 getBackNodesByTaskId:2673，任务不存在/入参为空返回空列表（与 Java 一致不报错）：

1. 过滤链①：当前节点 `allowReturn=="0"` → 空列表；
2. 过滤链②数据源：引擎 `QueryHistoricActivityInstances(finished)`；
3. 过滤链③：`activityType=="userTask"` + 非当前节点，按节点聚合任务 ID（多实例多行合并）；
4. 过滤链④祖先链：`ModelStore.ReturnSortOf`（workflow_model.return_sort，端口可选，nil 跳过）
   + `his_next_activity` 的 `pre_task_id` 链（每层取创建时间最早的消耗记录首条，对位 Java
   getParentTaskIds 取 `list.get(0)`）；父链非空时仅保留历史任务 ID 命中父链的活动；
   `returnSort=true` 时链逆序输出（Java 降序分支）；Go 增加防环终止（Java 成环栈溢出）；
5. 过滤链⑤：当前节点 `backStepCodes` 白名单（非空时仅白名单内节点）；
6. 过滤链⑥可达性：`isNodeReachable` 纯函数（等价 engine.IsReachable，因 workflow 包
   不 import internal/engine 的依赖约束在本包基于 bpmn/model 重写，处理子流程终点提升、
   事件子流程开始事件排除、嵌套容器）。

多实例节点按历史任务全量收集办理人（`assigneeNamesOf`，历史缺失回退运行任务，同名去重）；
视图 `BackNodeView{ActivityID, ActivityName, TaskIDs, AssigneeNames, Sort}` 按步骤排序号
（his_step.sort，未配置 0）+ 节点 ID 排序输出。

## 3. 任意退回门面（BackToStep，generalBack 对位）

执行顺序：目标执行人预存（`saveBackToStepNext`，Go 协议适配：BackTaskVo 无 request 字段，
执行人取目标节点历史办理人去重）→ allowReturn 校验 → 暂停拒绝 → 引擎
`WorkflowExtService().BackUserTaskToActivity`（TH 意见在命令前写入——引擎评论 API 绑定运行态任务）
→ 操作记录(isAgree=0, TH) → 收尾链：

- 预存清理：按模型后继枚举（`nextActivityIDsAfter`，getNextActivitys 对位）删除目标之后节点的
  预存记录（不含目标——目标记录即刚预存的执行人）；
- 待办清理：目标及之后节点（`DeleteByProcessInstanceAndActivityIDs`）+ 当前任务待办
  （Java generalBack 未清理当前任务待办行，Go 补齐避免死待办，与直送 deleteTaskMessageExtendByTaskId 同语义）；
- 已办完成时间回写；按实例重生成待办（`generateTodosAfterBack`，complete.go
  generateTodosForNewTasks 的同构复刻，count==0 幂等、无主任务跳过）。

`BackToPrevious` 对位 backTask:4502 简化退回：取当前节点唯一入线 sourceRef 直迁
（多入线报"上一节点不唯一"，零入线报错，仅串行流程），收尾做最小账本闭合
（当前待办清理 + 已办回写 + 重生成）。

### 引擎唯一增补（workflow_ext.go，62 行）

`BackUserTaskToActivity` 命令内（同一 cc，agenda.run 之前）内联 G7 历史清理：

- `backSuccessorActivityIDs`：BPMN 图 DFS 枚举目标之后可达元素（防环；子流程容器展开内部元素，
  历史活动行以内部元素 ID 落库）；
- `deleteBackHistoricActivities`：删除"目标+后继"全部历史活动行（零时间下界=全量，对位 Java
  generalBack L2594-2604 的 deleteHisActinstsByProcessInstanceIdAndActIds 无时间窗语义）；
  历史任务行与 Java 一致保留；新落位目标的活动行在 agenda.run 中创建，位于删除之后不受影响。

## 4. 直送门面（direct.go，completeToTargetActivity:4550 对位)

- 意见类型核实结论：**Java 直送场景 type 缺省取 `CommentTypeEnum.TZ`（跳转）**，显式传入
  vo.Type 时用 vo.Type（Java L4632：`isBlank(type) ? TZ : type`）。
- 链路：目标节点执行者模型校验（未配置执行者拒绝，Go 扩展 executorList 形态一并认可）→
  预存目标执行人（request 首条，end 保留代号跳过）→ TZ 意见（命令前写入）→ setAssignee →
  引擎 `WorkflowExtService().CompleteToTarget`（operationType=completeToTarget 由引擎写入，
  触发执行人重写钩子按预存记录回填目标节点执行人）→ 落 `workflow_complete_to_activity`
  （flowId 空、source=当前节点、target、taskId、procInstId）→ 操作记录(isAgree=1, TZ) →
  删当前节点预存（deleteCurrentWorkflowNextActivity 对位）→ 删当前待办 → 已办回写 →
  按实例重生成待办 → 表单状态机刷新（Java 直送链路未调用 updateWorkflowDocument，Go 补齐）。
- 与 complete.go `applyFreeSelectFallback` 的语义衔接（未改其文件）：常规办结 + 自由选路参数
  仍走 Complete（办结后纠偏迁移兜底仍在）；显式直送场景走本门面（单命令引擎级迁移，
  Java 伪造连线语义的等价能力），两入口并存。
