## 3. 与 Java 语义对照的决策点

1. **SaveFirstTaskUser 的 used 语义**：按 `ProcessesUtil#publishAndGetFirstTaskByKey:1142` 实现——首步记录 used=1、task_id=首任务 ID、pre_task_id 不设置（FirstStepRequest 增加 TaskID 字段承载首任务 ID，规格字段清单之外补齐）。
2. **版本号语义**：`LatestVersion` = his 表中同实例同节点 used=1 记录的最大版本（Java `getNextActivityLatestVersionByProcInstAndTaskKey` 仅统计已消耗）；每次 save* 整批共用一次推算（Java 循环外取 nextVersion）。
3. **SaveResolveNext**：对位 `saveResolveNextActivity`——used=1、taskId=当前任务、groupId 继承既有记录（findNextActivityByParams 四条件定位）；未找到既有记录时跳过插入（Java 同款）。
4. **DeleteForBackToStep**：Java 原 SQL 附带 create_time 全表比较的"顺带清理更早记录"，语义模糊副作用大，Go 收敛为删除目标节点全部记录（注释标注）。
5. **DeleteForRollback**：仅删运行态（procInst + pre_task_id=taskId AND next_activity_id != keep），Java 同款；历史表保留追溯。
6. **意见（comment）**：message 先折叠空白（`\s+`→单空格）再按 3900 截断加 "..."（Java 按 UTF-16 计数，Go 按 rune 等价）；Type 空默认 SP；**引擎 AddComment 不透出自定义 type**（引擎侧固定 "comment"），意见类型权威台账 = workflow_operation_record.type，P1.2 办结流程需同时调 CommentService.Add 与 OperationRecordService.Save（与 Java 双写一致）；空白意见在引擎侧被拒（ENGINE-1101），Go 域服务提前报错。
7. **操作记录补全**：对位 `saveWorkflowOperationRecord`——任务步骤/签收办结时间经历史任务、业务键/租户经运行→历史实例回退、流程分类经定义查询、处理人姓名/组经身份库（引擎组无层级路径，组路径列与简名列同值，多组逗号聚合）；未知任务/实例容错留空（Java 空指针处 Go 容错）。
8. **document 状态机**（对位 `updateWorkflowDocumentByProcessInstanceIdOrTaskId:96`）：LCZZ 最后记录→已终止（清待办+终止时间）＞实例结束→已完成（清待办+完成时间）＞操作记录数≤1→未提交、>1→流转中；待办聚合列去重逗号串（document_url/flow_task_id/flow_action_id/flow_action/flow_current_step_name/flow_current_persons）；**待办步骤代号含 Sign/Sign1/Sign2/EngineerSign→flow_status=已完成（不清聚合列）**；taskKey=Draft→flow_start_time；业务键解析失败静默跳过。状态值为中文字面值（协议兼容）。
9. **已办 ListByInstance 排序**：暂按 task_finish_time/create_time，TODO-P5 接入 his_step.sort 聚合排序。
10. **仓储缺口**：不改 P0-A 文件，store_sql.go 以只读裸 SQL 补齐（需 NewSQLStoresWithDB 注入连接池）+ 逐条按主键删除/更新补齐。

## 6. P1.2（发起/办结）对接说明

1. **装配**：`NewSQLStoresWithDB(pwfStore, db)` 得五大端口；域服务构造传 engine 七服务（窄接口由 `engine.TaskService()/HistoryService()/RuntimeService()/RepositoryService()/IdentityService()` 直接满足）。
2. **发起（publishAndGetFirstTaskByKey 等价）**：StartProcessInstance → 查首任务 → `next.SaveFirstTaskUser`（used=1+taskId）→ `comment.Add`（TJ）→ `operations.Save`（TJ）→ 按 next_activity used=1 记录生成待办（`message.CreateForTask` + `history.CreateForTask` 镜像 + `document.Save` 初始"未提交"）。
3. **办结（generalComplete 等价）**：`next.SaveAgreeNext`（end 跳过）→ 引擎 complete（operationType=agreeComplete 触发执行人重写钩子：`next.ListUnusedByInstance` + `MarkUsedAndWriteBack`）→ 删当前节点 next_activity → `comment.Add`（type 默认 SP）→ `operations.Save` → 删待办 `message.DeleteByTaskID` → 已办 `history.UpdateFinishTime` → 新节点生成待办 → `document.UpdateByProcessInstanceOrTask(procInstID, taskID)` 刷状态机。
4. **退回/撤回/直送（P2）**：`SaveBackToStepNext` / `DeleteForBackToStep` / `DeleteForRollback` / `SaveResolveNext` / `DeleteForResolve` 均已就绪，签名与 Java mapper 过滤条件一一对应。
5. **事务**：同一能力内的多表写入经 `pwfStore.WithTx(ctx, fn)` 共享工作单元（SQL 适配经 ctx 透传事务）；内存实现无事务语义（嵌入模式最终一致）。
