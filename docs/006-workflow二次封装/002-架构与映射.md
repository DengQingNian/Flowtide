# 006 系列文档之二：架构与映射

> 本文是 internal/workflow 模块的架构基准：包布局、Java 机制→Go 机制映射、引擎扩展点设计、存储与事务设计。实现与本文件冲突时，先改本文再改代码。

## 1. 模块布局

```
api/
  hooks.go             # 引擎全局钩子类型（TaskHook / HookControl / Defer）
  workflow.go          # workflow 门面接口（嵌入式使用者入口）
internal/
  engine/              # 引擎：新增全局钩子点 + 二次封装所需引擎能力（能力补齐单独文件，勿散改）
  persistence/
    workflow/          # workflow_* 行仓储（database/sql + 方言感知；integration 测试挂 FLOWABLE_*_INTEGRATION）
    schema/sql/{mysql,postgres}/002-workflow-1.0.sql   # DDL（双库）
  workflow/            # 业务封装主战场（门面服务、监听器、调度、推演、策略）
    service 职能文件：start.go / complete.go / back.go / rollback.go / direct.go
                       countersign.go / addsign.go / delegate.go / remind.go / model.go
                       step.go / simulate.go / document.go / comment.go / operation.go
                       nextactivity.go / message.go / business.go / exception.go / review.go ...
    listener/          # 全局监听（执行人重写、相邻同人自动办结、撤回回填）与节点级监听等价物
    schedule/          # 自动办结 / 超时提醒 / 催办 / 僵尸监控 4 个调度器（ticker/cron）
    rollback/          # 撤回策略族（工厂 + 6 策略）
  rest/                # /workflow/** 路由挂载（workflow_routes.go，避免散改 server.go）
admin/                 # 管理台：workflow 业务页面（九大页面）
testdata/compatibility/workflow/   # BPMN 语料（网关/子流程/多实例/调用活动/会签）
```

依赖方向：`internal/workflow → api.Engine（七服务）+ api hooks + internal/persistence/workflow`；`internal/workflow` 不 import `internal/engine`（通过 api 接口 + hooks 访问引擎）；引擎能力补齐放 `internal/engine/workflow_ext.go` 并挂到 api 接口。

## 2. Java 机制 → Go 机制映射

| Java 机制 | Go 对应 | 说明 |
| --- | --- | --- |
| FlowableEventDispatcher 全局监听 ×4 | `api.TaskHook`（TASK_CREATED/COMPLETED 全局钩子），引擎 createUserTask/completeTask 命令内同步调用 | 顺序=注册顺序；错误使命令失败回滚 |
| 监听器内再调引擎（相邻同人自动办结） | `HookControl.Defer(func(ctx))` 延迟到命令提交后执行 | 规避互斥锁重入 |
| TaskListener/ExecutionListener（BPMN class=） | BPMN 扩展属性内置类型名（businessCallTask、countersignCollectionConfig…），引擎监听点按类型分发到 workflow 注册的实现 | 不用反射 class；部署校验改 Go 版 checkCountersignListenerConfig |
| 自定义 Command（BackUserTaskCmd/RollbackCmd…） | 引擎能力补齐方法（workflow_ext.go）+ workflow 层策略族；退回基于 ChangeActivityState | 同包访问内部状态，无需 Command 封装 |
| MyBatis-Plus 实体/Mapper | `internal/persistence/workflow/` 方言感知行仓储（database/sql，不引 ORM）+ `internal/workflow` 仓储接口（内存实现供单测） | 与引擎 ACT 行仓储模式解耦（workflow 表不走引擎差分持久化） |
| Dubbo ProcessesService 门面 | REST `/workflow/{模块}/{方法}`（D8）+ `api/workflow.go` 门面接口 | 两路共用 internal/workflow 服务层 |
| auth 业务系统表 + HTTP 回调 | `workflow_business_system` 表 + Go net/http client（指数退避 3 次） | 报文兼容 006 规格附录 §3 |
| Seata AT | 引擎命令事务 + workflow 仓储工作单元（单进程本地事务） | 跨系统最终一致 + 异常表补偿 |
| 动态多数据源 | tenant_id 列过滤（D3） | |
| fel 表达式 | Flowtide 已有 UEL 兼容子集（internal/expr） | 连线条件、权重完成条件 |
| Spring 定时任务 | schedule/ 内 ticker/cron goroutine + 配置开关（与 Java 同名：noHandleAutoComplete、task-timeout-remind、send-workflow-remind、adjacentActivitySameOwnerAutoComplete、send-todo-remind） | |
| Redis 异常计数 | 进程内原子计数（metrics），可选外接 | |
| Authentication ThreadLocal | 显式参数/ctx 传 operator | |

## 3. 引擎扩展点设计（P0.3）

```go
// api/hooks.go
// TaskHook 任务生命周期全局钩子。在创建/完成任务的引擎命令内同步调用。
// @param ctx 命令上下文
// @param task 任务快照（改写无效，需经 ctl）
// @param ctl 钩子控制（状态改写 + 延迟动作）
// @return 错误（非空则当前引擎命令失败回滚）
type TaskHook func(ctx context.Context, task *Task, ctl HookControl) error

// HookControl 钩子控制接口
type HookControl interface {
    SetAssignee(taskID, userID string) error          // 命令内改写办理人
    SetCandidateUsers(taskID string, ids []string) error
    SetCandidateGroups(taskID string, ids []string) error
    SetVariable(name string, value any) error         // 流程级变量
    Defer(action func(ctx context.Context) error)     // 命令提交成功后执行（新命令上下文）
}
```

- 注册：`Engine.AddTaskCreatedHook(h)` / `Engine.AddTaskCompletedHook(h)`，按注册顺序执行；`api.Engine` 增加同名接口方法；
- 调用点：`createUserTask`（task.go，在 invokeTaskListeners("create") 之后）、`completeTask`（task.go，在 invokeTaskListeners("complete") 之后、recordTaskEnd 之前——确保差分行含最终态）；
- Defer 队列在 execute() 成功落盘后（锁外）顺序执行；Defer 内错误落 workflow_task_exception（P4 接管），P0 阶段记录日志即可；
- 多实例：每个实例任务创建都会触发钩子（与 Flowable TASK_CREATED 语义一致）。

## 4. 二次封装所需引擎能力补齐清单（随阶段实现）

| 能力 | 目标 | 所属阶段 |
| --- | --- | --- |
| 全局钩子 + Defer | api/hooks.go + engine 接线 | P0 |
| 执行人重写所需的模型节点信息读取（assignee/candidate/executorType/weightType/multiInstance） | RepositoryService 已有模型 JSON 或新增节点元数据查询 | P1 |
| 任意退回（并行网关四分支、子流程内外映射、汇聚占位） | ChangeActivityState 增强（workflow_ext.go） | P2 |
| 目标节点之后活动实例清理（运行时+历史） | 引擎状态级 API（删 state 内 ActivityInstances + 历史行） | P2 |
| 直送（指定目标办结，迁移语义） | CompleteToTarget(taskID, targetActivityID) | P2 |
| 终止（全部 execution 迁移至 EndEvent 走完） | 基于 ChangeProcessInstanceState 组合 | P2 |
| 删除实例（运行级联 + 历史级联 + 扩展级联） | DeleteProcessInstance cascade 确认/补齐 | P2 |
| 重激活（历史实例复活：清 endTime/deleteReason/duration，按 CREATE_TIME_ 升序重建变量） | ReactivateProcessInstance | P2 |
| 多实例动态加减成员 | AddMultiInstanceExecution / DeleteMultiInstanceExecution | P3 |

| 加签父子任务（PARENT_TASK_ID_、owner、countEnabled） | 确认 CreateTask 子任务能力 + 补齐 resolve 联动 | P1/P3 |

## 5. 存储与事务设计

1. **workflow_\* 表**：`internal/persistence/workflow/` 每表一个仓储（结构体 + 方法），方言感知（mysql `?` / postgres `$n`），事务经 `*sql.Tx` 工作单元（`WithTx(ctx, fn)`）；DDL 双库 `002-workflow-1.0.sql`，由 `internal/persistence/schema` embed + EnsureSchema 装载（兼容现有 checksum 机制，workflow DDL 独立 checksum）；
2. **仓储接口**：定义在 `internal/workflow`（端口），SQL 实现在 `internal/persistence/workflow`（适配器），另有内存实现（`internal/workflow/memstore.go` 等）供单元测试与嵌入式无 DB 模式；集成测试挂 `FLOWABLE_MYSQL_INTEGRATION` / `FLOWABLE_POSTGRES_INTEGRATION`；
3. **ID**：internal/idgen（现有实现）；公共列：id、creator、creator_name、create_time、updater、update_time、tenant_id；逻辑删除 `deleted` 手工过滤（仅 document/remind/remind_target 有）；
4. **与引擎事务边界**：引擎命令（内存状态+ACT 行）与 workflow 表写入是两个本地事务；顺序=先 workflow 预写（next_activity）→ 引擎命令 → workflow 收尾；失败路径以 workflow_task_exception + 补偿方法兜底（与 Java 一致）。**同一能力内 workflow 读写必须复用同一工作单元**；
5. **引擎数据查询**：待办/已办联查优先走引擎查询服务（075-078 下推模式），workflow 扩展列单独查后拼装，避免跨引擎仓储直连 SQL。

## 6. REST 挂载

- `internal/rest/workflow_routes.go` 注册 `/workflow/**` 全部路由（D8 Java 兼容路径），复用 server 中间件链（认证/租户/审计/限流自动生效）；
- 返回结构兼容 Java 两种 R 包装（code/msg/errorMessage/data/success）；
- `/workflow/**` 认证守卫与 `/service/**` 同策略（仅当显式启用认证选项时拦截）。
