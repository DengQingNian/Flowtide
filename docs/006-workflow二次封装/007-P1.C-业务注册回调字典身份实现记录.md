## 2. 回调报文与 Java 对照结论

Java 权威参照 listener/BusinessCallTaskListener.java:50-67 与 BusinessCallExecutionListener.java:39-48（paramMap → fastjson JSON.toJSONString → HttpUtil.post）。

| JSON 字段 | 任务级（TaskListener） | 执行级（ExecutionListener） | 本实现 |
| --- | --- | --- | --- |
| processDefinitionId / processInstanceId / businessKey / tenantId | 有 | 有 | 逐字一致 |
| taskId / taskName | 有 | **无**（执行级报文无此二字段） | TaskCallback 含、ExecutionCallback 不含，逐字一致 |
| flowElementId / flowElementName | 有 | 有 | 逐字一致 |
| params | 字符串（FixedValue 表达式文本，"k:v;k:v"） | **FieldExtension 列表**（fastjson 序列化为对象数组） | 按 P1-C 任务口径统一传字符串（"k:v;k:v"）；P1.2 监听器接线时把执行级扩展属性先行格式化为该串 |

行为对照：注册表查无（CollectionUtils.isEmpty）与地址为空（StringUtils.isNotBlank）均静默跳过；差异点：Java 捕获异常仅记日志，Go 侧重试耗尽后**返回错误 + ExceptionRecorder 落库口**（D5 管理台重发），调用方（监听器接线）可自行吞错以保持 Java 语义。ParseParams 对"值含冒号/无冒号分段"比 Java（split[1] 取段，越界即崩）更容错。

## 4. 身份门面与引擎能力差距（D10 降级说明）

| 能力 | 引擎（ACT_ID_*）现状 | 门面降级方案 |
| --- | --- | --- |
| 用户树 | 用户/组/成员关系齐备，**组无父子层级** | 组节点（一层）→ 成员用户节点；未入组用户挂"未分组"；**完全无组时退化为平铺用户列表**（注释说明） |
| 组织树 | 组表无 parent 列，无层级 | 单根 + 平铺组节点（注释说明），真实层级待 IdentityAdapter |
| 资源树 | 引擎无资源/菜单模型 | 返回单根空树占位；外部 auth 适配器实现 `IdentityAdapter.ResourceTree` 后即有数据 |
| 账号搜索 | ListUsers 全量 + 内存过滤 | ID/显示名/姓/名/邮箱包含匹配（不区分大小写），空关键字全量；适配器接管后由外部实现优化 |

`IdentityAdapter`（UserTree/OrgTree/ResourceTree/SearchAccount）已定义并接线：注入后全部方法委托外部实现（优先于内置身份库），本阶段无默认实现。

## 6. 遗留与 P1.2 对接注意点

1. 本任务不做引擎监听器接线：P1.2 在 TASK_CREATED 等钩子内组包 `TaskCallback`/`ExecutionCallback` 后调用 `CallbackClient.Send*Callback`；执行级扩展属性需先格式化为 "k:v;k:v" 字符串；
2. ExceptionRecorder 当前为空实现，P4 接 `workflow_task_exception` 仓储（`CallbackException` 字段已对位该表：kind→来源、payload→params、cause→message）；
3. 字典未与真实前端字典库逐字核对项（messageType/flowStatus/targetType 等自拟条目）待 P6 契约测试确认；
4. SQLBusinessSystemStore 仅 MySQL 集成验证，PostgreSQL 方言占位符（$n）路径由单测（sqlmock）覆盖，如需双库实机验证可在集成测试补 PG 分支。
