## 当前结论

**可回退迁移尚未实现。** 仓库没有已验证的反向转换器，也没有完成「Java 读取 Go 写入数据并续跑」的演练。当前只能依赖数据库备份恢复到切换前快照，并重新启动 Java 执行者。

## 回退方式

| 方式 | 前提 | 数据风险 | 状态 |
| --- | --- | --- | --- |
| 备份恢复 | 切换前全量备份、恢复演练通过 | 丢失切换后写入 | 可执行但未演练 |
| 反向转换 | 已实现并验证的 Go → Java 转换 | 语义丢失/字段不兼容 | 未实现 |
| 双写 | 不推荐 | 冲突与重复执行 | 禁止 |
| 保留旧镜像 | 无数据回退 | 只回退程序，不回退数据 | 不构成回退 |

## 回退演练应包含

1. 在隔离环境恢复切换前备份。
2. 用 Java 版本读取恢复后的库并推进一个用户任务。
3. 验证历史、变量、作业与身份链接。
4. 记录恢复耗时、数据损失边界与人工步骤。
5. 明确回退触发条件、决策人、窗口与停止条件。
6. 演练结果存档，并与迁移报告绑定到同一提交/版本。

## 回退窗口

窗口应覆盖：

- 关键业务流程至少一个完整周期；
- 作业与定时器至少一次触发；
- 历史查询与审计检查；
- 监控稳定观察；
- 业务方确认。

窗口结束前不得删除 Java 库备份、旧版本镜像或迁移报告。

## 验收证据

| 证据 | 当前 |
| --- | --- |
| 备份可恢复 | 有工具与流程，未完成正式演练 |
| Java 读取 Go 数据 | 未完成 |
| 反向转换器 | 未实现 |
| 回退窗口与负责人 | 未定义 |
| 回退演练报告 | 无 |

在上述证据齐备前，任何「可回退」表述都不成立。
