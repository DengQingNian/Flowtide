## 覆盖结论

| 项目 | 结果 |
| --- | --- |
| 官方方法端点 | 184 |
| 实现方法端点 | 242 |
| 官方缺失 | 0 |
| 扩展端点 | 58 |
| 逐字段 Java 对照 | 二十四个方法的 82 个原版 HTTP 场景通过；全量待完成 |
| 契约测试 | 184 方法基础矩阵通过；完整请求响应契约待完成 |

“官方缺失 0”只说明路径与方法均已注册。它不能证明客户端调用会得到与 Java 相同的响应。

## 已知差异类型

### 1. 响应字段与空值

Go DTO 与 Java DTO 不是逐字段复制。部分字段可能缺失、使用不同默认值，或把嵌套对象展开为扁平字段。

### 2. 分页与排序

任务、实例及执行方法已通过默认排序、零大小、越界、负值回退及请求体分页优先等原版场景。其他方法和任务字段组合仍待逐项对齐，查询仍有全量读取与内存分页。固定原版 unassigned=false 也选择未签收任务，与 OpenAPI 描述有差异。

### 3. 错误码

Go 使用 <code>ENGINE-/REST-/AUTH-</code> 错误码，未映射 Java 全量错误码。客户端若依赖具体错误码分支，需要适配。

### 4. 异步语义

6 个 <code>variables-async</code> 方法已通过持久排队、重试、死信、双库重启恢复及 14 个原版 HTTP 场景对照。实例变量集合成功返回 201，执行变量集合及单变量返回 204；执行集合与 OpenAPI 标记的 201 存在差异，以固定 Java 控制器实际响应为准。跨节点作业协调仍未实现。

### 5. 租户

认证绑定租户与请求租户的优先级已实现；部分列表端点的租户过滤仍在内存完成，尚未全部下推。

### 6. 副作用与级联

部署删除、实例删除、任务删除、批量迁移的级联范围与历史保留策略需要逐路径对照。

## 扩展端点

扩展端点补充了官方规范未覆盖的运维与查询需求，但不计入官方覆盖率，也不保证 Java 客户端可识别。典型扩展：

- 引擎属性 CRUD、审计日志、批次统计。
- 作业桶删除、move/reschedule。
- 身份链接单条读取/按类型删除。
- 历史评论/附件/变量明细补充查询。
- 部署资源 ETag/304。

## 验收方法

1. 从 [REST 浏览器](/rest-explorer) 选一个方法与路径。
2. 找到官方 OpenAPI 对应操作与 schema。
3. 用 Java 版本构造黄金请求/响应。
4. 对比状态码、响应体、分页、错误与副作用。
5. 覆盖空值、边界、越权与并发冲突。
6. 将结果写入能力矩阵，而不是只更新路由统计。
