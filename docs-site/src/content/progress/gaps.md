## 试用条件

当前版本可用于新建库原型、功能验证和迁移预检。生产环境的切换与回退尚未验收，试用时请确认以下条件。

1. 新建数据库，或已接受离线转换与人工停写；
2. 单执行者部署，不共享状态源；
3. 不使用集群作业、外部工作项与完整脚本；
4. 接受接口与状态格式在版本间调整；
5. 有独立备份与回退方案。

如果部署方式或业务功能超出这些范围，请先完成相应验收，或继续使用 Java 版本。

## P0：生产可用性差距

| 差距 | 影响 | 下一步 |
| --- | --- | --- |
| Java 行为对照缺失 | 客户端可能遇到响应模式、分页、错误码差异 | 建立请求/响应回放与逐字段契约测试 |
| 停写切换与回退未演练 | 存量库无法安全接管 | 在真实 Java 样本上完成备份、转换、数量核对与回退 |
| 集群能力缺失 | 只能单节点，故障需人工恢复 | 作业租约、抢占、幂等与故障转移 |
| 查询下推不完整 | 数据量增长后内存扫描变慢 | 双库执行验收、变量与无租户变体下推、索引评估 |
| 异步集群协调 | 持久变量作业、重试、死信、双库恢复与原版 HTTP 场景已通过 | 跨节点租约、抢占及故障转移 |
| 权限审计不完整 | mTLS/RBAC 组合未全量验证 | 权限矩阵、负向回放与证书角色映射 |

## P1：BPMN 完整性

- 完整定时器周期、cron 时区与跨节点调度。
- 用户任务型补偿处理器。
- 动态 BPMN 与流程定义动态变更。
- 事件注册表、外部工作项与消息中间件。
- 事件子流程、补偿、事务子流程的 Java 双向路径对照。
- 批处理的真实数据库与 Java 行为专项验收。

## P2：多引擎与生态

- CMMN 引擎（模型、运行时、REST）。
- 完整 DMN 引擎（DRD、BKM、决策服务）。
- Form、App、Content 引擎。
- LDAP、Kafka/Rabbit、Webhook。
- MSSQL/Oracle/DB2 方言。
- Helm/Kubernetes、压测与长期稳定性。

## 风险登记

| 风险 | 触发条件 | 缓解 |
| --- | --- | --- |
| 文档与代码漂移 | 能力声明未随提交更新 | 构建时生成事实、链接校验、<code>verifiedCommit</code> |
| 过度宣称 | 把「路由存在」写成「兼容」 | 四列证据矩阵、状态徽标、措辞检查 |
| 数据分叉 | 多执行者共享状态源 | 独占锁、启动拒绝、部署手册 |
| 迁移误判 | 预检无阻断即切换 | 明确「预检不等于可切换」 |
| 回退失败 | 只保留旧镜像未保留数据 | 备份恢复与反向转换演练 |
| 性能误读 | 本机基准外推生产 | 标注环境与边界，不以 QPS 承诺 |

## 建议的下一步顺序

1. 固定 Java 样本，回放请求与响应，逐字段检查行为是否一致。
2. 在真实 Java 库上完成一次受控停写演练与回退演练，形成可重复运行手册。
3. 完成查询下推的双库执行验收并补齐变量与无租户变体路径，建立真实数据库容量基线。
4. 引入作业租约与故障恢复，解除单执行者限制。
5. 再讨论多引擎与生态扩展。
