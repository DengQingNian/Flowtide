## 官方端点已覆盖，但仍有差异

1. **响应模式**：部分字段可能缺失、为空或类型不同。
2. **分页语义**：默认页大小、总数计算与排序字段未逐项对齐。
3. **错误码**：使用 <code>ENGINE-/REST-</code> 自定义码，未映射 Java 全量错误码。
4. **异步语义**：<code>variables-async</code> 为同步替代，不保证时序与重试。
5. **副作用**：批量、迁移与删除的级联行为需要逐路径对照。
6. **租户**：部分列表端点未完全下推租户过滤。

## 扩展端点

扩展端点是对官方规范的补充，例如：

- 引擎属性 CRUD 与审计日志。
- 批次统计、作业桶删除、move/reschedule。
- 身份链接单条读取与按类型删除。
- 历史评论、附件、变量明细的补充查询。
- 部署资源条件缓存（ETag/304）。

扩展端点不计入官方覆盖率，也不承诺与 Java 客户端兼容。

## 如何验收一个端点

1. 在 [REST 浏览器](/rest-explorer) 找到方法与路径。
2. 对照官方 OpenAPI 的请求体与响应 schema。
3. 用 Java 版本生成黄金响应，与 Go 响应逐字段比较。
4. 覆盖空值、分页边界、错误码、租户越权与并发冲突。
5. 把结果记录到能力矩阵，而不是只更新路由清单。
